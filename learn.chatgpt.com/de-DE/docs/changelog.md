  ### Geplante Aufgaben durch Ereignisse in Gmail, Slack und GitHub auslösen

  Geplante Aufgaben in ChatGPT können jetzt ausgeführt werden, wenn unterstützte Ereignisse in Gmail, Slack
  oder GitHub auftreten. Filtere Gmail-Nachrichten nach Absender oder Betreff, beobachte ausgewählte
  Slack-Kanäle oder reagiere auf Aktivitäten in Pull Requests wie Reviews, Kommentare,
  Commit-Updates und Merges.

  Ereignisgesteuerte Aufgaben sind in den unterstützten Tarifen in ChatGPT im Web und auf Mobilgeräten
  verfügbar. Verbinde die entsprechende App und genehmige den angeforderten Zugriff, bevor du
  eine Aufgabe erstellst.
  Die ChatGPT-App für Slack muss Mitglied jedes beobachteten Kanals sein, und die
  verbundene GitHub-App muss Zugriff auf jedes beobachtete Repository haben.

  Eine ereignisgesteuerte Aufgabe kann nicht zusätzlich nach einem Zeitplan ausgeführt werden. Wenn passende
  Ereignisse kurz nacheinander eintreffen, kann ChatGPT sie in einem Durchlauf zusammenfassen.
  Öffne **Geplant** , um ausstehende Ereignisse zu prüfen, oder wähle **Jetzt ausführen**.

  durch Ereignisse in Apps auslöst](/codex/automations?surface=web#web-trigger-tasks-from-app-events).

  GitLab-Unterstützung ist als Betaversion für alle ChatGPT-Tarife verfügbar. Verbinde ein GitLab-Projekt

  ### Verlauf der Computernutzung

  Der [Verlauf der Computernutzung](/codex/customization/computer-history) ist eine optional aktivierbare Funktion
  der ChatGPT-Desktop-App für macOS. Sie wandelt Aktivitäten in Apps und
  auf Websites in Erinnerungen und eine Zeitleiste um, die ChatGPT und Codex nutzen können. Du entscheidest,
  welche Apps und Websites erfasst werden, kannst die Erfassung pausieren und deinen Verlauf
  jederzeit überprüfen oder löschen.

  die Funktion aktivieren können. Zum Start ist die Funktion im Europäischen Wirtschaftsraum (EWR),
  in der Schweiz und im Vereinigten Königreich nicht verfügbar.

  ### Wir stellen Daybreak Blue und Daybreak Red vor

  Daybreak bietet zugelassenen Fachleuten für defensive Cybersicherheit jetzt zwei Zugriffsstufen: Daybreak Blue und
  Daybreak Red. Mit ihnen kannst du im Rahmen ausdrücklich autorisierter Aufträge Sicherheitsbefunde beheben und
  die Korrekturen validieren.

  Nutze Daybreak Blue zunächst für die meisten Aufgaben der defensiven Cybersicherheit. Damit erhältst du Zugriff
  auf vielseitig einsetzbare Modelle wie GPT-5.6 Sol, etwa zum Aufspüren von Schwachstellen,
  zur Überprüfung von Code auf Sicherheitsrisiken, zur Entwicklung von Erkennungsverfahren, zur Reaktion auf Sicherheitsvorfälle, zur Malwareanalyse
  und zur Validierung von Patches.

  Daybreak Red bietet einen separat genehmigten Zugriff auf eigens für solche Aufgaben trainierte Modelle wie
  GPT-5.6 Cyber. Du kannst sie für die autorisierte Reproduktion von Schwachstellen, die Validierung von Exploits,
  Penetrationstests, Red Teaming und die Analyse komplexer Systeme einsetzen.

  Der Zugriff muss über
  [Trusted Access for Cyber](/codex/cyber-safety#trusted-access-for-cyber) genehmigt werden und
  gilt nur für die genehmigte Identität, den genehmigten Workspace beziehungsweise die genehmigte API-Organisation und
  das genehmigte Projekt, das genehmigte Modell sowie die genehmigte Produktoberfläche. Für Daybreak Red sind eine separate Genehmigung
  und Freischaltung erforderlich; der Zugriff auf Daybreak Blue berechtigt nicht zum Zugriff auf Daybreak Red.

  Arbeite in einer isolierten Umgebung, lege den Auftragsumfang fest, verwende
  [Berechtigungsprofile](/codex/permissions) nach dem Prinzip der geringsten Rechte und konfiguriere
  die [Automatische Überprüfung](/codex/sandboxing/auto-review) für infrage kommende Aktionen, bevor sie
  die Sandbox-Grenze überschreiten.

  Erfahre mehr über [Cybersicherheit](/codex/cyber-safety),
  [Kosten in Codex-Credits](/codex/pricing#credits-overview) und
  [Preise für API-Token](/api/docs/pricing).

  ### Die Websuche ist jetzt standardmäßig aktiviert

  Codex aktiviert jetzt die Websuche für lokale Aufgaben in der Codex CLI und der IDE-Erweiterung.
  Standardmäßig verwendet Codex einen Websuche-Cache, also einen von OpenAI gepflegten Index mit Webergebnissen. Im Cache-Modus werden vorab indexierte Ergebnisse zurückgegeben, statt Webseiten live abzurufen. Im Live-Modus werden dagegen die neuesten Daten aus dem Web abgerufen. Wenn du `--yolo` oder eine andere [Sandbox-Einstellung mit Vollzugriff](/codex/agent-approvals-security) verwendest, liefert die Websuche standardmäßig Live-Ergebnisse. Um dieses Verhalten zu deaktivieren oder den Modus zu wechseln, verwende die Konfigurationsoption `web_search`:

  + `web_search = "cached"` (Standard; liefert Ergebnisse aus dem Websuche-Cache)
  + `web_search = "live"` (ruft die neuesten Daten aus dem Web ab; entspricht `--search`)
  + `web_search = "disabled"`, um das Tool zu entfernen

  Weitere Informationen findest du in der [Dokumentation zur Konfiguration](/codex/config-file/config-basic).

Optional kannst du ein Wartungsskript konfigurieren, das die Umgebung ausgehend von ihrem im Cache gespeicherten Zustand aktualisiert und für neue Aufgaben vorbereitet. Weitere Informationen findest du in der Dokumentation.

  #### Automatisches Umgebungs-Setup

  Umgebungen ohne manuelle Setup-Skripte führen jetzt automatisch die Standard-Installationsbefehle für gängige Paketmanager wie yarn, pnpm, npm, go mod, gradle, pip, poetry, uv und cargo aus. Dadurch treten bei neuen Umgebungen 40 % weniger Testfehler auf.
