## Codex がいつでも使えるスキルの作成

スキルを使うと、繰り返し行う作業向けの再利用可能な指示、リソース、スクリプトを Codex に提供できます。[スキル](/ja-JP/codex/build-skills) には、Codex が最初にうまく対応できたタスクや、その際に使ったドキュメント、コマンド、例を保存できます。

まず、うまくいった例を 1 つ用意します。たとえば、PR をチェリーピックした Codex チャット、Notion のリリースチェックリスト、役立つ PR コメント一式、ローンチ手順を説明した Slack スレッドなどです。

## 使用方法

1. Codex に使わせたいコンテキストを追加します。

   保存したい Codex チャットを開いたまま、Slack スレッドまたはドキュメントのリンクを貼り付け、Codex に記憶させたいルール、コマンド、例を追加します。

2. スタータープロンプトを実行します。

   プロンプトでは、作成するスキルに名前を付けたうえで、保存するタスク、ドキュメント、PR、コマンド、または出力を `$skill-creator` に渡します。

3. Codex にスキルの作成と検証を任せます。

   作成結果では、`$skill-name` を定義し、いつ起動すべきかを説明し、再利用可能な指示を適切な場所に保存します。

   `~/.codex/skills` 内のスキルは、どのリポジトリからでも利用できます。現在のリポジトリにあるスキルは、コミットしてチームメンバーにも利用してもらえます。

4. スキルを使い、チャットから更新します。

   次の PR、アラート、レビュー、リリースノート、またはデザインのタスクで、新しい `$skill-name` を呼び出します。間違ったテストコマンドを使う、レビューのルールを見落とす、ランブックの手順を飛ばす、そのままでは送信したくない下書きを作成するといった問題があれば、その修正をスキルに追加するよう Codex に依頼します。

## ソース資料の提供

スキルの動作方法を説明する資料を `$skill-creator` に渡します。

| 手元にあるもの                                              | 追加する内容                                                                                                                                                             |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **保存したい Codex チャットのワークフロー** | そのチャットを開いたまま、`use this chat` と入力します。Codex はチャットのコンテキスト、コマンド、編集内容、フィードバックを出発点として利用できます。                                         |
| **ドキュメントまたはランブック**                                      | リリースチェックリストを貼り付けるか、インシデント対応ランブックのリンクを追加するか、API の PDF を添付するか、リポジトリ内の Markdown ガイドを Codex に参照させます。                                 |
| **チーム内の会話**                                      | アラートについて説明している Slack スレッドを貼り付けるか、フロントエンドのルールが記載された PR レビューへのリンクを追加するか、顧客の問題を説明したサポートでの会話を添付します。 |
| **スキルで再利用するスクリプトまたはコマンド**             | 今後の Codex タスクに実行させたいテストコマンド、プレビューコマンド、リリーススクリプト、ログ取得スクリプト、またはローカルの補助コマンドを追加します。                                    |
| **良い結果の例**                                          | 今後のタスクで手本にしたい、マージ済み PR、最終版の変更履歴エントリ、承認済みのローンチノート、解決済みチケット、変更前後のスクリーンショット、または Codex の最終回答を追加します。         |

ソースが Slack、Linear、GitHub、Notion、Sentry にある場合は、[プラグイン](/ja-JP/codex/plugins) を使ってそのツールを Codex に接続し、スタータープロンプトでそのツールに言及するか、該当部分をチャットに貼り付けます。

## Codex の作成内容

ほとんどのスキルは `SKILL.md` ファイルから始まります。`$skill-creator` は、ワークフローで必要になったときに、より長い参考資料、スクリプト、またはアセットを追加できます。

## 作成可能なスキル

今後のタスクで、同じランブックを読む、同じ CLI を実行する、同じレビュー基準に従う、同じ形式のチーム向け更新文を書く、または同じブラウザフローを QA するときにも、このパターンを使えます。たとえば：

- **`$buildkite-fix-ci`** は、失敗したジョブのログをダウンロードし、エラーを診断して、必要最小限のコード修正を提案します。
- **`$fix-merge-conflicts`** は GitHub PR をチェックアウトし、ベースブランチに合わせて更新し、競合を解決して、正確な push コマンドを返します。
- **`$frontend-skill`** は、Codex が UI に関する好み、既存コンポーネント、スクリーンショットを使った QA ループ、アセットの選び方、ブラウザでの最終調整から逸れないようにします。
- **`$pr-review-comments`** は、レビューのメモを、適切なトーンと GitHub リンクを含む簡潔なインラインコメントに変換します。
- **`$web-game-prototyper`** は、最初にプレイ可能なゲームループの範囲を定め、アセットを選び、ゲームの操作感を調整し、スクリーンショットを撮影して、ブラウザ上で仕上げます。
