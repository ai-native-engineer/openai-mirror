## グラフではなく意思決定を軸にした設計

ダッシュボードの仕様を定める前に、ダッシュボードが支援すべき意思決定と、そのシグナルを受けて行動する担当者を定義します。仕様書を実際のデータに基づくものにするため、ChatGPT に指標の定義、ソースデータのエクスポート、既存の例、ワークフローのコンテキスト、ステークホルダーからのフィードバックを渡します。

1. ワークフロー、対象ユーザー、意思決定、レビュー頻度を明記します。
2. 指標用語集、ソースデータのエクスポート、ダッシュボードの例、ステークホルダーからのフィードバックを添付します。
3. データソースの不足、品質チェック、担当体制に関する要件を特定するよう ChatGPT に依頼します。
4. スタータープロンプトを実行し、KPI 階層、グラフ仕様、フィルター、モニタリング計画の草案を作成します。
5. 公開リスクをレビューし、提案された指標をソースデータに照らして検証します。

ダッシュボード仕様書を、アナリスト、データオーナー、ユーザー間の取り決めとして扱います。各グラフが何を意味するのか、いつ信頼できるのか、どのアクションのきっかけとすべきかを定義します。

## 行動につながるモニタリング

仕様書のレビュー後、最も価値の高いチェック項目を、エスカレーションの判断基準が明確なモニタリングチェックリストにまとめるよう ChatGPT に依頼します。
