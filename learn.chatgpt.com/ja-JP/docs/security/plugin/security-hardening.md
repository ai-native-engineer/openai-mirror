`$codex-security:propose-security-hardening` を使用して、収集したセキュリティ上の証拠から
構造的またはアーキテクチャ上の強化策を立案します。
このワークフローでは、完了した Codex Security スキャンを分析するか、
提供された検出結果、開示レポート、インシデントレビュー、評価文書、
ソースコードを基に分析を開始できます。

得られるのはパッチではなく設計ポートフォリオであり、脆弱性が修正されることを証明するものではありません。Codex がリポジトリを変更するのは、選択肢を選び、その変更を行うよう明示的に依頼した後だけです。

## 証拠の準備

ワークフローに次の情報を提供してください。

- スキャンディレクトリ、または明示的に指定した検出結果とレポートの一式
- 対象のソースツリーと、利用可能な場合は関連するリビジョンまたはスナップショット
- 検出結果を裏付ける PoCs、トレース、インシデントの証拠、または評価資料
- パフォーマンス、メモリ、互換性、信頼性、運用、納期、または変更範囲に関する制約

ワークフローでは証拠を基に、繰り返し破られる不変条件、分散した制御、特権が集中する要所、脆弱な分離境界、繰り返し現れる修復パターンを特定します。また、アーキテクチャの変更よりも局所的な修正の方が問題の規模に見合っていると結論付ける場合もあります。

## ワークフローの実行

次のようなプロンプトを送信します。

```text
Use $codex-security:propose-security-hardening to analyze [scan directory or finding paths] against [source tree and revision]. Develop evidence-backed structural hardening options with engineering tradeoffs, before-and-after diagrams, a migration plan, and an implementation handoff. Do not modify the repository.

## ポートフォリオのレビュー

有用なポートフォリオは、次の要件を満たす必要があります。

- 各変更案を、具体的な検出結果、ソースコード、脅威モデルに基づく根拠と結び付けます。
- 現在の設計と、新しい設計で維持すべきセキュリティ上の不変条件を説明します。
- 残存リスク、パフォーマンス、信頼性、運用、互換性、移行コストを含め、異なる選択肢を比較します。
- 証拠による裏付けがある場合に限り、前提条件と未解決事項を明示したうえで選択肢を推奨します。
- ロールアウト、検証、ロールバック、実装に関するガイダンスを含めます。
- 観測された事実、推論、提案する設計上の特性を明確に区別します。

選択肢を選ぶ前に、証拠とトレードオフをレビューしてください。アーキテクチャ図や設計上の推奨事項は、元の検出結果や実装した修正の検証に代わるものではありません。

## スキャンで得られた強化ガイダンスの活用

報告対象の検出結果を含む標準スキャン、ディープスキャン、変更スキャンについて、
セキュリティ強化ポートフォリオの作成を依頼できます。Codex はポートフォリオを `hardening/hardening.md` に、
構造化された分析結果を `hardening/hardening.json` に書き込み、
補足の提案や図を `hardening/` 配下に保存します。スキャンでは `report.md` からポートフォリオにリンクします。

リンクを引き続き利用できるように、スキャンディレクトリ全体をまとめて保持してください。
ポートフォリオの根拠となる個別のレポートを確認するには、「[脆弱性レポートの
作成](/ja-JP/codex/security/plugin/vulnerability-reports)」を参照してください。
