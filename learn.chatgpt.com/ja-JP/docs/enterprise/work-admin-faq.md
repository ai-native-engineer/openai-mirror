ChatGPT Work は、Codex を支える技術を ChatGPT に取り入れ、時間のかかる複数ステップのタスクに対応します。チャット、ファイル、ワークスペースのリソース、接続済みシステムからコンテキストを収集し、承認済みのツールを使用して、レビューできる状態の成果物を作成できます。アクセス、コンテキスト、アクション、ネットワークの動作、クレジット使用量は、プラン、ワークスペースの設定、情報ソースに対する権限、利用環境によって異なります。

## 概要

ChatGPT Work では、時間のかかる複数ステップのタスクを ChatGPT に委任できます。接続された情報ソースから情報を収集し、複数のステップにわたって推論し、ドキュメント、プレゼンテーション、分析結果を作成して、レビュー用に提示できます。

ChatGPT Work は、対象のプランとワークスペースで、対応する
ウェブ、モバイル、デスクトップから利用できます。対応している場合は、
ワークスペースのオーナーまたは権限を持つ管理者が、Work クラウド、Work ローカル、Codex ローカルを
それぞれ独立した権限で管理できます。対象の Enterprise および Edu ワークスペースでは、
権限を持つ管理者が無効にしない限り、デフォルトのワークスペースロールに Work が含まれます。
Work クラウドにはブラウザとネットワークの制御による追加の制限が適用され、
利用可否はロール、プラン、ワークスペース、リージョンによって異なります。詳しくは、
[ChatGPT Work と Codex](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex) を参照してください。

この「よくある質問」では、管理者による ChatGPT Work の管理について、アクセスとデータの制御、
コンプライアンスと可視性、利用状況と支出、インシデント対応、
ロールアウトの進め方を説明します。ホスト型の実行モデルとセキュリティ境界については、
[ChatGPT Work の概要](/ja-JP/codex/enterprise/chatgpt-work-overview)を参照してください。

## 主要な管理機能

管理者は、次の制御レイヤーを通じて ChatGPT Work を管理します。

- **エンタープライズワークスペースへのアクセス：** ID とアクセスの制御により、
  認証とワークスペースへのアクセスを管理します。プランと構成に応じて、
  管理者が制御できる ID 機能には、SSO、ドメイン検証、
  SCIM プロビジョニング、ユーザーライフサイクル管理、
  ID グループの同期などが含まれる場合があります。ChatGPT Business には、SCIM と同期された ID グループは
  含まれません。ユーザーは、アカウント単位で OpenAI の MFA を有効にできます。
  ChatGPT にはワークスペース全体で MFA を必須にする機能はありません。
  これを必要とする組織は、ID プロバイダーを通じて SSO と MFA を必須にしてください。
  SSO および関連する ID 設定は、
[グローバル管理コンソール](https://help.openai.com/en/articles/12289294-admin-portal)で管理します。
  [多要素認証](https://help.openai.com/en/articles/7967234-enabling-or-disabling-multi-factor-authentication-mfa)も参照してください。
- **ワークスペース内での ChatGPT Work へのアクセス：** 対応している場合、Work クラウドは
  対応するウェブ、モバイル、デスクトップ上でホスト型の Work を管理します。
  Work ローカルはデスクトップのローカル環境における Work を管理し、Codex ローカルは
  デスクトップ、CLI、IDE クライアントで利用できるローカルの Codex へのアクセスを制御します。
  クラウドブラウザとネットワークの設定により、Work クラウドはさらに制限されます。
  カスタムのロールベースのアクセス制御（RBAC）と利用できる権限は、プランとワークスペースによって異なります。
- **グループメンバーシップ：** SCIM に対応したプランでは、
  ID プロバイダーを通じてグループを同期し、従業員の入社、ロールの変更、
  退職に合わせてアクセスが更新されるようにします。詳しくは、
[グループとプロビジョニング](/ja-JP/codex/enterprise/groups-and-provisioning)を参照してください。
- **ワークスペースとメンバーのロール：** Enterprise の組み込みロールには、
  オーナー、管理者、メンバー、分析閲覧者があります。対応プランでは、カスタムロールと
  メンバー向けの RBAC によって、ChatGPT Work、プラグイン、その他の機能へのアクセスを制御します。
  シートの種別が適用される場合、メンバーには ChatGPT を含むシートも必要です。
  Codex 専用のシートでは Work を利用できません。詳しくは、
[ロールとワークスペースの権限](/ja-JP/codex/enterprise/roles-and-workspace-permissions)を参照してください。
- **プラグインとアプリ：** プラグインポリシーによって、プラグインの利用可否と
  インストールを管理します。アプリへのアクセス、アクションの制御、承認時の動作は
  個別に設定します。ワークスペースエージェントが利用できる場合は、独自の制御が
  適用されます。詳しくは、[プラグインの制御](/ja-JP/codex/enterprise/apps-and-connectors)、
[プラグイン](/ja-JP/codex/plugins)、
[App セキュリティホワイトペーパー](https://cdn.openai.com/business-guides-and-resources/app-security-whitepaper.pdf)を参照してください。
- **ソースシステムの権限：** ユーザーがアクセスできるコンテンツと実行できるアクションは、
  元のアプリケーションでアカウントまたは共有接続に許可されたものに限られます。詳しくは、
[アプリの管理者向け制御、セキュリティ、コンプライアンス](https://help.openai.com/en/articles/11509118-admin-controls-security-and-compliance-in-apps-enterprise-edu-and-business)を参照してください。
- **承認とアクションの制限：** アクション制御に対応したアプリでは、
  管理者は、すべてのアクション、読み取り専用アクション、または独自に選んだアクションの組み合わせを許可し、
  新しく追加されたアクションの扱いを決められます。アプリの権限によって、
  ChatGPT がアプリの使用前に確認を求めるタイミングが別途決まります。
- **クレジット：** ChatGPT Work と Codex は、料金、クレジット、利用上限を共有します。
  対象となる Enterprise および Edu の管理者は、ワークスペースのデフォルト設定、
  グループのデフォルト設定、個別の上書き設定を通じて、ユーザーごとの月間上限を設定できます。
  ワークスペースで許可されていれば、ユーザーは上限の引き上げをリクエストできます。Business には
  別のクレジットおよび支出制御モデルが適用されます。詳しくは、
[ChatGPT の利用上限と支出制御](/ja-JP/codex/enterprise/usage-limits)を参照してください。
- **分析とレポート：** グローバル管理コンソールとワークスペースの分析では、
  導入状況とクレジット使用量を分析できます。Compliance API と Codex の
  レポート機能は、ドキュメントに記載された対象イベントと製品の範囲で使用してください。
  特定のプロンプト、ファイル、承認、アクション、エラー、
  ツール呼び出しが対象になると確約する前に、現在のスキーマを確認してください。詳しくは、
[ガバナンス](/ja-JP/codex/enterprise/governance)を参照してください。

## アクセス、データ、システム、ユーザーアクション

### データやシステムへのアクセスとユーザーアクションの保護

ChatGPT Work には、ChatGPT ワークスペースにすでに導入されている
ID、アクセス、権限の制御が適用されます。管理者は、ID 管理、
ワークスペースのロール、対象プランで利用できる
[RBAC](https://help.openai.com/en/articles/11750701-rbac) を使用して、
ChatGPT Work を利用できるユーザーを決定します。

対応している場合は、
[SCIM](https://help.openai.com/en/articles/10011769-openai-platform-scim-integration-faq) とグループ同期を通じて、
ID プロバイダーとアクセス情報を同期できます。これにより、
従業員の入社、ロールの変更、退職に合わせて、アクセスと権限を一元管理できます。

ソースシステムでは、操作に使用されるアカウントまたは承認済みの
共有接続に付与された権限が適用されます。個人用の接続では、
そのユーザーがソースシステムで持つアクセス権限が使用されます。エージェントが所有する接続や共有接続を使うと、
エージェントの利用を許可されたユーザーが、接続に使われるアカウントを通じて、
自分のアカウントではアクセスできないデータやアクションも利用できる場合があります。
接続のスコープ、使用できるアクション、エージェントの利用対象者は、業務上必要な範囲に制限してください。詳しくは、
[ワークスペースエージェントの接続と権限](https://help.openai.com/en/articles/20001143-chatgpt-workspace-agents-for-enterprise-and-business)を参照してください。

### ChatGPT Work によるデータとコンテキストへのアクセス方法

ChatGPT Work は、現在のチャット、アップロードされたファイル、ワークスペースのリソースに加え、承認済みのアプリや、該当する場合はプラグインを通じて接続済みシステムを利用できます。有効な機能と権限に応じて、ドキュメント、リポジトリ、チケット、チャンネル、メール、カレンダーなどが対象になります。過去のファイルは、現在のチャット、対応するプロジェクト、許可されたライブラリへのアクセス、または有効化されたライブラリの自動参照を通じて利用できる場合があります。保存済みのメモリには、専用のワークスペース設定とユーザー設定が適用されます。

コンテキストの取得元ごとに独自の制御が適用されます。ユーザーはチャットのコンテキストを提供し、管理者はワークスペースのリソースを管理し、接続済みシステムは認証と権限を適用します。ChatGPT Work がアクセスできるのは、ユーザーまたは承認済みの共有接続に許可された情報に限られます。

ChatGPT Work は、該当する ChatGPT ワークスペースの保護機能を継承します。レジデンシー、保持、ログ記録、機能の提供状況は、プラン、リージョン、利用環境、接続先システムによって異なるため、お使いの構成での対応範囲を確認してください。

### 制限またはレビューの対象となる影響の大きいアクション

アクションのリスクは内容によって異なります。一般に、情報の読み取りや下書きの作成は、データの変更、情報の共有、外部システムでの操作よりも影響が小さくなります。ロール、適用範囲を絞った権限と認証情報、対応する承認機能を組み合わせ、影響の大きいアクションを、信頼できるレビュー済みの用途に限定してください。

一般的なアクションには、次のカテゴリがあります。

- **読み取り：** 承認済みのソースにある情報にアクセスし、検索または要約します。
  基になるデータは変更しません。
- **下書き：** ドキュメント、メール、レポート、コードなどのコンテンツを準備し、
  使用前に人がレビューできるようにします。
- **書き込み：** ドキュメント、チケット、リポジトリ、プロジェクト管理ツールなど、
  接続済みシステム内のレコードを作成、更新、削除します。
- **共有：** 情報の送信や公開などを通じて、
  より多くの人やシステム、外部の宛先が情報を利用できるようにします。
- **スケジュール実行：** ユーザーが毎回実行を開始しなくても、
  将来の指定日時または定期的なスケジュールに従ってタスクを開始します。
- **実行：** コードやシェルコマンドの実行、ブラウザの自動操作など、
  外部環境と直接やり取りするタスクをツールで実行します。

影響の大きいアクションには、人によるレビュー、制限付きの認証情報、必要最小限のスコープ、対応する承認機能を使用してください。プラグインのアクションには、引き続き各連携先の権限とセキュリティ制御が適用されます。

### 企業向けのプライバシーとデータに関するコミットメントへの対応

ChatGPT Work には、お客様の ChatGPT ワークスペースに適用される
プライバシー、セキュリティ、データに関するコミットメントが適用されます。対象範囲は、プラン、構成、利用環境、機能、
リージョンによって異なります。ChatGPT Enterprise の場合、これには
[デフォルトでビジネスデータを学習に使用しないこと](https://help.openai.com/en/articles/8983130-what-if-i-want-to-keep-my-history-on-but-disable-model-training)、
転送時と保存時の暗号化、ワークスペースレベルのアクセス制御、
対応する監査ログの記録が含まれます。

データレジデンシー、推論レジデンシー、HIPAA、業務提携者契約への対応は、
すべての環境で一律ではありません。利用中の機能とリージョンについて、最新の
[データおよび推論レジデンシーのガイダンス](https://help.openai.com/en/articles/9903489-data-residency-and-inference-residency-for-chatgpt)と、
お客様の契約内容を確認してください。

接続済みサービスには、保持、ログ記録、アクセス、レジデンシー、コンプライアンスに関する独自の要件があります。ChatGPT Work がプラグイン、リポジトリ、サードパーティのシステムを使用する場合は、ChatGPT ワークスペースの制御と接続先システムの制御の両方を評価してください。

Codex のアクティビティについては、開発環境、
リポジトリ、設定済みのツール、関連するアクティビティにも企業向けの制御を適用できます。ワークスペースの制御と併せて、
[管理者向けロールアウトガイド](/ja-JP/codex/enterprise/admin-setup)と
[ガバナンス](/ja-JP/codex/enterprise/governance)を確認してください。

### 保存、保持、削除の対象となるデータ

ChatGPT Work のデータ保持と削除は、ChatGPT ワークスペースの
プラン、管理設定、利用中の機能によって管理されます。保持の扱いは、
ChatGPT Work がアクセスする情報によって異なる場合があります。会話と対象となる
ライブラリのファイルには、該当するワークスペースの設定が適用されます。プロジェクトのファイル、
一時的にアップロードされたファイル、保存済みのメモリ、コンプライアンスイベント、
同期されたアプリデータ、サードパーティの記録には、個別の保持および削除ルールが適用される場合があります。詳しくは、
[チャットとファイルの保持ポリシー](https://help.openai.com/en/articles/8983778-chat-and-file-retention-policies-in-chatgpt)を参照してください。

ChatGPT Work では、チャット内容、アップロードまたは生成されたファイル、成果物、
実行メタデータが作成される場合があります。Codex のチャットでは、リポジトリまたは環境の
メタデータ、コマンド出力、差分、ログが作成される場合もあります。現在の製品ドキュメントと
[Compliance API](/ja-JP/codex/enterprise/compliance-api) のドキュメントで、正確なデータの種類、
保持期間、削除方法を確認してください。

ChatGPT ワークスペースと接続済みのエンタープライズシステムの両方で保持要件を確認し、組織のデータガバナンス、コンプライアンス、記録保持ポリシーが各システムに適用されるようにしてください。

## オブザーバビリティ

### 管理者やオーナーが確認できる利用状況データ

管理者とオーナーは、製品分析とコンプライアンスログを使って、異なる観点から
利用状況を把握できます。グローバル管理コンソールでは、対応範囲内で ChatGPT と
Codex の導入状況やクレジット使用量を確認できます。ユーザー別、製品別、エージェント別、モデル別の
内訳をどこまで確認できるかは、分析機能とワークスペースによって異なります。対象の
ワークスペースでは、Compliance API から対象となる ChatGPT の会話記録を取得でき、
対応するクラウド上の Work のアクティビティも含まれます。対象範囲は、製品、
利用環境、権限、利用可能なエンドポイント、ドキュメントに記載されたイベントスキーマによって異なります。詳しくは、
[ワークスペースの分析](/ja-JP/codex/enterprise/workspace-analytics)と
[Compliance API](/ja-JP/codex/enterprise/compliance-api) を参照してください。

### プロンプト、出力、ファイル、アクション、ツール呼び出しのログ記録

対象の Enterprise および Edu ワークスペースでは、コンプライアンス・ログ・プラットフォームから
Work のユーザープロンプトとエージェントの応答を確認できます。
[接続済みアプリの呼び出しは別途ログに記録されます](https://help.openai.com/en/articles/11509118-admin-controls-security-and-compliance-in-apps-enterprise-edu-and-business)。
対象のワークスペースでは、対応する
[ライブラリ専用の Compliance API エンドポイント](https://help.openai.com/en/articles/20001052-library-for-chatgpt)から、現在利用可能なライブラリ内のファイルにアクセスできます。
ただし、これらの記録だけでは、ホスト環境でのすべてのファイル操作、
シェルコマンド、ブラウザ操作、ツール呼び出し、承認を網羅する監査証跡にはなりません。
認証が必要な Compliance API ドキュメントで、
現在対象となっているイベントと製品を確認してください。

コンプライアンス・ログ・プラットフォームのデータ保持期間は 30 日です。組織でより長期間の保持が必要な場合は、記録を
承認済みの電子情報開示、データ損失防止、SIEM、
またはデータレイクのシステムへ継続的にエクスポートしてください。詳しくは、
[OpenAI コンプライアンスプラットフォームガイド](https://help.openai.com/en/articles/9261474-compliance-api-for-chatgpt-enterprise-edu-and-chatgpt-for-teachers)を参照してください。

### 異常な動作、障害、利用量の急増の早期検出

ワークスペースの分析、コンプライアンスログ、連携した監視ツールは、管理者による利用状況の確認や、対象となる ChatGPT、Work、Codex のアクティビティの調査に役立ちます。選択したレポート機能に応じて、アクティブユーザー、対象となるメッセージ、アプリのアクティビティ、エージェントの利用状況、認証イベントや管理イベント、クレジット消費量などのシグナルを確認できます。エクスポートしたログは、電子情報開示、データ損失防止、SIEM、監査、調査に利用できます。検出精度は、プラン、イベントの対象範囲、帰属情報、情報の鮮度、設定済みのルールによって異なります。

レビューが必要となる可能性のあるシグナルには、利用量やクレジット消費量の予期しない増加、通常と異なるユーザーやエージェントのアクティビティ、繰り返される運用エラー、関連する認証イベントや管理イベントなどがあります。具体的にどのシグナルを確認できるかは、該当する分析、コンプライアンス、監査ログのスキーマと照合してください。

Codex のアクティビティについては、Codex の分析機能と Analytics API から、対応する
導入状況とアクティビティの指標を確認できます。ローカルの Codex クライアントを使用する組織は、
API リクエスト、エラー、プロンプトのメタデータ、
ツール承認の判断、ツールの実行結果などのイベントを対象とした OpenTelemetry エクスポートにオプトインできます。プロンプトの内容は、
別途明示的にオプトインして `otel.log_user_prompt = true` を有効にしない限り、マスキングされます。
詳しくは、
[監視とテレメトリ](/ja-JP/codex/agent-approvals-security#monitoring-and-telemetry)を参照してください。
このローカル版 Codex のテレメトリでは、
ウェブ版 ChatGPT Work の OpenTelemetry エクスポートは提供されません。

## ガバナンス

### 管理者によるアクセス、権限、ポリシーの制御方法

ガバナンスは、相互に関連しながらも独立した 3 つのレイヤーで構成されます。

- **ChatGPT Work のアクセス制御** では、
  各利用環境で ChatGPT Work を利用できるユーザーを決定します。
- **ワークスペースエージェントの制御** では、ワークスペースエージェントが利用できる場合に、
  再利用可能なエージェントや共有接続の構築、公開、共有、
  スケジュール設定、構成を行えるユーザーを決定します。
- **Codex の管理対象の設定** では、対象となるローカルの Codex ランタイムの動作を管理します。
  ホスト型の ChatGPT Work は設定できません。

管理対象の設定は、対応するランタイムの動作を制限するものです。ワークスペースへのアクセスを付与したり、RBAC の代わりになったり、ユーザーのワークスペースへのアクセスを取り消したりするものではありません。これらのレイヤーは、ChatGPT Work のポリシーを一律に制御する単一の仕組みではありません。分析機能とコンプライアンスログを使用すると、ドキュメントに記載された製品とイベントの対象範囲内で、さらに状況を把握できます。

対応するローカルの Codex クライアントには、エンタープライズ管理者が
[管理対象の設定](/ja-JP/codex/enterprise/managed-configuration)と
[権限プロファイル](/ja-JP/codex/permissions)を適用できます。これらのローカルクライアント向けの制御は、
ホスト型の ChatGPT Work へのアクセス権を付与するものでも、そのワークスペース権限に代わるものでもありません。

### グループ、ロール、ワークスペース、機能ごとのアクセス範囲の設定

はい。カスタムメンバー RBAC に対応した対象のエンタープライズおよび Edu プランでは、
ワークスペースのロール、ID グループ、
管理者が定義した権限を使って ChatGPT Work の機能の利用範囲を設定できます。
ChatGPT Business では、該当するワークスペースレベルの制御を使用しますが、
カスタムメンバー RBAC と SCIM グループ同期は利用できません。
業務上のニーズと組織のポリシーに基づいて、対応する機能を割り当ててください。詳しくは、
[RBAC ガイド](https://help.openai.com/en/articles/11750701-rbac)と
[RBAC の手順ガイド](https://vimeo.com/1207482321/d1286e4467?share=copy&fl=sv&fe=ci)を参照してください。

カスタム RBAC が利用できる組織では、これを使って、ChatGPT Work へのアクセス、ワークスペース設定の管理、承認済みプラグインの構成、対応するワークスペースエージェント機能の使用を許可するユーザーを指定できます。対象となるエンタープライズおよび Edu ワークスペースでは、月間使用量の上限をワークスペースのデフォルト値、グループごとのデフォルト値、ユーザーごとの上書き設定で調整し、段階的なロールアウトに役立てることができます。

接続先システムへのアクセスは、引き続き個別に管理されます。ワークスペースの権限、プラグイン設定、ソースシステムの制御を使って、プラグイン、共有認証情報、リポジトリ、書き込み可能なアクションの利用者を必要最小限に絞ってください。対応するローカルの Codex クライアントでは、管理対象の設定によってローカルランタイムの機能をさらに制限できます。ホスト型の Work には、独自のワークスペース制御と製品固有の制御が適用されます。

### ランタイムとネットワークの境界の管理

ChatGPT Work のセキュリティ境界はタスクによって異なります。標準のチャット、外部システムと連携するワークフロー、スケジュール済みタスク、Codex チャットは、権限、ツール、ネットワークアクセスがそれぞれ異なる環境で実行されることがあります。

各実行環境は、その環境に適用される制御を使って管理してください。Work Cloud は、対応するウェブ、モバイル、デスクトップ環境でのホスト型 Work を管理します。Work Local はデスクトップ上のローカル Work を管理し、Codex Local はデスクトップ、CLI、IDE クライアントでの対応するローカルの Codex アクセスを制御します。ブラウザとシェルのネットワーク権限によって、Work Cloud はさらに制限されます。検索、アプリ、プラグイン、利用可能なワークスペースエージェント、ソースシステムの権限は、それぞれ個別に制御されます。管理対象の設定とローカルランタイムのポリシーが適用されるのは、それぞれが対応するローカルの利用環境に限られます。これらの制御を相互に代用することはできません。

Codex のアクティビティでは、ChatGPT デスクトップアプリ、CLI、IDE でのローカル実行は、オペレーティングシステムのサンドボックスと承認ポリシーに従ってユーザーのマシン上で行われます。Codex Cloud は、OpenAI が管理する隔離された環境でチャットを実行します。対応するローカルクライアントでは、エンタープライズ管理者が管理対象の要件を使って、権限プロファイル、承認、ファイルシステムとネットワークへのアクセス、MCP サーバー、フック、コマンドルール、その他の対応するランタイムの動作を制限できます。

## 使用量とコスト

<a id="how-does-work-usage-translate-into-spend-over-time"></a>
<a id="how-does-work-mode-usage-translate-into-spend-over-time"></a>

### ChatGPT Work の使用量が継続的な支出に与える影響

[ChatGPT Work と Codex は料金体系、クレジット、使用量の上限を共有しています](/ja-JP/codex/pricing)。
対象となるクレジットベースの契約では、従業員のチャットと Work の合計使用量を、
ワークスペースに割り当てられた共有クレジット量と照らし合わせて確認してください。
消費量は、モデル、適用される推論や速度の設定、処理される入力と出力、
対象となるツールや機能によって異なります。

契約済みのクレジットを使っても、請求額が自動的に増えるわけではありません。
実際の請求額は、クレジット残高、契約料金、アカウントで超過利用が認められているかどうか、
ワークスペースに設定された超過利用上限によって異なります。
計画の参考例、実際に適用されるユーザー上限、レポートの対象範囲、請求の詳細については、
[ChatGPT Work：使用量とコスト](/ja-JP/codex/enterprise/chatgpt-work-usage-and-cost)を参照してください。

使用量の変動が特に大きくなりやすいのは、頻繁に実行される、大量の情報を取得または処理する、複数のツールやアプリを呼び出す、失敗後に再試行する、大きな成果物を生成するといったワークフローです。コストに注意が必要な例には、スケジュール済みまたは定期的な作業、大容量のファイル、企業内の幅広いソースからの情報取得、繰り返されるアプリの呼び出し、リポジトリの処理、コマンドの実行、クラウド環境の利用を伴う Codex チャットなどがあります。ワークスペースエージェントの API トリガーが利用可能な場合、そのトリガーによって使用量が増えることもあります。

支出制御、使用状況の分析、レポートを使って、これらのパターンを継続的に監視してください。現在の分析画面で対応している項目別に使用状況を確認し、業務上の価値に応じて上限やロールアウトの範囲を調整します。集計された分析結果を、ワークフローごとの正確なコスト内訳として扱わないでください。

ワークスペースの分析、コンプライアンスログ、連携した監視ツールは、管理者が使用状況を確認し、対応するアクティビティを調査するのに役立ちます。リスクのある動作や通常と異なる動作を検知できるかどうかは、プラン、ログの対象範囲、帰属情報、データの鮮度、監視システムに設定されたルールによって異なります。

### 利用可能な使用量制限、アラート、上限

対象となるエンタープライズおよび Edu ワークスペースでは、クレジットベースの利用について、ユーザーごとの月間上限とワークスペース全体の支出制御を利用できます。

- **クレジット消費量の監視：** Global Admin Console とワークスペースの設定で、
  対応するクレジット使用量レポートを確認します。
- **月間上限のデフォルト値の設定：** ワークスペースで使用する、
  ユーザーごとのクレジット上限のデフォルト値を設定します。
- **グループ別の上限の適用：** 各グループのワークフロー、担当業務、ロールアウト段階に応じて、
  ユーザーごとの月間上限のデフォルト値を設定します。
- **ユーザーごとの上書き設定の作成：** グループ全体のデフォルト値は変更せず、
  特定のユーザーに別の上限を設定します。
- **上限引き上げリクエストのレビュー：** リクエスト機能が有効な場合、
  ユーザーは月間上限の引き上げをリクエストできます。承認すると、ユーザーごとの上書き設定が作成されます。
- **ワークスペース全体の支出リスクの管理：** Global Admin Console で、
  ワークスペースのクレジットアラートと超過利用上限を個別に設定します。
  アラートは受信者に通知し、超過利用上限は、
  契約済みのクレジットプールを使い切った後の対象となる利用を制限します。
- **使用量データのエクスポート：** 対象となるエンタープライズ管理者は、
  統合 Cost API を通じてクレジット使用量のデータにアクセスし、
  社内のレポート作成や監視に利用できます。

ユーザーは自身の使用量を確認でき、機能が有効な場合は追加のクレジットをリクエストできますが、
割り当てられた上限を変更することはできません。詳しくは、
[使用量の上限と超過利用の管理](https://help.openai.com/en/articles/20001001-manage-usage-limits-and-overages-in-chatgpt-enterprise-and-edu)
および
[支出制御の手順ガイド](https://vimeo.com/1207484127/0f2029dd01?share=copy&fl=sv&fe=ci)を参照してください。

## インシデント対応とアクセス取り消しの制御

### 管理者によるアクセスやアクティビティの停止方法

ユーザーを削除する際やインシデントを確認する際には、管理者がアクセスの停止、アプリの無効化、共有認証情報の取り消し、スケジュール済みタスクの一時停止、Codex の認証情報の取り消しを行う必要がある場合があります。

取り消しには、次の方法があります。

- ユーザーのワークスペースまたはグループへのアクセス権を取り消します。SCIM で管理されているユーザーの場合は、ID プロバイダーでアクセス権を取り消してください。そうしないと、その後の同期でユーザーが再びプロビジョニングされる可能性があります。
- 該当するプラグインまたはアプリを無効化するか、利用を制限します。
- 共有接続、ボット、サービスアカウントは、それぞれの管理画面から取り消します。ワークスペースの所有者と管理者は、Codex ワークスペースのアクセストークンを別途取り消すことができます。
- エージェントの所有者またはワークスペース管理者が、ワークスペースエージェントの公開を停止するか、エージェントを削除します。
- 該当するスケジュール済みタスク、または利用可能な場合はワークスペースエージェントの API トリガーを無効にします。
- Codex へのアクセスについては、該当するアクセストークン、リポジトリ接続、クラウド環境へのアクセス権を個別に取り消します。管理対象の設定は、アクセス権を取り消すための仕組みではありません。

## 管理者に推奨される対応

- **最初にアクセスを許可する対象を確認します。** 
  ChatGPT Work へのアクセスを制限するか、試験運用を行うか、広く展開するかを決定します。
  多くの組織では、パワーユーザー、推進担当者、明確なユースケースを持つチームから導入を始めます。
- **ロールと権限を確認します。** 「 **権限とロール**」で、
  ChatGPT Work にアクセスできるユーザーやグループを確認します。
  業務上の必要性や準備状況、求められるガバナンスの水準に合わせてアクセス権を設定します。
- **プラグインとデータソースを確認します。** 
  ChatGPT Work は、ファイル、メール、カレンダー、Slack、CRM などの承認済みの業務コンテキストを利用すると、最も効果を発揮します。
  有効なプラグインとその利用対象者を確認します。
  アプリのポリシーが、ユーザーに求められる作業の任せ方に引き続き合っているかも見直します。
- **適切なユースケースを明確に示します。** 
  ChatGPT Work は、複数のステップを伴う、より価値の高いタスク向けに位置付けます。
  具体例として、リサーチ、情報の統合、分析、ファイル作成、ワークフローの更新、再利用可能な成果物の作成が挙げられます。
  簡単な質問、軽微な書き換え、ブレインストーミングにはチャットを使用します。
- **クレジットと利用量の管理設定を確認します。** 
  ChatGPT Work は長時間にわたるタスクを実行できるため、通常のチャットでの会話よりも多くのクレジットを消費する場合があります。
  デフォルト設定、グループ単位のデフォルト設定、ユーザーごとの上書き設定を確認します。
  業務上の価値に見合った労力をかけるための社内ガイダンスも見直します。
- **最初に取り組む価値の高いワークフローを特定します。** 
  明確でレビュー可能な成果を得られる業務から始めます。
  例として、顧客ブリーフィング、定期レポート、リサーチ結果の統合、トラッカーの更新、完成度の高い文書やスライドなどが挙げられます。
- **推進担当者とサポートチームの体制を整えます。** 
  推進担当者、トレーニング責任者、サポートチームに展開用のリソースを優先的に提供します。
  質問に答え、フィードバックを収集し、効果的な作業の任せ方の手本を示せるようにします。
- **レビューと承認で求められる対応を周知します。** 
  出力を共有または利用する前に、その内容をレビューし、重要な主張を検証し、影響の大きいアクションを承認する必要があります。
  これらの責任は引き続き人が負うことを、ユーザーに伝えます。
- **利用の定着状況を継続的に確認し、調整します。** 
  展開後に、利用状況、フィードバック、クレジット消費量、任せた作業を確認します。
  得られた知見を基に、アクセス権、ガイダンス、トレーニング、展開範囲を調整します。
