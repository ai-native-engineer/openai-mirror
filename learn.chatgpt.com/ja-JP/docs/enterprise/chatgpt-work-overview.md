ChatGPT Work と Codex は、実行、分離、権限管理に関する基本的な仕組みを共有しており、ChatGPT Business または Enterprise の契約に定められた同一のセキュリティ境界内で動作します。それぞれで利用できる機能と制御項目は、タスクがローカルとクラウドのどちらで実行されるか、使用できるツール、適用されるワークスペースポリシーによって異なります。

ChatGPT Work は、権限を持つワークスペースメンバーが利用できる情報、ファイル、アプリケーション、ツールを使用して、複数のステップから成るタスクを完了できます。ウェブ版では、これらのタスクはメンバーのデバイスではなく、クラウド上で実行されます。

この概要では、実行環境の境界、ネットワークとアプリケーションの制御、データの取り扱い、ウェブ版の ChatGPT Work でタスクを安全に実行する仕組みについて説明します。機能の利用可否と管理者向けの制御項目は、プランとワークスペースの構成によって異なります。

ホスト環境での実行、接続済みアカウントの権限、
ブラウザとネットワークの設定、データ保持、監査で確認できる情報について詳しくは、
[ChatGPT Work のクラウドセキュリティ](/ja-JP/codex/enterprise/chatgpt-work-cloud-security)をご覧ください。

デバイスへのアクセス、ローカルブラウザのセッション、管理ポリシー、
ローカルデータの取り扱いについては、
[ChatGPT Work のローカルセキュリティ](/ja-JP/codex/enterprise/chatgpt-work-local-security)をご覧ください。

## 実行環境の分離、ファイル、デバイスへのアクセス

ChatGPT Work が利用できるファイルとツールは、Work の実行場所、ユーザーの権限、管理者の設定によって異なります。

### ローカル Work

ローカル Work は、ユーザーのデバイス上の ChatGPT デスクトップアプリを通じてタスクを実行します。ユーザーの権限、適用されるワークスペースの制御、デバイスのセキュリティポリシーに従い、利用が許可されたローカルファイル、アプリケーション、その他のリソースにアクセスできます。Web 上の Work とは異なり、クラウド上の会話にファイルをアップロードすることなく、コンピューター上に置いたままのリソースを操作できます。

### クラウド Work

クラウド Work は、対応するウェブ版、モバイル版、デスクトップ版で利用できます。OpenAI が管理するインフラストラクチャ上の隔離された環境で、Codex ハーネスを実行します。クラウド上の会話はこれらの環境間で同期でき、対応するタスクは、ユーザーが会話画面を離れている間も継続できます。

ウェブ版の Work は、ユーザーのコンピューター上にあるファイルやアプリケーション、開いているブラウザのタブに直接アクセスできません。ユーザーは、ファイルをアップロードするか、対応するプロジェクトに追加するか、認可された接続済みアプリを使用することで、ファイルを提供できます。デスクトップ版では、独自の権限設定によってローカルファイルとアプリケーションへのアクセスが制御されます。

アップロードまたは生成した対象ファイルは、
[ライブラリ](https://help.openai.com/en/articles/20001052-file-storage-and-library-in-chatgpt)が利用可能な場合、
そこに保存できます。
管理者は、ChatGPT がライブラリに保存されたファイルを自動的に参照するかどうかを制御できます。
自動参照を無効にしても、
ユーザーが利用を許可されたファイルに明示的にアクセスしたり、そのファイルを添付したりすることは妨げられません。

[コードとシェルのサンドボックス](/ja-JP/codex/sandboxing?surface=web)、
[ドキュメント、スプレッドシート、プレゼンテーションの作成と編集](https://help.openai.com/en/articles/20001278-creating-and-editing-documents-spreadsheets-and-presentations-with-chatgpt-work)、
および
[ChatGPT でのファイル保存とライブラリ](https://help.openai.com/en/articles/20001052-library-for-chatgpt)をご覧ください。

## ネットワークアクセスと外部接続先

Work は、コードやシェルの実行、クラウドブラウザなどのツールを使用してタスクを完了します。これらのツールごとに権限を設定できます。

- **コードとシェルコマンド**：パブリックインターネットへのアクセスは、
  適用されるワークスペースポリシーと Work の個別のネットワーク設定によって決まります。
  パブリックインターネットへのアクセスが許可されていない場合でも、
  Work の動作に必要な OpenAI 承認済みの接続先にはコマンドからアクセスできます。
  この設定が制御するのはネットワークの接続先であり、実行できるコマンドの種類ではありません。
- **ウェブ検索**：検索の制御設定は、
  Work のコードとシェルのネットワーク設定とは別です。

コードとシェルの個別設定は、利用可能な場合、
**設定** \> **データコントロール** \> **Work のネットワークアクセス**に表示されます。 **パブリックインターネットへの
アクセスを許可する** をオンにしても、適用される管理者の制限は上書きされません。
オフにすると、コードとシェルコマンドの接続先は、
管理対象の許可リストに含まれる必要な接続先に制限されます。
接続済みアプリ、ウェブ検索、クラウドブラウザは無効になりません。

コードとシェルのネットワーク設定の変更は、現在の実行が終了し、
Work が実行環境を更新した後に有効になります。詳しくは、
[コードとシェルのサンドボックス](/ja-JP/codex/sandboxing?surface=web)および
[Work のアクセス制御](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex)をご覧ください。

外部への通信に関する制御は、
[ワークスペースの IP アクセス制限](https://help.openai.com/en/articles/12111596-ip-allowlisting-for-chatgpt)とは別です。
後者は、ChatGPT ワークスペースまたは Compliance API への外部からのアクセスを制限します。

## クラウドブラウザとウェブサイトへのアクセス

ChatGPT Work が利用できるツールの一つに、
[クラウドブラウザ](https://help.openai.com/en/articles/20001280-using-cloud-browser-in-chatgpt)があります。
これは、
[アプリ内ブラウザ](https://help.openai.com/en/articles/20001277-using-the-built-in-browser-in-the-chatgpt-desktop-app)とは別のツールです。
クラウドブラウザはリモートで動作し、
ユーザーのローカルブラウザとは別のブラウザセッションを使用します。ローカルのタブ、拡張機能、閲覧履歴、保存されたパスワード、
認証済みのローカルセッションにはアクセスできません。

クラウドブラウザでは、公開ウェブサイトを閲覧したり、対応する公開フォームに情報を入力したり、承認済みアプリの関連情報を使ってウェブサイト上のタスクを進めたりできます。Enterprise と Edu のワークスペースでは、クラウドブラウザを通じたウェブサイトへのサインインは利用できません。ブラウザの利用可否は、プラン、地域、提供状況、ワークスペースの権限によって異なります。Enterprise ワークスペースでは、管理者が Work へのアクセスに加えて、クラウドブラウザへのアクセスも有効にする必要があります。

ウェブサイトへのアクセスと操作は、それぞれ別に制御されます。

- 既定では、ChatGPT は新しいウェブサイトにアクセスする前に確認を求めます。
  利用可能な場合、ユーザーは **常に確認する**、 **自動承認**、 **常に許可する**から選択でき、
  個々のウェブサイトを許可またはブロックできます。 **自動承認** では、自動化されたリスクチェックが実施されます。
**常に許可する** では、ウェブサイトへのアクセス時に行う対話形式のレビューが省略されます。管理者も同様に、
  ユーザーの承認設定を制限できます。たとえば、
   **常に許可する** をワークスペース全体で無効にできます。
- ウェブサイトへのアクセスを許可しても、そのサイト上のすべての操作が承認されるわけではありません。ChatGPT は、金銭、法律、アカウントなどに関して重大な責任や義務が生じる可能性のある操作の前に、別途確認を求めることがあります。

ユーザーは Work の会話で、提供されているページのスクリーンショットやブラウザ操作の再生を確認できます。これらのユーザー向けの記録は、Compliance API でエクスポートできることや、管理者が閲覧できる完全な実行履歴が存在することを意味するものではありません。

詳しくは、
[ChatGPT でのクラウドブラウザの使用](https://help.openai.com/en/articles/20001280-using-cloud-browser-in-chatgpt)および
[ブラウザ](/ja-JP/codex/browser?surface=web)をご覧ください。

## 接続済みアプリケーション、認証情報、権限

接続済みアプリまたはプラグインを通じた Work のアクセスは、ワークスペースで許可された連携機能と、その接続に付与された権限の範囲内に限られます。管理者は管理ダッシュボードで、プラグインやアプリの利用可否、ワークスペースのロールごとのアクセス、外部認可、操作の設定、連携元システムの権限を制御できます。

Enterprise と Edu のワークスペースでは、プラグインと、それらが利用するアプリは既定でオフになっています。Business のワークスペースでは、プラグインとアプリは既定でオンになっています。プラグインを利用可能にしても、必要なアプリが自動的に有効になったり、アカウントへのアクセス権が付与されたりすることはありません。ChatGPT Work がアクセスするには、個人用、共有、またはエージェント所有のアカウントについて、必要な接続が認可されている必要があります。共有またはエージェント所有の接続では、接続先アカウントが連携元システムで持つ権限が使用されます。この権限は、リクエストしたユーザーの権限と異なる場合があります。

対応している場合、管理者はアプリの操作を読み取り専用の操作、または承認された一連の操作に制限できます。アプリの権限設定によって、ChatGPT がアプリを使用する前、変更を加える前、重要な操作を実行する前に確認を求めるかどうかも決められます。すべてのアプリが同じ操作制御に対応しているわけではなく、すべての操作に人による個別の確認が必要なわけでもありません。

同期機能を使用するアプリでは、元のコンテンツや権限の変更が反映されるまでに時間がかかることがあります。アプリとの接続を解除しても、会話、生成済みファイル、独自の保持ポリシーが適用される記録にすでに保存された情報は、自動的には削除されません。

詳しくは、
[プラグインとアプリの管理者向け制御、セキュリティ、コンプライアンス](https://help.openai.com/en/articles/11509118-admin-controls-security-and-compliance-in-apps-enterprise-edu-and-business)、
[プラグインの制御](/ja-JP/codex/enterprise/apps-and-connectors)、
[管理者による Google Workspace のセットアップ](https://help.openai.com/en/articles/10929079-google-workspace-admin-managed-setup)、
[同期機能付き ChatGPT アプリ](https://help.openai.com/en/articles/10847137-chatgpt-apps-with-sync)をご覧ください。

## プライバシーとデータの取り扱い

ChatGPT Work は、利用している ChatGPT ワークスペースに適用されるプライバシー、セキュリティ、データの取り扱いに関するポリシーに従います。会話、アップロードしたファイル、生成したファイル、接続済みアプリケーション、ブラウザデータには、それぞれ異なる保持および削除のルールが適用される場合があります。

詳しくは、[エンタープライズのプライバシー](https://openai.com/enterprise-privacy/)、
[チャットとファイルの保持ポリシー](https://help.openai.com/en/articles/8983778-chat-and-file-retention-policies-in-chatgpt)、
[データレジデンシーと推論レジデンシー](https://help.openai.com/en/articles/9903489-data-residency-and-inference-residency-for-chatgpt)、
[ChatGPT Work 管理者向けのよくある質問](/ja-JP/codex/enterprise/work-admin-faq)をご覧ください。

### データの種類ごとに異なる保持ルール

- **Work の会話：** 
  ChatGPT ワークスペースの会話に適用される保持設定と削除設定に従います。
- **ライブラリに保存したファイル：** ファイルとワークスペースに適用される保持ルールに従います。
  会話を削除しても、
  ライブラリに保存したファイルは削除されません。
- **プロジェクトのファイル：** 適用される削除ルールと例外に従い、
  プロジェクトが削除されるまで、そのプロジェクトに保持されます。
- **ライブラリ以外への一時的なアップロード：** Enterprise では、
  別の保持設定が適用されない限り、一時的にアップロードしたファイルが 48 時間後に期限切れになる場合があります。
- **保存済みメモリ（有効な場合）：** メモリに関する個別の制御設定に従います。
- **クラウドブラウザの Cookie：** ローカルブラウザのデータとは別に保持されます。
  ユーザーはクラウドブラウザの設定から削除できます。
- **コンプライアンス・ログ・プラットフォームの記録：** プラットフォーム上で 30 日間利用できます。
  エクスポートしたコピーには、受け取り先のシステムの保持ポリシーが適用されます。
- **接続済みアプリケーションのデータ：** 元の記録には、
  接続先アプリケーションのポリシーが適用されます。チャット、ファイル、同期済みインデックスに保存されたコピーには、
  該当する OpenAI の保存および保持ルールも適用されます。

会話の削除、Work タスクの終了、ブラウザの Cookie の削除、コンプライアンス記録の保持は、それぞれ別の操作です。チャットを削除すると表示されなくなり、30 日以内の完全削除が予定されます。ただし、公表されているセキュリティ上の例外、法的な例外、非識別化に関する例外が適用されます。

[チャットとファイルの保持ポリシー](https://help.openai.com/en/articles/8983778-chat-and-file-retention-policies-in-chatgpt)、
[ChatGPT のメモリ](https://help.openai.com/en/articles/8590148-memory-in-chatgpt-faq)、
および
[OpenAI コンプライアンスプラットフォーム](https://help.openai.com/en/articles/9261474-compliance-api-for-chatgpt-enterprise-edu-and-chatgpt-for-teachers)をご覧ください。
