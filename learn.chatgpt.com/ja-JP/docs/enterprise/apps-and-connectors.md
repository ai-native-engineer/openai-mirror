プラグインは再利用可能なワークフローをまとめたもので、
ほかのツールに接続するスキルやアプリを含めることができます。ChatGPT と Codex は、
対応する環境で同じ公開プラグインディレクトリを使用し、ワークスペースで利用できるプラグインは管理者が決定します。
詳しくは、[プラグイン](/ja-JP/codex/plugins)、
[スキル](/ja-JP/codex/skills-and-plugins)、
[アプリとコネクタ](https://help.openai.com/en/articles/11487775)をご覧ください。

メンバーがコネクタ連携機能を使用できるのは、プラグインとアプリがそのメンバーのロールで利用可能で、かつ接続先サービスへのアクセス権がある場合に限られます。

プラグインは、Web 版、デスクトップ版、モバイル版の ChatGPT のチャットと Work、ChatGPT デスクトップアプリ内の Codex、Codex CLI のプラグインブラウザで利用できます。IDE 拡張機能では利用できません。

これらの制御とワークスペースのロールおよび権限との関係については、
[ロールとワークスペースの権限](/ja-JP/codex/enterprise/roles-and-workspace-permissions)をご覧ください。

## 機能利用に関わる制御の仕組み

プラグインは、次の複数の制御レイヤーにまたがる場合があります。

| レイヤー                   | 決定される内容                                                           | 管理場所                                                                                                              |
| ----------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 利用可否            | ユーザーがプラグインバンドルを利用できるかどうか                           | 対応する Web 版とデスクトップ版では[ワークスペース設定](https://chatgpt.com/admin/settings)、CLI では CLI プラグインブラウザ |
| 含まれるスキル         | インストール済みのプラグインが提供する再利用可能な指示                 | プラグインパッケージと[スキルの制御](/ja-JP/codex/enterprise/skills)                                                               |
| アプリへのアクセス              | ユーザーがコネクタ連携機能を利用できるかどうか                          | [ワークスペースのアプリ](https://chatgpt.com/admin/ca)と[権限とロール](https://chatgpt.com/admin/settings)                    |
| アクションと権限 | ユーザーが実行できるアクションと、コネクタを使用する前に ChatGPT が確認を求めるタイミング | [ワークスペースのアプリ](https://chatgpt.com/admin/ca)にあるコネクタのアクションの制御と App の権限                            |
| サービスの認可   | 認証済みの ID がアクセスできる外部データとアクション        | 接続先サービスとその ID プロバイダー                                                                                 |
| ランタイム権限     | エージェントがデータやツールを受け取った後に実行できること                        | 利用中の環境におけるランタイム、サンドボックス、承認の制御                                                              |

これらのレイヤーを使い、2 段階で導入を進めます。まず適切なプラグインを利用可能にし、その後、各ワークフローに必要な機能と権限を設定します。

## ステップ 1：プラグイン利用の有効化

対応する Web 版とデスクトップ版では、ワークスペースのプラグイン制御によって、
どのロールがプラグインを使用またはインストールできるかが決まります。Codex CLI では、
専用のプラグインブラウザからインストールします。
[プラグインを作成する](https://developers.openai.com/plugins/build/plugins)では、
パッケージ化と配布について説明しています。

GitHub からワークスペースのプラグインをインポートし、最新の状態に保つ方法については、
[プラグインの管理](/ja-JP/codex/enterprise/plugin-management)をご覧ください。

### レビュー用の公開カタログのエクスポート

対象となる ChatGPT Enterprise ワークスペースのオーナーと管理者は、そのワークスペースで利用できる公開プラグインの一覧を CSV 形式でダウンロードできます。プラグインの利用可否を変更する前に、エクスポートしたデータを使用して、プラグイン、アプリ、スキルのメタデータをレビューしてください。

1. [管理 \> プラグイン](https://chatgpt.com/admin/plugins)を開きます。
2. **公開**を選択します。
3. ページヘッダーにあるダウンロードアイコン（**CSV をエクスポート**）を選択します。

ダウンロードされるファイルの名前は `public-plugins-security-review.csv` で、次の項目が含まれます。

- プラグインのメタデータ：`Plugin Name`、`Plugin Description`、`Date Added (UTC)`、
`OpenAI Verified`、`Developer Name`、`Version`
- アプリのメタデータ：`App Name(s)`、`App Description(s)`
- チャットスキルのメタデータ：`Skill Name(s)`、`Skill Description(s)`

プラグインに複数のアプリやスキルが含まれている場合、対応する値はセミコロンで区切られます。エクスポートには、最大 48 時間前の公開カタログのスナップショットが使用されます。現在のワークスペースで表示できる公開プラグインのみが含まれ、そのワークスペース向けに作成されたプラグインは含まれません。この機能は FedRAMP ワークスペースでは利用できません。

## ステップ 2：機能の管理

  ChatGPT でアプリやプラグインを利用可能にしても、接続先サービスのファイル、レコード、アクションへのアクセス権は付与されません。トラブルシューティングやアクセス範囲の拡大を行う前に、メンバーのワークスペースでのロールと承認済みのアクション設定を確認してください。そのうえで、認証済みのアカウントまたは共有接続に、接続先サービスで想定どおりの権限があることを確認します。

ChatGPT と Codex のプラグインには、外部システムの検索、データの取得や同期、外部システムでの操作を行うコネクタを含めることができます。プラグインの利用可否と、各コネクタに付与されるアクセス権やアクションは、それぞれ別に制御されます。

コネクタ連携機能は、
[ワークスペースのアプリ](https://chatgpt.com/admin/ca)と
[権限とロール](https://chatgpt.com/admin/settings)から管理します。管理者は利用可能な制御機能を使って、
次の操作を行えます。

- アプリやコネクタを有効にし、ワークスペースのロールに応じてアクセス権を割り当てます。
- アクションの制御に対応するコネクタでは、読み取り専用のアクション、または承認済みのカスタムアクションセットを許可し、新たに追加されたアクションをワークスペースでどう扱うかも設定します。
- ChatGPT がアプリを使用する前に確認を求めるタイミングを定める App の権限を設定します。
- 接続先の各サービスと認証済みユーザーが付与したスコープおよび権限の範囲内にアクセスを制限します。

最新の対応状況と手順については、
[アプリの管理機能、セキュリティ、コンプライアンス](https://help.openai.com/en/articles/11509118)をご覧ください。

## 初期導入対象の絞り込み

業務上の必要性が明確なプラグインから導入してください。プラグインごとに、全員が利用できるようにするか、特定のロールや試験導入グループに限定するか、追加のレビューを求めるかを判断します。

接続先サービスごとに、業務上の責任者、利用が許可されたデータ、承認済みの読み取りまたは書き込みアクション、認証方法、サポートや削除に関する連絡先を記録します。

書き込みアクションを有効にしたり、新しい連携機能を公開したりする前に、対象となるロールの範囲を確認し、接続先サービスで想定した権限だけを持つアカウントでテストしてください。

幅広く展開する場合は、メール、
カレンダー、ファイル管理やドキュメント管理のシステムなど、チームが日常的に使用するカテゴリから始めてください。
[プラグインディレクトリ](https://chatgpt.com/apps)を参照して、
対応する ChatGPT と Codex の各環境における最新の利用可否と機能を確認してください。

初期導入対象にかかわらず、読み取りアクションから始めてください。書き込みアクションを有効にする前に、プラグインの所有者を特定し、コネクタのスコープとサービスの権限をレビューして、データへのアクセス権を確認し、外部への影響と復旧手順を文書化します。

## データフローとセキュリティ

ChatGPT がプラグインに含まれるアプリやコネクタを使用すると、接続先サービスにリクエストを送信し、そのサービスにおける認証済みユーザーの権限で許可されたデータまたはアクションの結果を返します。

ChatGPT は、接続されたアプリのデータを次の 2 通りの方法で処理します。

- **同期なし：** ChatGPT はチャットと deep research のデータを一時的に処理し、
  インデックス化しません。
- **同期あり：** ChatGPT は、接続先のコンテンツのうち選択されたものをあらかじめインデックス化します。
  アプリが同期に対応しているかどうかは、そのプラグインページで確認できます。

モードによって ChatGPT が接続先のコンテンツをインデックス化する方法は変わりますが、通常のチャット保持設定が置き換わるわけではありません。アプリを使用した ChatGPT の会話は、引き続き Compliance API を通じて利用できます。

OpenAI のアプリに関するガイダンスでは、転送中および保存時の暗号化、ユーザーごとの認可、ロールとアクションの制御、アプリを使用する会話でのネットワークアクセス制限について説明しています。また、Business、Enterprise、Edu のお客様については、アプリ経由でアクセスした情報をモデルの学習に使用しないことも明記しています。リクエストが接続先のサービスに届くと、そのサービスのスコープ、データ保持、データレジデンシー、その他のポリシーも適用されます。

データの取り扱いに関する最新情報は、[アプリのセキュリティとコンプライアンス](https://help.openai.com/en/articles/11509118)と
[同期対応アプリ](https://help.openai.com/en/articles/10847137)を参照してください。
ChatGPT デスクトップアプリ、Codex CLI、または IDE 拡張機能で
ローカルに構成した MCP サーバーについては、
[Codex の MCP 構成](/ja-JP/codex/extend/mcp)を参照してください。
