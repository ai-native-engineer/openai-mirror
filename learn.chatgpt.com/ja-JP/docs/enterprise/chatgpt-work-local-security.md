ChatGPT Work は、ユーザーのコンピューター上にある承認済みのファイル、アプリケーション、ブラウザセッションを使って、ローカル環境のタスクを完了できます。アクセス範囲は、ワークスペースの権限、ユーザーが既存のアカウントでアクセスできる範囲、OS の権限、アプリケーションの承認、対応するデバイスポリシーによって決まります。

利用できるローカル機能は、デスクトップアプリと OS の対応状況、ワークスペースの利用権、ロールの権限、デバイスポリシー、製品の展開状況によって異なります。

## セキュリティの要点

- ローカル環境のタスクは ChatGPT デスクトップアプリを通じて実行されます。同じアプリでホスト型のクラウドタスクを開いても、そのタスクがローカルで実行されるわけではありません。

- ローカルおよびホスト型の Work で利用できる制御機能は、ワークスペースの設定と展開状況によって異なります。

- ファイルへのアクセス、コンピューターの使用、ブラウザ、接続されたアプリには、それぞれ異なる権限と承認が適用されます。

- 企業システムにすでにサインインしているブラウザやアプリケーションを使うと、そのアカウントの権限でアクセスできる場合があります。

- 対応する管理対象デバイスのポリシーにより、ワークスペースのアクセス制御を置き換えることなく、ローカル機能を制限できます。

- 対象の OpenAI サービスで処理される Business、Enterprise、Edu のワークスペースデータは、転送中も保存時も暗号化され、デフォルトでは OpenAI モデルの学習に使用されません。

- ローカルファイル、タスクのコンテキスト、ブラウザデータ、接続先システムの記録、監査イベントには、それぞれ異なる保存と保持のルールが適用される場合があります。

## ローカル環境のタスクの実行場所

Work のローカル環境では、ユーザーのコンピューター上のデスクトップアプリを通じて、承認済みのリソースにアクセスします。Work のクラウド環境は、同じデスクトップアプリから開いた場合でも、OpenAI が管理するインフラストラクチャ上で動作します。

ローカルファイルはデバイス上に保持できますが、タスクを完了するために、関連するファイルの抜粋、プロンプト、スクリーンショット、ブラウザのコンテンツ、ツールの実行結果が OpenAI サービスに送信される場合があります。ローカルでの実行は、モデルの推論がオフラインまたはデバイス内だけで行われることを意味しません。

## ファイルとデバイスへのアクセス

ローカル環境のタスクでは、対応するファイル、アプリケーションのコンテンツ、ブラウザセッション、認可された接続先システムなど、ユーザーが提供した情報や利用可能にした情報を扱えます。アクセス範囲は、ユーザーがすでに持っている権限と、その機能に適用される制御によって決まります。

ローカルでの Work の利用を許可しても、すべてのアプリケーションが自動的に承認されたり、管理者権限が付与されたり、別のシステムへのアクセスに使用するアカウントの権限制約を回避できたりするわけではありません。承認済みの共有接続は、ユーザーの個人アカウントとは異なる権限を持つ場合があります。

## コンピューターの使用とアプリケーションの承認

[コンピューターの使用](/ja-JP/codex/computer-use)で対応するデスクトップアプリケーションを操作できるのは、その機能が利用可能で、必要な OS の権限が付与され、ユーザーがそのアプリケーションの使用を許可している場合に限られます。利用できるオプションに応じて、承認を現在のセッションまたは今後のタスクに適用できます。

macOS では、「画面収録」の権限により、コンピューターの使用機能がアプリケーションの内容を確認できるようになり、「アクセシビリティ」の権限により、クリック、入力、画面内の移動が可能になります。対応する macOS のタスクはバックグラウンドで実行できます。Windows では、コンピューターの使用機能は表示中のアクティブなデスクトップ上で動作し、ユーザーが同じセッションを使い続けている間にバックグラウンドで実行することはできません。

ユーザーはいつでもタスクを停止できます。コンピューターの使用では、OS のセキュリティ確認での承認、管理者としての認証、ターミナルアプリケーションや ChatGPT 自体の操作の自動化はできません。

### ロックされたデバイス

対応する macOS 構成では、承認済みの「コンピューターの使用」タスクを、Mac のロック中も継続できるように任意で設定できます。利用できるかどうかは、アプリのバージョン、機能の展開状況、適用される要件、リモート操作の利用条件を満たしているかどうかによって決まります。

管理者は、対応する管理対象の設定を通じて、ロック中のデバイス操作を無効にできます。Windows のコンピューターの使用には、アクティブでロックされていないデスクトップが必要です。macOS でロック中の使用が可能だからといって、Windows でも同様に対応しているわけではありません。

## ブラウザセッションと既存のサインイン状態

Work のローカル環境から、すべてのブラウザや企業アカウントに自動的にアクセスできるわけではありません。アクセス範囲は、使用するブラウザ、サインインしているアカウント、そのブラウザの利用方法で必要となる承認によって決まります。

| ブラウザの操作経路                                | セッションとセキュリティ境界                                                                                                                                                                                                 |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [デスクトップのアプリ内ブラウザ](/ja-JP/codex/browser)    | ユーザーが通常使っているブラウザとは別のブラウザプロファイルを使用します。そのプロファイル内でサインインできます。対応するウェブサイトへのアクセスには承認が必要な場合があります。内蔵ブラウザではファイルのアップロードを自動化できません。              |
| [Chrome 拡張機能](/ja-JP/codex/chrome-extension) | 拡張機能とウェブサイトへのアクセスが承認されると、既存のブラウザタブやアカウントを操作できます。ユーザーはサイトへのアクセスを 1 回限りで承認することも、今後のアクセスを許可することもできます。閲覧履歴やローカルファイルへのアクセスには、別途レビューが必要です。 |
| コンピューターの使用によるブラウザ操作            | デスクトップアプリケーションとして承認されたブラウザを使用し、そのブラウザにサインイン済みのアカウントも利用します。OS の権限、アプリケーションの承認、既存のアカウントの権限は引き続き適用されます。               |

ウェブサイトの承認オプションや、慎重な扱いが必要な操作の確認は、ブラウザの利用方法によって異なります。すべてのサイトを許可すると、その後の承認リクエストが減るため、有効にする前にその設定でよいか確認してください。

ホスト型のクラウドブラウザはユーザーのローカルブラウザとは別のもので、既存のサインイン状態を自動的に引き継ぐことはありません。対応するクラウドワークフローでは、ユーザーの許可を必要とするサインインを別途求める場合があります。

## アプリ、プラグイン、接続されたアカウント

接続されたアプリを通じて、別のシステムの情報や操作にアクセスできます。プラグインはアプリをツールとして内部で使用できます。プラグインを利用可能にしても、必要なアプリが自動的に有効になったり、アカウントが認可されたり、すべての操作が許可されたりするわけではありません。

プラグインとアプリを利用できるかどうかは、ワークスペースのプランと設定によって決まります。[ChatGPT Work の概要](/ja-JP/codex/enterprise/chatgpt-work-overview)では、プラグインと、それらが内部で使用するアプリは、Enterprise と Edu のワークスペースではデフォルトでオフ、Business のワークスペースではデフォルトでオンであると説明されています。対象のワークスペースと製品の利用環境で、実際の設定を確認してください。

タスクで接続先システムを使用する前に、ワークスペースでアプリと必要なプラグインが許可されていること、接続が認可されていること、接続されたアカウントが要求された情報にアクセスしたり操作を実行したりできることを確認してください。読み取り専用の設定、許可される操作、確認の要件は連携ごとに異なります。

デスクトップ専用プラグイン、ローカルツール、その他のローカルで提供される機能では、インストールや承認の手順が異なる場合があります。すべてのローカルツールで同じ管理者承認プロセスが使われると想定しないでください。

### 個人用接続と共有接続

個人用接続では、接続したユーザーが連携元システムで持つ権限を使用します。共有接続やエージェントが所有する接続では、接続されたアカウントの権限を使用するため、ユーザー自身のアクセス範囲よりも広くなる場合があります。

共有アカウントのアクセス範囲を必要なデータと操作に限定し、利用できるユーザーを制限したうえで、対応する操作制御や確認の仕組みを適用してください。接続先システムの記録には、引き続きそのシステムの権限と保持ポリシーが適用されます。

## 管理者によるアクセス管理と管理対象デバイスのポリシー

**ワークスペースの設定** \> **権限とロール** で利用できる Work の制御機能を確認してください。ローカルとホスト型の Work が別々の権限として表示されるかどうかは、ワークスペースの設定と展開状況によって異なります。詳しくは、[Work 管理者向けのよくある質問](/ja-JP/codex/enterprise/work-admin-faq)を参照してください。

ユーザーやグループごとに承認された実行環境のみを有効にし、変更後に実際のアクセス範囲を確認してください。

Work を利用できるユーザーは、ワークスペースの権限によって決まります。管理者は、`requirements.toml` に定義した要件を強制適用することで、対応するデスクトップ機能を制限することもできます。導入形態に応じて、これらの要件は、ワークスペースで管理する設定、システムレベルの設定ファイル、または対応する macOS のモバイルデバイス管理ツールを通じて配布できます。

強制適用される要件を個々のユーザーが上書きすることはできません。一方、管理対象のデフォルト値は初期設定を定めるもので、ユーザーが変更できる場合があります。どちらもワークスペースのロールや OS の権限を置き換えるものではありません。

| 管理対象の設定                                       | セキュリティ上の目的                                                             |
| ----------------------------------------------------- | ---------------------------------------------------------------------------- |
| `features.computer_use = false`                       | 対応する「コンピューターの使用」の機能を無効にします。                                 |
| `allow_appshots = false`                              | 対応する Appshot のキャプチャを防止します。                                           |
| `features.in_app_browser = false`                     | デスクトップアプリの内蔵ブラウザを無効にします。                                  |
| `features.browser_use = false`                        | 対応するブラウザの自動操作を無効にします。他のブラウザ操作経路は別途確認してください。 |
| `features.apps = false` または `features.plugins = false` | 対応する接続済みのアプリケーションまたはプラグインを制限します。                        |
| `computer_use.allow_locked_computer_use = false`      | 対応するコンピューターの使用機能を、Mac のロック中は利用できないようにします。                        |

利用できる設定と配布方法は、クライアント、OS、ワークスペース、導入構成によって異なります。代表的な管理対象デバイスで制限を検証してください。対応するポリシー設定、設定例、MDM のセットアップ手順については、[管理対象の設定](/ja-JP/codex/enterprise/managed-configuration)を参照してください。

## ローカルネットワークと非公開リソース

タスクは、デバイス上のブラウザ、承認済みのデスクトップアプリケーション、接続されたアプリなどの経路を通じて、企業の情報にアクセスできます。既存のデバイス、プロキシ、VPN、連携元システム、エンドポイントの制御は、経路ごとに適用のされ方が異なる場合があります。

企業の VPN にアクセスできても、すべてのツールによるすべての社内リソースの利用が自動的に許可されるわけではありません。同様に、クラウド上の Work のブラウザやクラウドネットワークの制御で、ローカルデバイスのネットワーク通信全体が制限されるわけではありません。ワークフローで実際に必要となる接続、利用主体、接続先、操作を確認してください。

## データの取り扱いと保持

組織のエンドポイント、ファイルアクセス、プロキシ、データ損失防止の制御を、対象のデバイスとワークフローに適用してください。処理が始まる前に、これらの制御によって機密情報がタスクに取り込まれるのを防げるかどうかを確認してください。監査ログやコンプライアンス関連のエクスポートは監視や調査に役立ちますが、それ自体で処理をブロックするものではありません。

保存方法や保持のルールは、情報の種類や保存先によって異なります。

| 情報の種類                            | 確認事項                                                                                                                                                     |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ローカルの会話記録                      | デスクトップ環境でローカルの記録を保存、削除、バックアップ、共有する仕組み。ホスト環境の会話の保持設定が、ローカルのすべてのデータに適用されると想定しないでください。 |
| ローカルファイルと生成された出力               | デバイス上のストレージ、エンドポイントポリシー、ユーザーが許可したアップロード、外部共有、別途保存されたコピー                                                       |
| プロンプト、ファイルの抜粋、アプリケーションのコンテキスト | モデルやサービスに渡されるコンテンツ、適用されるワークスペースの規約、ワークフローでの実際のデータの流れ                                                           |
| 音声と Appshots                              | マイク入力、最前面のウィンドウのスクリーンショット、アプリケーション内の読み取り可能なテキスト、ローカルのセッションストレージ、タスクのコンテキストとして送信されるコンテンツ                          |
| ブラウザのデータ                                    | 使用するブラウザプロファイル、既存のサインイン状態、閲覧履歴、ダウンロード、ウェブサイトの承認、別途保存されたタスクの内容                           |
| 接続先システムの記録                        | ソースシステムの権限と保持ルール、接続アカウントの識別情報、会話や別の保存先に別途保存された情報              |
| コンプライアンスとアクティビティの記録                 | ワークスペースで取得できる Work ローカルのイベント、サポートされている連携、受信側システムの保持ポリシー                                   |

サポート対象の Business、エンタープライズ、Edu ワークスペースでは、対象となる OpenAI サービスで処理される業務データは転送中も保存時も暗号化され、デフォルトでは OpenAI モデルの学習や改善に使用されません。これらの保護措置があっても、デバイス上のすべてのファイル、サードパーティ製アプリケーション、ブラウザプロファイル、ソースシステムの記録を OpenAI が管理するわけではありません。

対象のデータ種別に適用されることを確認せずに、ホスト環境の会話、一時的なアップロード、コンプライアンスログの保持期間をローカルの記録に適用しないでください。

## 監査とコンプライアンスで確認できる情報

利用できるレポート機能は、ワークスペースのプラン、製品の利用形態、イベント、接続されたアプリケーション、導入環境の構成によって異なります。インシデント対応や規制への適合性の確認にワークスペースのエクスポートを利用する前に、Work ローカルのどの情報が含まれるかを確認してください。

関連するシステムで、タスクの識別情報、記録対象のプロンプトと応答、接続アプリの呼び出し、ブラウザでの承認、アプリケーションの操作、ローカルファイルの操作、エンドポイントのイベントが記録されるかどうかを確認してください。ソースシステムやデバイスの記録からは、ChatGPT ワークスペースの記録とは異なる情報を把握できる場合があります。

OpenAI は、拡張機能を通じて実行された Chrome の操作をすべて網羅する記録を別途保存していません。ローカルファイルの操作、スクリーンショット、ブラウザの操作、承認、外部システムの更新のすべてが Compliance API に含まれると想定しないでください。

## 承認済みのタスク 1 つから開始

管理対象デバイスを使う少人数のグループから始め、選択した財務ワークブックの比較など、承認済みのタスクを 1 つ選んでください。各ユーザーの Work へのアクセス権を確認し、タスクに必要なファイル、アプリケーション、ブラウザセッション、接続アカウントだけを利用できるようにしてください。

承認済みの操作が実行できること、制限された操作がブロックされること、取得できる記録が監視の要件を満たすことを確認してください。アクセス範囲を広げる前に、結果と外部に加えられた変更をユーザーにレビューしてもらってください。
