ChatGPT Work は既存の ChatGPT ワークスペースの一部であり、そのワークスペースに適用されるプライバシー、セキュリティ、データの取り扱いに関するポリシーに従います。Business、Enterprise、Edu のワークスペースには、転送時と保存時の暗号化などの保護措置がすでに適用されており、OpenAI はデフォルトではビジネスデータをモデルの学習に使用しません。

Work クラウドでは、ホスト環境でのタスク実行や、接続先のシステムにアクセスしたり認可されたアクションを実行したりできるオプションのツールも提供されます。組織で有効にする機能について、権限、保持設定、利用可能な監査記録を確認してください。

利用できる機能と制御は、ワークスペースのプラン、展開状況、構成、
接続されている連携機能によって異なります。実行モデルの全体像については、
[ChatGPT Work の概要](/ja-JP/codex/enterprise/chatgpt-work-overview)を参照してください。

## セキュリティの要点

- クラウド上のタスクは、ユーザーのデバイスではなく、OpenAI が管理するインフラ上で実行されます。
- クラウドタスクは、そのデバイスのローカルファイル、デスクトップアプリケーション、ブラウザセッション、プライベートネットワークへのアクセスを引き継ぎません。
- 接続されたアプリは、認可済みアカウントの権限を使用します。対象となるのは、個人アカウント、共有アカウント、またはエージェントが所有するアカウントです。
- Work へのアクセス、ローカル実行、クラウドでのブラウザ利用、接続されたアプリ、コードやシェルのネットワーク通信は、ワークスペースと各機能の制御に従います。
- Business、Enterprise、Edu のワークスペースデータは、転送時と保存時に暗号化され、デフォルトでは OpenAI モデルの学習に使用されません。
- データ保持の扱いと監査で把握できる範囲は、データの種類、保存先、イベント、適用される製品設定によって異なります。

## クラウドタスクの実行場所

対応する ChatGPT のウェブ版、モバイル版、デスクトップ版からクラウドタスクを開始できます。ウェブ版とモバイル版の Work はクラウドで実行されます。デスクトップアプリでは、対応する権限が利用可能で有効になっている場合に、クラウドタスクまたはローカル環境のタスクを実行できます。

ユーザーのデバイスは、組織の IT 管理下にある信頼境界の内側にあり、OpenAI が運用するシステムの外側にあります。デスクトップアプリからクラウドタスクを開始しても、そのタスクがユーザーのコンピューターに直接アクセスできるようにはなりません。どのインターフェースから開始しても、タスクは OpenAI が管理する環境内で実行されます。

Work クラウドは、Codex のタスク実行ハーネスを使用します。Work と Codex は実行と隔離の中核となる仕組みを共有していますが、利用できるツール、権限、管理機能は同一ではありません。ワークスペースへのアクセス、承認済みの接続、タスクに意図的に提供する情報はお客様が管理し、ホスト型の実行環境は OpenAI が管理します。

Work クラウドは、OpenAI が管理する共有インフラ上で実行されます。現在サポートされている実行経路では、タスクは VM を基盤とするサンドボックス内で実行され、実行状態はワークスペース内の認証済みアカウントのユーザーに紐付けられます。Work は、複数のタスクで環境を再利用したり、保持対象の状態を維持しながら環境を置き換えたりできます。これは、タスクごとに新しいコンテナが割り当てられることや、お客様ごとに専用の物理ホストが用意されることを意味しません。お客様が Work クラウドのコンテナを提供、ホスト、管理することはありません。

## クラウドタスクがアクセスできる対象

クラウドタスクは、認可された経路で利用可能になった次のような情報を使用できます。

- ユーザーが会話に入力した情報
- 意図的にアップロードしたファイル、ライブラリから添付したファイル、またはプロジェクト経由で利用可能になったファイル
- 有効なアプリと認可済みのアカウント接続を通じて取得したコンテンツ
- 適用されるアクセス制御のもとで、有効なクラウドブラウザやその他の許可されたウェブ機能を通じてアクセスしたウェブサイトのコンテンツ

クラウドタスクは、ローカルファイル、インストール済みアプリケーション、ユーザーのブラウザセッションへのアクセスを直接引き継ぎません。デバイスが企業の VPN、社内ウェブサイト、プライベートネットワークにアクセスできても、クラウドタスクにそのアクセスが付与されるわけではありません。

認可済みの接続を使うと、その接続固有のアクセス経路を通じて内部システムの情報を利用可能にできます。その接続によって、従業員のデバイスやネットワークへの無制限のアクセスがクラウドタスクに付与されるわけではありません。

## アプリ、プラグイン、接続アカウント

アプリを使うと、Work が別のシステムの情報にアクセスしたり、アクションを実行したりできます。プラグインは、内部で使うツールの 1 つとしてアプリを利用できます。プラグインを利用可能にしても、内部で使うアプリが自動的に有効になったり、アカウントが認可されたり、その連携機能が実行できるすべてのアクションが承認されたりするわけではありません。

接続されたアプリを直接、またはプラグインを介して使用するタスクは、次の条件をすべて満たす場合に限り進められます。

- ワークスペースで、そのアプリと、そのアプリを必要とするプラグインが有効になっていること
- ユーザーが、ワークスペースまたはロールに関する必要なアクセス権を持っていること
- 認可済みの個人アカウント、共有アカウント、またはエージェントが所有するアカウントを接続に使用していること
- 接続されたアカウント、承認済みのスコープ、利用可能なアプリのアクション設定によって、要求された情報へのアクセスや操作が許可されていること

**アクションの制御**に対応するアプリでは、管理者は読み取り専用のアクション、
すべてのアクション、または任意の組み合わせを許可できます。 **アプリの権限** では、
ChatGPT がアプリを操作する際に確認を求めるタイミングを制御します。アプリとワークスペースによっては、
 **常に確認**、 **すべての変更**、 **重要な
アクション**、 **確認しない**を選択できます。 **すべての変更**では、対応する読み取り操作は確認なしで進められますが、
変更には確認が必要です。

設定されたポリシーで許可されている場合、認可済みの書き込みは確認なしで実行できます。それによって、アプリに許可されたアクション、ワークスペースへのアクセス、接続されたアカウントの権限が拡大するわけではありません。ChatGPT は、その場合でもリスクの高い一部のアクションをブロックすることがあります。

ワークスペースで、プラグインと、それが利用する各アプリが使用可能であることを確認してください。
ロールのアクセス権、接続されたアカウントの認可、アクションの権限は、
それぞれ別の判断事項として確認してください。
[プラグインの制御](/ja-JP/codex/enterprise/apps-and-connectors)を参照してください。

### 個人用の接続と共有接続

個人用の接続は、接続した従業員が接続元システムで持つ権限を使用します。一方、共有接続やエージェント所有の接続では、その接続に使用するアカウントの権限を使用します。そのアカウントは、依頼者の個人アカウントではアクセスできない情報にアクセスしたり、実行できないアクションを実行したりできる場合があります。

共有接続を有効にする前に、アカウントの権限とスコープを制限し、
利用できるユーザーを選び、実行可能なアクションを確認してください。
[ワークスペースエージェントの接続と権限](https://help.openai.com/en/articles/20001143-chatgpt-workspace-agents-for-enterprise-and-business)を参照してください。

接続されたアプリから取得したコンテンツが、自動的にライブラリのファイルとして保存されることはありません。そのコンテンツを後で会話、プロジェクト、ライブラリ、同期済みインデックスに保存した場合、そのコピーには保存先のルールが適用されます。

## クラウドブラウザとネットワークアクセス

クラウドブラウザ、ウェブ検索、接続されたアプリ、コードやシェルのネットワーク通信は、それぞれ独立した機能です。1 つを制限しても、他の機能が自動的に無効になるわけではありません。

### クラウドブラウザ

クラウドブラウザは、Work のタスクがウェブサイトを操作するために使用できるホスト型のツールです。ウェブブラウザやデスクトップアプリで ChatGPT を開いても、クラウドブラウザ機能が有効になるわけではありません。クラウドタスクは、この機能なしでも実行できます。

ホスト型ブラウザは、ユーザーのローカルブラウザのプロファイル、開いているタブ、既存のサインイン状態、保存済みパスワード、パスワードマネージャー、閲覧履歴を引き継ぎません。対応している場合、ユーザーはホスト環境の安全なサインインフローで別途サインインできます。これによって、ユーザーのローカルブラウザセッションへのアクセスが付与されるわけではありません。

対応するウェブサイト操作には公開フォームの操作も含まれる場合があり、
認可済みアプリの情報とウェブサイト上のタスクを組み合わせることもできます。これらの設定を利用できる場合、
ウェブサイトの権限には **常に確認**、 **自動承認**、 **常に
許可**があります。 **自動承認** では自動的なリスクチェックが行われ、 **常に許可**では、
ウェブサイトへのアクセスに対する対話形式のレビューが省略されます。どちらも、アプリに新たな権限を付与するものでも、
ウェブサイト上のすべてのアクションを承認するものでもありません。重大な影響を伴うアクションには、
引き続き別途確認が必要になる場合があります。

Enterprise ワークスペースで Work のタスクがクラウドブラウザを使用するには、
管理者が Work へのアクセスとクラウドブラウザへのアクセスの両方を有効にする必要があります。
[ChatGPT でのクラウドブラウザの使用](https://help.openai.com/en/articles/20001280-using-cloud-browser-in-chatgpt)を参照してください。

### コードとシェルのネットワーク通信

コードやシェルの実行時におけるパブリックインターネットへのアクセスには、専用のネットワークポリシーが適用されます。パブリックインターネットへのアクセスがオフでも、管理されている接続先の許可リストにより、ChatGPT Work に必要なネットワーク接続先には引き続きアクセスできる場合があります。

この許可リストが制御するのは、シェルコマンドではなくネットワークの接続先です。コードやシェルの実行時のパブリックインターネットアクセスを無効にしても、それだけでクラウドブラウザ、ウェブ検索、接続されたアプリが無効になるわけではありません。ネットワーク設定の変更は、実行中のコードやシェルコマンドが完了し、実行環境が更新された後に適用されます。

[コードとシェルのサンドボックス](/ja-JP/codex/sandboxing?surface=web)を参照してください。

## データの取り扱いと保持

Work クラウドは、前述の ChatGPT ワークスペースに適用される
プライバシーとセキュリティの保護措置に従います。
[エンタープライズのプライバシー](https://openai.com/enterprise-privacy/)を参照してください。

クラウドタスクに関連する情報の保持期間や削除のタイミングは、一律ではありません。

| データの種類                        | 保持と削除の扱い                                                                                                                                                                                                                                                           |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Work の会話                   | ワークスペースの会話保持設定に従います。削除されたチャットは、通常 30 日以内の完全削除が予定されています。ただし、公表されているセキュリティ、法的要件、非識別化に関する例外が適用される場合があります。                                                                                |
| ホスト環境の実行状態とスナップショット | 会話やファイルとは別のライフサイクルに従います。実行状態へのアクセスはアカウントのユーザーに限定され、対象となる保存済みスナップショットの保持にはワークスペースの会話保持設定が考慮されます。タスクを終了したりチャットを削除したりしても、関連するすべてのアーティファクトが直ちに消去されるわけではありません。 |
| ライブラリに保存したファイル               | アップロードまたは生成したファイルには、ライブラリとワークスペースの該当する保持ルールが適用されます。会話を削除しても、ライブラリに保存したファイルは削除されません。                                                                                                                                      |
| プロジェクトのファイル                        | 適用される削除ルールに従い、ファイルが取り除かれるかプロジェクトが削除されるまで、そのプロジェクトとの関連付けが維持されます。                                                                                                                                                                       |
| 保存済みメモリ（有効な場合）         | メモリには個別の管理設定が適用されます。会話を削除しても、既存の保存済みメモリが必ず削除されるわけではありません。                                                                                                                                                                             |
| 一時的なアップロード                    | エンタープライズでライブラリ外に一時アップロードされた対象データは、ほかの保持設定が適用されない限り、48 時間後に期限切れになる場合があります。                                                                                                                                                      |
| 接続アプリのコンテンツ                | 元のシステムの記録には、そのシステムのポリシーが適用されます。会話、プロジェクト、ライブラリ、または同期インデックスに保存されたコピーには、保存先のルールが適用されます。                                                                                                                         |
| クラウドブラウザのデータ                   | ホスト型ブラウザのデータは、ローカルブラウザのデータとは別です。ユーザーは該当する設定から、クラウドブラウザに保存された Cookie を削除できます。                                                                                                                                                    |
| コンプライアンス記録                   | コンプライアンス・ログ・プラットフォームの記録は 30 日間利用できます。エクスポートされたコピーには、受信側システムの保持ポリシーが適用されます。                                                                                                                                                               |

会話の削除、ライブラリのファイルや保存済みメモリの削除、
アプリの接続解除、ホスト型ブラウザのデータ消去は、それぞれ別の操作です。
1 回の操作ですべてのコピーが削除されるとは考えず、
該当する保存先を確認してください。
[チャットとファイルの保持ポリシー](https://help.openai.com/en/articles/8983778-chat-and-file-retention-policies-in-chatgpt)をご覧ください。

会話や実行のコンテキストを適切に保持すると、Work が中断されたタスクを再開したり、前の手順を参照したり、より一貫した結果を出したりするのに役立ちます。保持期間を短くしたりデータを削除したりすると、こうした作業の継続性が低下することがあるため、セキュリティ要件とワークフローの有用性のバランスを考慮して設定を選んでください。

対象のエンタープライズおよび Edu ワークスペースでは、お客様が管理する暗号化が必要な場合、サポート対象のホスト型実行環境のスナップショットを含む、対応する保存済みコンテンツに Enterprise Key Management を使用できます。対象範囲は、データの種類や導入環境によって異なります。キーをローテーションしても、既存のデータは削除されず、それだけで以前に暗号化されたコンテンツへのアクセスが拒否されることもありません。キーへのアクセスの取り消しや無効化は別の操作であり、サポート対象のワークフローに支障をきたすことがあります。どちらの操作も、保持ポリシーや削除ポリシーの代わりにはなりません。

データレジデンシーと推論レジデンシーは、組織の契約、リージョン、構成に応じて、
対象コンテンツとサポート対象のワークロードにのみ適用されます。
接続アプリ、外部プロバイダー、一部の処理や同期インデックスには、
データの保存場所や処理場所に関する別のルールが適用されることがあります。
プロダクト、連携、リージョンごとの対応状況を確認してください。
[データレジデンシーと推論レジデンシー](https://help.openai.com/en/articles/9903489-data-residency-and-inference-residency-for-chatgpt)をご覧ください。

OpenAI API の[ゼロデータ保持](/api/docs/guides/your-data#zero-data-retention)は、
API 固有の制御機能であり、ChatGPT Work の保持ルールを定めるものではありません。

## 管理者向けアクセス制御

クラウドタスクの各要素に適用される制御を確認してください。

- **Work クラウドと Work ローカル：** 個別に制御できる場合は、
   **ワークスペース設定** \>
**権限とロール**で、クラウドとローカルの Work を別々に管理してください。ほかのワークスペースでは、
  ローカルの Work が Codex ローカルと共通の設定で制御される場合があります。
- **アプリとプラグイン：** 利用可能にする連携と、
  それらを利用できるユーザーやロールを選択してください。
- **接続アカウントのアクション：** アカウントの権限、アプリケーションのスコープ、
  アクションや確認に関する利用可能な制御設定を確認してください。
- **ブラウザとネットワーク：** クラウドブラウザへのアクセスと、
  コードやシェルからのパブリックネットワークへのアクセスを個別に評価してください。

承認済みのユーザーまたはグループにのみ **Work クラウド** を有効にしてください。
**Work クラウド** と **Work ローカル** を個別に制御できる場合は、対象ロールの **Work クラウド**を有効にし、
 **Work ローカル** を無効にすることで、ローカル実行を許可せずにクラウドの Work を利用可能にできます。
ローカルの Work と Codex が共通の設定で制御される場合は、ローカル実行を無効にする前に、
両方への影響を確認してください。これらの制御は、
権限を持つユーザーが意図的にファイルをクラウドタスクにアップロードすることを防ぐものではありません。

**デフォルト**、 **オン**、 **オフ** の状態に対応したロール権限では、
**デフォルト** はワークスペースの設定を継承し、 **オン** はアクセスを許可し、 **オフ**は
そのロールを通じたアクセスを取り消します。ユーザーに複数のカスタムロールが割り当てられている場合は、
別のロールによって引き続きアクセスが許可されることがあります。Work とプラグインの一部の設定では、
これとは異なり、2 つの状態を切り替える方式が使われます。割り当てられたすべてのロールを通じた実効アクセス権を確認してください。
[ロールベースのアクセス制御](https://help.openai.com/en/articles/11750701-rbac)をご覧ください。

利用可能な場合、 **Work クラウド** の権限は、対応するウェブ、
モバイル、デスクトップの各環境に共通して適用されます。この権限だけで、
どの環境でクラウドタスクを実行できるかを個別に選択することはできません。
導入時に特定の利用環境を除外する必要がある場合は、デバイス管理やその他のアクセス制御を検討してください。

## 監査とコンプライアンスで確認できる情報

対象のエンタープライズおよび Edu ワークスペースでは、コンプライアンス・ログ・プラットフォームに、サポート対象の Work のプロンプトと応答が含まれる場合があります。接続アプリの呼び出しには別のログがあり、元のシステムで利用できる監査記録は連携によって異なります。対応するコンプライアンスエンドポイントから、対象のライブラリファイルにアクセスできる場合があります。

記録の対象範囲は、イベントと、そのイベントが発生するシステムによって異なります。お客様が確認できるコンプライアンスのエクスポートデータに、すべてのシェルコマンド、ブラウザ操作、アプリ呼び出し、ファイル操作、承認が含まれるとは限りません。

エンドポイント監視では、管理対象デバイス上の ChatGPT クライアントやネットワークトラフィックを観測できますが、ホスト型実行環境内のアクションを調べることはできません。代わりに、Work、コンプライアンス、接続先システムの記録のうち、サポート対象のものを使用してください。

現在のコンプライアンスイベントの記録対象範囲に加え、ワークスペースのレポート、
接続先システムの監査ログ、エクスポートされた記録を受信するシステムの
保持ポリシーを確認してください。
[OpenAI コンプライアンスプラットフォーム](https://help.openai.com/en/articles/9261474-compliance-api-for-chatgpt-enterprise-edu-and-chatgpt-for-teachers)をご覧ください。

## 小規模な試験導入からスタート

少人数のグループで取り組む実用的なタスクを 1 つ選んでください。たとえば、セキュリティチームであれば、承認済みのベンダーアドバイザリと、利用が許可された資産インベントリを照合し、影響を受ける可能性を評価したドラフトをレビューしてから対応を決めることができます。クラウドブラウジングや接続アプリを利用できない場合は、そのアドバイザリと承認済みの資産インベントリの抜粋を直接提供してください。

タスクに必要なアクセスだけを有効にしてください。アクセス範囲を広げる前に、
接続アカウントの権限、保持設定、利用できる監査記録、
人が結果をレビューすべきポイントを確認してください。ロールアウトの計画については、
[管理者向けロールアウトガイド](/ja-JP/codex/enterprise/admin-setup)をご覧ください。
