## よくある質問

### Codex が編集していないファイルがサイドパネルに表示される

プロジェクトが Git リポジトリ内にある場合、レビューパネルにはプロジェクトの Git の状態に基づく変更が自動的に
表示されます。これには、Codex が
加えていない変更も含まれます。

レビューペインでは、ステージ済みの変更とまだ
ステージされていない変更を切り替えたり、ブランチを main と比較したりできます。

前回の Codex ターンでの変更だけを確認するには、差分
ペインを「**前回のターン**」ビューに切り替えます。

[レビューペインの使い方について詳しく見る](/ja-JP/codex/code-review?surface=app)。

### サイドバーからプロジェクトを削除

サイドバーからプロジェクトを削除するには、プロジェクト名にカーソルを合わせ、
三点リーダーをクリックして「削除」を選択します。復元するには、
「**新しいプロジェクトを追加**」ボタン（「**チャット**」の横）を使用するか、次のショートカットでプロジェクトを再追加します

<kbd>Cmd</kbd>+<kbd>O</kbd>。

### アーカイブ済みのチャットを探す

アーカイブ済みのチャットは「[設定](codex://settings)」で確認できます。チャットのアーカイブを解除すると、
サイドバーの元の場所に再表示されます。

### サイドバーに一部のチャットしか表示されない

サイドバーでは、プロジェクトの状態に応じてチャットを絞り込めます。チャットが
見つからない場合は、「**チャット**」の横にあるフィルターアイコンを選択し、続いて
「**時系列**」を選択します。それでもチャットが見つからない場合は、
「[設定](codex://settings)」を開き、「**アーカイブ済みのチャット**」を確認します。

### Worktree でコードが実行されない

Worktree は別のディレクトリに作成され、デフォルトでは Git にコミットされた
ファイルを継承します。プロジェクトで依存関係やツールを管理する方法によっては、
Worktree でセットアップスクリプトを実行するために
[ローカル環境](/ja-JP/codex/environments/local-environment) を使用するか、無視対象のセットアップファイルを
[`.worktreeinclude`](/ja-JP/codex/environments/git-worktrees#copy-ignored-local-files-into-managed-worktrees) でコピーする必要があります。
または、通常のローカルプロジェクトで変更をチェックアウトできます。詳しくは、
[Worktree のドキュメント](/ja-JP/codex/environments/git-worktrees) をご覧ください。

### App がチームメイトの共有ローカル環境を認識しない

ローカル環境の構成は、プロジェクトルートの `.codex` フォルダー内に
配置する必要があります。複数のプロジェクトを含むモノレポで
作業している場合は、プロジェクトを
`.codex` フォルダーがあるディレクトリで開いてください。

### Codex が Apple Music へのアクセスを求める

タスクによっては、Codex がファイルシステム内を移動する必要があります。macOS の
「ミュージック」「ダウンロード」「デスクトップ」など、特定のディレクトリへのアクセスには
ユーザーによる追加の承認が必要です。Codex がホームディレクトリを読み取る必要がある場合は、
macOS からそれらのフォルダーへのアクセスを承認するよう求められます。

<a id="automations-create-many-worktrees"></a>

### スケジュール済みタスクで多数の Worktree が作成される

スケジュール済みタスクを頻繁に実行すると、時間の経過とともに多数の Worktree が作成されます。不要になった
スケジュール実行はアーカイブし、該当する Worktree を保持するつもりがある場合を除いて、実行を
ピン留めしないでください。

### 誤った実行先を選んだ後のプロンプト復元

誤った実行先（**ローカル**、**Worktree**、**クラウド**）で誤ってチャットを開始した場合は、現在の実行をキャンセルし、コンポーザーで上矢印キーを押すと直前のプロンプトを復元できます。

### Codex CLI では動作するが、ChatGPT デスクトップアプリでは動作しない機能

ChatGPT デスクトップアプリと Codex CLI には異なるバージョンの Codex が含まれる場合があるため、
どちらか一方で先に機能が利用可能になることがあります。試験的な機能も
Codex CLI に先に導入される場合があります。

システム上の Codex CLI のバージョンを確認するには、次を実行します：

```bash
codex --version

ChatGPT デスクトップアプリに同梱されている Codex のバージョンを確認するには、
互換性維持のために残されている `Codex.app` バンドルのパスを使用します：

```bash
/Applications/Codex.app/Contents/Resources/codex --version

## フィードバックとログ

チームにフィードバックを送るには、メッセージ入力欄に <kbd>/</kbd> と入力します。既存のチャットで
フィードバックを開始した場合は、フィードバックとともに
既存のセッションを共有するかどうかを選択できます。フィードバックを送信すると、
チームと共有できるセッション ID が発行されます。

問題を報告するには：

1. Codex の GitHub リポジトリで「[既存のイシュー](https://github.com/openai/codex/issues)」を検索します。
2. [新しい GitHub イシューを作成](https://github.com/openai/codex/issues/new?template=2-bug-report.yml&steps=Uploaded%20thread%3A%20019c0d37-d2b6-74c0-918f-0e64af9b6e14)

その他のログは次の場所にあります：

- App のログ（macOS）： `~/Library/Logs/com.openai.codex/YYYY/MM/DD`
- セッションのトランスクリプト： `$CODEX_HOME/sessions`（デフォルト： `~/.codex/sessions`）
- アーカイブ済みセッション： `$CODEX_HOME/archived_sessions`（デフォルト： `~/.codex/archived_sessions`）

ログを共有する場合は、機密性の高い
情報が含まれていないか、事前に確認してください。

## 処理が止まった場合の復旧方法

チャットの処理が止まっているように見える場合：

1. Codex が承認を待っているか確認します。
2. ターミナルを開き、`git status` などの基本的なコマンドを実行します。
3. より簡潔で対象を絞ったプロンプトで、新しいチャットを開始します。

Worktree の作成を誤ってキャンセルしてプロンプトが失われた場合は、コンポーザーで
上矢印キーを押すとプロンプトを復元できます。

## ターミナルの問題

**ターミナルが停止しているように見える**

1. ターミナルパネルを閉じます。
2. <kbd>Ctrl</kbd>+<kbd>\`</kbd> で再度開きます。
3. `pwd` または `git status` などの基本的なコマンドをもう一度実行します。

コマンドが想定どおりに動作しない場合は、まずターミナルで現在のディレクトリと
ブランチを確認してください。

それでも停止したままの場合は、進行中のチャットが完了するまで待ってから、アプリを再起動してください。

**フォントが正しく表示されない**

Codex では、レビューペイン、統合ターミナル、アプリ内に表示されるその他のすべてのコードに同じフォントが使用されます。フォントは、「[設定](codex://settings)」ペインの「**コードフォント**」で設定できます。
