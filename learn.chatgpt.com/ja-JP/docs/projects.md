プロジェクトを使って関連するチャットを整理し、ChatGPT に必要なコンテキストを提供します。
ChatGPT デスクトップアプリの **プロジェクト** ビューには、ChatGPT プロジェクトと、
コンピューター上のフォルダーに接続するローカルプロジェクトが表示されます。

## プロジェクトの選択またはプロジェクトなしでの開始

作業が継続する場合、複数の成果物を作成する場合、
または同じファイルやソースが必要な場合は、プロジェクトを作成します。
作業が単独で完結し、プロジェクトの共有コンテキストが不要な場合は、プロジェクトなしでチャットを開始します。

プロジェクトを使って、関連するチャット、ファイル、指示、ソースをまとめて管理します。
同じプロジェクトに、チャットまたは ChatGPT Work で開始したチャットを含めることができます。

## プロジェクトの選択またはプロジェクトなしでのチャット開始

作業が継続する場合、複数の成果物を作成する場合、
または同じファイルやソースが必要な場合は、プロジェクトを作成します。
作業が単独で完結し、プロジェクトの共有コンテキストが不要な場合は、プロジェクトなしでチャットを開始します。

各プロジェクトには、プロジェクト内のチャットを一覧表示する **チャット** セクションと、アップロードしたファイルや接続されたコンテキストを管理する **ソース**セクションがあります。
プロジェクトの指示は、
そのプロジェクト内のすべてのチャットに適用されます。ChatGPT プロジェクトから
コンピューター上のフォルダーに直接アクセスすることはできないため、ChatGPT に使用させたいソースをアップロードまたは接続してください。

どちらの場合も、プロジェクトから新しいチャットを開始し、
共有ファイルや指示を利用します。その後は **チャット**から再びそのチャットに戻れます。

Codex CLI では、起動したディレクトリがチャットのプロジェクトとして扱われます。
Codex に作業させたいディレクトリで `codex` を実行するか、
`--cd <directory>`（`-C`）を指定して明示的に設定します。CLI では
ChatGPT のプロジェクトビューは表示されません。

IDE 拡張機能では、IDE で開いているフォルダーまたはワークスペースがローカルプロジェクトとして扱われます。
マルチルートワークスペースでは、チャットに使用するワークスペースルートを選択します。
この拡張機能には、Web またはデスクトップアプリの ChatGPT プロジェクトビューは表示されません。

## プロジェクトでの作業

**プロジェクト** ビューでは、ChatGPT プロジェクトとローカルプロジェクトをまとめて管理できます。
ChatGPT プロジェクトでは、関連するチャット間でプロジェクトのファイルとコンテキストを共有できます。
ローカルプロジェクトでは、ソースファイル一式やコードベースなど、
コンピューター上の 1 つ以上のフォルダーにチャットからアクセスできます。

成果ごとに個別のチャットを開始すると、メッセージや結果をその成果に集中させながら、
関連する作業をプロジェクト内で整理できます。

  
    
  

## プロジェクトでの作業

ChatGPT プロジェクト内の各チャットでは、同じアップロード済みファイル、プロジェクトの指示、
接続済みソースにアクセスできます。簡単なやり取りにはチャットを、
規模の大きい成果物の作成には ChatGPT Work を使用します。どちらもプロジェクトの
**チャット** セクションにチャットとして表示されます。成果ごとに個別のチャットを開始すると、
プロジェクトの共有コンテキストを維持しながら、メッセージや結果をその成果に集中させられます。

## プロジェクトディレクトリでの作業

チャットのファイルコンテキストとして使用するディレクトリから Codex を起動します。
`/new` を使って、成果ごとに個別のチャットを開始します。Codex の起動中に `/resume` を使用するか、
`codex resume` を実行すると、保存済みのチャットを再開できます。

チャットには会話履歴と記録された作業ディレクトリが保持され、Codex は
現在の作業ツリーからファイルを読み取ります。今後のチャットでも利用できるよう、
長期的に使用するプロジェクトの指針は `AGENTS.md` またはチェックイン済みのドキュメントに記載します。

## ワークスペースでの作業

チャットのファイルコンテキストとして使用するフォルダーまたはワークスペースを開きます。
成果ごとに新しいチャットを開始し、再開するときは **最近のチャット** から
選択します。同じプロジェクト内のチャットでは同じファイルを扱えますが、
会話履歴はチャットごとに保持されます。

現在の選択範囲と開いているファイルが、現在のターンのコンテキストになります。
今後のチャットでも利用できるよう、長期的に使用するプロジェクトの指針は `AGENTS.md` または
チェックイン済みのドキュメントに記載します。

## プロジェクトとチャットの整理

進行中の作業は見つけやすい状態に保ち、完了した作業は邪魔にならないよう整理します：

- **プロジェクトをピン留め** すると、サイドバーの上部付近に表示されます。
  プロジェクトビューからピン留めすることもできます。
- **チャットをピン留め** すると、プロジェクトに新しいチャットが追加されても、
  頻繁に開くチャットを見つけやすい状態に保てます。
- **チャット名を変更** し、
  「Q3 ローンチ概要」や「チェックアウトのアクセシビリティレビュー」など、成果を表す短いタイトルを付けます。
- **プロジェクトを検索** するには、プロジェクトビューを使用します。サイドバーの **チャットを検索** を開くと、
  タイトルを覚えていない場合でも、フレーズやブランチ名を手掛かりに
  過去のチャットを探せます。チャット検索にはデフォルトのショートカットはありませんが、
   **設定 \> キーボードショートカット**で割り当てることができます。
- 作業が完了したら、**チャットをアーカイブ** します。プロジェクトのメニューで
**チャットをアーカイブ** を選択すると、そのプロジェクトのチャットをまとめてアーカイブできます。

ピン留めしてもコンテキストは追加されず、ChatGPT がアクセスできる内容も変わりません。
変わるのは、プロジェクトやチャットがサイドバーに表示される位置だけです。

アーカイブしたチャットは **設定 \> アーカイブ済みのチャット**から復元できます。

## フォルダーとコードベース向けのローカルプロジェクト

ChatGPT がコンピューター上のファイルを読み取ったり変更したりする必要がある場合は、ローカルプロジェクトを追加します。
プロジェクトにフォルダーは必須ではありませんが、必要に応じてフォルダーを関連付けられます。

フォルダーを追加または変更するには、プロジェクトのメニューを開き、 **プロジェクトを編集**を選択します。
 **フォルダーを追加** を選択すると、複数のフォルダーを関連付けられます。
ChatGPT は、関連付けたすべてのフォルダー内のファイルを読み取り、変更できます。
デフォルトの作業ディレクトリを変更するには、フォルダーにポインターを合わせ、 **プライマリに設定**を選択します。

新しいチャットはプライマリフォルダーで開始されます。Codex は、このフォルダーを
Git 操作や `AGENTS.md`、スキル、
`config.toml` の自動検出におけるデフォルトの場所としても使用します。セカンダリフォルダーでも、
ファイルの検索、読み取り、編集を行えます。ただし、Codex は
セカンダリフォルダーからこれらのプロジェクトファイルを自動検出しません。

アプリとそのドキュメント、ウェブサイトとバックエンドのように、
関連する作業が異なる場所にある場合は、複数のフォルダーを使用します。
関連のない作業や、各チャットからリポジトリの一部だけにアクセスさせる場合は、
別々のプロジェクトを作成します。これにより、作業コンテキストを必要な範囲に絞れます。
現在、リモートプロジェクトでサポートされるフォルダーは 1 つだけです。

[ローカル環境](/ja-JP/codex/environments/local-environment)を使って、プロジェクトのセットアップアクションと
共通コマンドを定義します。[レビュー
ペイン](/ja-JP/codex/code-review?surface=app)には、同じプロジェクトに関連付けた
複数のリポジトリにまたがる変更を表示できます。Pull Request と
[Worktree](/ja-JP/codex/environments/git-worktrees) の操作は、プライマリリポジトリを
対象とします。Worktree でチャットを開始した場合も、
他のフォルダーは関連付けられたままになります。

プロジェクトや Worktree は作業を整理するためのものですが、[サンドボックス](/ja-JP/codex/sandboxing)が
ローカルコマンドによる読み取り、変更、ネットワークアクセスの範囲を制御します。

<a id="start-a-task-without-a-project-1"></a>

## プロジェクトなしでのチャット開始

プロジェクトの共有ファイルや指示、ソースが不要な場合は、ChatGPT ホームから
チャットを開始します。チャットまたは ChatGPT Work を利用できます。
Web では、どちらを使ってもチャットが作成されます。

作業の規模が大きくなったら、プロジェクトに移し、成果ごとに内容が分かるチャット名を付けます。
プロジェクトでは、調査、下書き、レビュー、フォローアップ用のチャットを並行して進めながら、
すべてのメッセージが 1 つのコンテキストに混在するのを防げます。

## 簡単な質問向けのクイックチャット

クイックチャットでは、通常の ChatGPT チャットが開きます。
ChatGPT のチャットは、Codex のチャットとプロジェクトが表示される Codex サイドバーには表示されません。

**新しいチャット**にポインターを合わせ、その右側にある **クイックチャット** アイコンを選択します。
次のショートカットキーを押すこともできます：

macOS では <kbd>Cmd+Option+N</kbd>、Windows と Linux では <kbd>Ctrl+Alt+N</kbd> を押します。
 **新しいチャット**から既存の ChatGPT チャットを開き、
Codex チャットに追加することもできます。

## 他のツールとコンテキストの取り込み

- そのリクエストだけに必要なファイルや[画像入力](/ja-JP/codex/image-inputs)は、
  チャットに直接添付します。
- [プラグイン](/ja-JP/codex/plugins)をインストールし、他のサービスのコンテキストや
  アクションを取り込みます。
- 組織や開発環境で Model Context Protocol を通じてツールが公開されている場合は、[MCP](/ja-JP/codex/extend/mcp) サーバーを
  設定します。
- [メモリ](/ja-JP/codex/customization/memories)が利用できる場合は、それを使って過去の作業で得た有用なコンテキストを
  今後のチャットに引き継ぎます。

- 視覚的なコンテキストがそのリクエストにのみ関係する場合は、
  [画像入力](/ja-JP/codex/image-inputs)をチャットに渡します。
- [プラグイン](/ja-JP/codex/plugins)をインストールして、
  他のサービスからコンテキストとアクションを取り込みます。
- 組織または開発環境で Model Context Protocol を介してツールが公開されている場合は、
  [MCP](/ja-JP/codex/extend/mcp) サーバーを設定します。
- 利用できる場合は、[メモリ](/ja-JP/codex/customization/memories)を使用して、
  過去の作業で得た有用なコンテキストを今後のチャットに引き継ぎます。

- 開いているファイルを参照するか、エディターでコードを選択して、現在のターンにコンテキストを追加します。
- 組織または開発環境で Model Context Protocol を介してツールが公開されている場合は、
  [MCP](/ja-JP/codex/extend/mcp) サーバーを設定します。
- 利用できる場合は、接続先の Codex ホストの[メモリ](/ja-JP/codex/customization/memories)を使用して、
  有用なコンテキストを今後のチャットに引き継ぎます。

- ファイルと接続済みのソースをプロジェクト内のすべてのチャットで利用できるようにするには、
  プロジェクトの **ソース** セクションに追加します。
- ファイルまたは[画像入力](/ja-JP/codex/image-inputs)がそのチャットにのみ関係する場合は、
  チャットに直接添付します。
- ChatGPT Work では、[プラグイン](/ja-JP/codex/plugins)をインストールして、
  他のサービスからコンテキストとアクションを取り込みます。
- 利用できる場合は、[メモリ](/ja-JP/codex/customization/memories)を使用して、
  過去の作業で得た有用なコンテキストを今後のチャットに引き継ぎます。
