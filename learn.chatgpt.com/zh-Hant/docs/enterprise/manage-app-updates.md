ChatGPT 桌面應用程式通常會自行檢查並安裝更新。如果
貴組織需要在使用者取得新版本前先進行審查，
可以關閉應用程式的內建更新程式，並透過
裝置管理平台部署已核准的版本。

應用程式的更新程式預設為啟用。關閉此更新程式並不會阻止
Microsoft Store、Microsoft Intune、行動裝置管理（MDM）、
套件管理員或其他外部部署工具安裝更新。

## 開始之前

請確認您具備下列項目：

- 您對工作區中的
[受管理的設定](https://chatgpt.com/codex/settings/managed-configs)
  具有 Codex 管理員存取權。
- macOS 或 Windows 版 ChatGPT 桌面應用程式版本，支援
由組織管理的更新。
- MDM 或軟體部署平台，可將已核准的應用程式套件
安裝到受管理的裝置上。
- 用於測試新版本、部署安全性更新及追蹤
已安裝應用程式版本的流程。

如果尚未在 Windows 上部署應用程式，請先參閱
[部署 Windows 應用程式](/zh-Hant/codex/enterprise/windows-deployment)。

## 關閉應用程式內更新

  關閉應用程式內更新後，貴組織有責任
及時部署新的應用程式版本與安全性修正。延遲更新可能
會使應用程式及其隨附元件暴露於已知的安全性
漏洞。舊版應用程式不會另行獲得安全性修補程式或
延伸支援。

建立一項受管理原則，以停用桌面應用程式本身的更新程式：

1. 開啟
[受管理的設定](https://chatgpt.com/codex/settings/managed-configs)。
2. 選取 **新增原則**，或為您要管理的使用者、群組或
   平台開啟現有原則。
3. 在 **目標** 下，選取 **新增目標**，將原則指派給特定的
**群組**、**使用者**，或 **平台**。如情況
   允許，請先從小型試行群組開始。
4. 開啟 **原始 TOML**，並找到 **requirements.toml** 編輯器。
5. 新增下列原則：

   ```toml
   [features]
   in_app_updates = false

   如果原則已有 `[features]` 資料表，請將
`in_app_updates = false` 加入該資料表。請勿新增第二個 `[features]` 資料表，
   也不要將此設定放在 **config.toml** 中。

6. 選取 **儲存變更**。
7. 請受影響的使用者完全結束並重新開啟 ChatGPT 桌面應用程式。僅關閉
應用程式視窗不一定足以重新啟動應用程式。

部分工作區會顯示原則清單編輯器，而不是 **原始 TOML** 分頁。在
該介面中，請將相同 TOML 區塊直接加入適用的原則；如可使用，請透過
**群組** 指派該原則，然後選取 **儲存**。

如需受管理原則傳遞與優先順序的詳細資訊，請參閱
[受管理的設定](/zh-Hant/codex/enterprise/managed-configuration)。

## 驗證受管理的設定

應用程式重新啟動後，請在受影響使用者的裝置上驗證原則：

1. 使用此原則所涵蓋的帳戶登入 ChatGPT 桌面應用程式。
2. 開啟 **設定** \> **一般**。
3. 找到 **應用程式內更新**，並確認其顯示 **受管理** 以及訊息
   「您的組織已關閉應用程式內更新。」
4. 確認裝置管理平台仍可部署已核准的應用程式
版本。

**檢查更新** 選單選項可能仍會顯示，即使原則會
封鎖應用程式內更新。請使用 **受管理** 指標驗證原則，
而不是查看該選單選項是否顯示。

如果第一次重新啟動後仍未顯示指標，應用程式可能仍
使用快取的原則。請等待原則重新整理，然後完全結束並重新開啟
應用程式。在 **受管理** 顯示前，請勿仰賴這項更新限制。

## 部署已核准的應用程式版本

關閉應用程式內更新後，請使用現有的裝置管理流程
部署新版本：

1. 選擇貴組織計畫部署的應用程式版本。
2. 針對裝置機群中的每種作業系統與
裝置架構，取得支援的安裝套件。
3. 使用一小群具代表性的使用者測試該版本。
4. 透過 Microsoft Intune、MDM 平台或
其他軟體部署工具，部署已核准的套件。
5. 檢查裝置清冊，確認平台已安裝預期的
版本，然後將部署範圍擴大至其他群組。

您的管理平台會決定如何分階段推出版本、選取版本，
以及在部署未完成時如何復原。如果平台允許
回復至舊版，這麼做不會延長支援期限，也不保證
服務相容性。

若為 macOS，請下載
[ChatGPT 桌面應用程式安裝程式](https://persistent.oaistatic.com/codex-app-prod/ChatGPT.dmg)。
如需 Windows 安裝方式及架構專用套件，請參閱
[部署 Windows 應用程式](/zh-Hant/codex/enterprise/windows-deployment)。

## 重新啟用應用程式內更新

若要恢復應用程式的正常更新行為：

1. 找出會為受影響使用者關閉更新的受管理原則、系統 `requirements.toml` 檔案及 MDM
   設定檔。
2. 將 `in_app_updates = false` 從每個適用的 `[features]` 資料表中移除。
3. 儲存原則變更，並重新部署所有已更新的裝置管理需求設定。
4. 請受影響的使用者完全結束並重新開啟 ChatGPT 桌面應用程式。
5. 檢查 **設定** \> **一般**，確認受管理的 **應用程式內更新**
   列已不再顯示。

若沒有任何適用的原則設定 `in_app_updates = false`，應用程式的內建
更新程式會依正常方式運作。如果 **受管理** 指標仍然
顯示，請檢查其他工作區原則、MDM 設定檔及系統
`requirements.toml` 檔案。請參閱
[位置與優先順序](/zh-Hant/codex/enterprise/managed-configuration#locations-and-precedence)
，瞭解受管理來源的套用順序。

## 瞭解安全性與支援責任

應用程式收到並套用受管理更新原則後，該原則會：

- 防止桌面應用程式檢查、下載或安裝更新，這些操作不得
透過其本身的更新程式進行。
- 不提供由 OpenAI 管理的版本固定功能、獨立的發布管道，
也不保證舊版的服務相容性。
- 適用於受支援的 macOS 版和 Windows 版 ChatGPT 桌面應用程式組建。此原則
不會管理行動應用程式、Codex CLI 或 IDE 擴充功能的更新。

## 排解常見問題

如果身分驗證問題、連線問題或逾時導致應用程式
無法擷取或套用受管理原則，其內建更新程式可能會
維持啟用。在 **受管理** 顯示前，請勿認定應用程式會封鎖更新。

如果 **受管理** 指標未顯示，請確認：

- 受影響的使用者已選取預期的工作區。
- 原則的套用目標包含該使用者、群組或平台。
- 裝置上執行的是受支援的應用程式版本。
- 應用程式可以連線至傳遞受管理原則的服務。
- 此設定位於 **requirements.toml**，而不是 **config.toml**。
- 儲存原則後，使用者已完全結束並重新開啟應用程式。

如果無法開啟「受管理的設定」或儲存原則，請確認您具備
該工作區的 Codex 管理員存取權。

停用應用程式內更新後，如果應用程式版本有所變更，請檢查是否由
Microsoft Store、Intune、MDM、套件管理工具或其他部署系統
安裝了更新。此政策只會控制應用程式的內建更新程式。
