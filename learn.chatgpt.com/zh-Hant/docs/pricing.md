## 常見問題

### Sites 的費用是多少？

[Sites](/zh-Hant/codex/sites) 在公開測試期間包含於符合資格的 ChatGPT 方案中。
是否可用取決於您的方案、地區與工作區設定。

### 我的方案有哪些使用量限制？

您可以傳送的訊息數量取決於所用模型、任務的規模與複雜度，以及任務是在本機或雲端執行。小型指令碼或例行函式可能只會消耗少部分額度；較大型的專案、長時間執行的任務，或需要智慧體保留更多上下文的長時間工作階段，每則訊息則會消耗明顯更多額度。

看似相似的任務，消耗的額度可能不同。模型選擇、上下文、推理、工具使用、檢索及快取都會影響使用量，因此只看提示詞長度無法可靠估算。

請選擇最適合您工作需求的 GPT-5.6 模型：

- **Sol** 專為最艱鉅的工作而打造，包括複雜推理、模糊不明的問題、
  進階程式碼編寫，以及事關重大的決策。
- **Terra** 是日常工作的主力模型，適用於正式作業、報告撰寫、文件分析、
  程式碼編寫，以及需要穩健判斷的工作。
- **Luna** 針對需要快速、大量處理的工作進行最佳化，例如路由、
  分類、擷取、支援、背景自動化，以及目標明確的
  程式碼編寫任務。

### 桌面版 ChatGPT 語音

桌面版 ChatGPT 語音採用獨立額度，依方案而異，並以滾動的 5 小時時段計算。透過語音啟動的任務會使用您現有的 Codex 使用額度。達到其中任何一項限制時，ChatGPT 都會通知您。

GPT-Live 負責即時對話。當您在現有的 Codex 任務中使用語音時，
工作會由該任務所選的模型處理。可用性與設定方式
請參閱 [ChatGPT 語音](/zh-Hant/codex/features/voice#start-talking)。

- **Plus：** 約 15–30 分鐘
- **Pro 5x（$100/月）：** 約 1–2.5 小時
- **Pro 20x（$200/月）：** 無限使用語音
- **Business：** 約 45 分鐘
- **Enterprise / Edu（舊版）：** 約 45 分鐘

無限使用語音不代表 Codex 任務也能無限使用。透過 ChatGPT 語音啟動的任務仍會消耗您現有的 Codex 使用額度。

採用點數制或隨用隨付計費的 Business、Edu 和 Enterprise 工作區，使用桌面版語音每分鐘約需 6 點。桌面版 ChatGPT 語音目前無法透過 API 金鑰使用。

### 達到使用量限制時會發生什麼事？

我們希望您能完成已在進行中的工作。如果您在回合進行期間達到使用量限制，智慧體仍可繼續處理該回合，但須遵守公平使用限制。

ChatGPT Plus 和 Pro 使用者達到使用量限制後，可購買額外點數繼續工作，無須升級現有方案。

採用[彈性
定價](https://help.openai.com/en/articles/11487671-flexible-pricing-for-the-enterprise-edu-and-business-plans)的 Business、Edu 和企業方案
可以購買額外的工作區點數，繼續工作。

如果即將達到用量限制，也可以改用較小的模型，讓額度用得更久。

所有使用者也都可以使用 API 金鑰進行額外的本機對話，用量依
[標準 API 費率](https://platform.openai.com/docs/pricing)計費。

### 圖像生成如何計入用量限制？

圖像生成與本機訊息及雲端對話
共用一般用量限制。與不含圖像生成的類似回合相比，
圖像生成消耗方案內含額度的速度平均為 3-5 倍，實際速度取決於
圖像品質與尺寸。方案內含額度用完後，圖像生成
也會扣除[點數](#credits-overview)。

免費方案不提供圖像生成。使用 Codex 搭配 API 金鑰時，圖像生成將依 API 定價計費，而非計入 ChatGPT 方案內含的用量限制。

### 我可以在哪裡查看目前的用量限制？

你可以在[用量
儀表板](https://chatgpt.com/codex/settings/usage)中查看目前的用量限制。如需在進行中的 Codex CLI 工作階段
查看剩餘額度，可以使用 `/status`。

每隔一到兩週查看一次儀表板，掌握使用速度和剩餘額度。如果用量高於預期，請評估改用較小的模型或縮小任務範圍，是否仍能產出實用的結果。

### Token 和點數是什麼？

Token 是 ChatGPT 讀取和寫入的小型資訊單位。你的提示詞、檔案、對話紀錄、工具結果，以及 ChatGPT 的回覆都會使用 Token。

點數是採用點數計費的方案用來支付適用用量的單位。方案內含額度用完後，仍可使用可用點數繼續工作。點數購買價格與適用折扣取決於你的方案或合約。

### 哪些操作會計入程式碼審查用量？

程式碼審查用量只適用於 Codex 透過 GitHub 執行的審查，例如
在 Pull Request 中標記 `@Codex` 要求審查，或在程式碼庫中啟用
自動審查。在本機或 GitHub 以外執行的審查，則計入
一般用量限制。

### 如何讓額度用得更久？

上述用量限制和點數消耗皆為平均值。你可以嘗試以下方法，充分運用可用額度：

- **控制提示詞的長度。** 向智慧體提供精準的指示，
  並移除不必要的上下文。
- **限制來源資料。** 只提供相關檔案，並在可行時
  縮小資料來源或日期範圍。
- **依需求設定輸出。** 明確指定讀者、格式和長度，並
  區分必要工作與非必要的改進。
- **精簡 AGENTS.md。** 如果你正在處理較大的專案，
  可以將 AGENTS.md 檔案[分層放在程式碼庫的
  不同目錄中](/zh-Hant/codex/agent-configuration/agents-md#layer-project-instructions)，控制透過這些檔案加入的上下文量。
- **限制使用的 MCP 伺服器數量。** 每個
[MCP](/zh-Hant/codex/extend/mcp) 伺服器都會為訊息加入更多上下文，並消耗
  更多額度。不需要 MCP 伺服器時，請將其停用。
- **改用較小的模型處理例行任務。** 使用 GPT-5.6 Terra 或
  GPT-5.6 Luna 可以讓本機訊息額度用得更久，實際效果取決於
  你原先使用的模型。

如需瞭解如何選擇任務及界定範圍，請參閱[有效率地
使用 Work](/zh-Hant/codex/prompting#use-work-efficiently)。
