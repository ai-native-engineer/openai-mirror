## 簡介

從一個技術堆疊遷移至另一個時，您可以運用 Codex 規劃並執行受控遷移，包括路由、資料模型、組態、身分驗證、背景作業、建置工具、部署、測試，甚至程式語言和框架本身的慣例。

Codex 在這方面很有用，因為它可以盤點舊有系統、建立新舊概念之間的對應關係，並透過多個檢查點逐步完成變更，而不必一次進行大規模重寫。在以下情況下，這點尤其重要：從舊有框架遷出、移植至新的執行階段，或在產品仍須持續運作的同時，以漸進方式用另一個技術堆疊取代現有堆疊。

## 使用方式

1. 先盤點遷移範圍，包括舊有套件、框架慣例、路由、資料存取、身分驗證、組態、建置工具、測試、部署假設，以及所有在遷移後仍須維持有效的外部契約。
2. 請 Codex 將舊有概念對應至目標技術堆疊，並指出沒有直接對應關係的項目。
3. 選擇漸進式策略：建立相容層、逐一移植模組、採用抽象分支法，或使用絞殺者模式，每次圍繞一個邊界進行替換。
4. 在遷移本身迫使您做出使用者可見的變更之前，請保持系統行為穩定，並明確指出這些例外情況。
5. 每完成一個里程碑，就執行範圍最小但足以證明一致性的驗證：lint、型別檢查、針對性測試、契約測試、煙霧測試，或與舊有路徑進行並排比對。
6. 每完成一個檢查點，就審查差異和剩餘的過渡風險，不要等到全面重寫完成後才進行審查。

## 善用 ExecPlans

我們在 [程式碼現代化操作手冊](/cookbook/examples/codex/code_modernization) 中介紹了 ExecPlans：這類文件可讓 Codex 持續掌握清理工作的全貌、明確說明預期的最終狀態，並記錄每一輪作業後的驗證結果。
當您要求 Codex 執行複雜的遷移時，請讓它為系統的每個部分建立一份 ExecPlan，確保每項決策和技術堆疊選擇都有記錄，且日後可供審查。

## 搭配目標

對於耗時較長的分段遷移工作，請使用 [目標](/zh-Hant/codex/use-cases/follow-goals) 引導 Codex 完成工作。設定目標時，請明確指定最終狀態、一致性檢查、回復要求和停止條件。
