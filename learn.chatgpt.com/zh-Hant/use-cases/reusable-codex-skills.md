## 建立一項可供 Codex 隨時使用的技能

使用技能為 Codex 提供可重複使用的指示、資源和指令碼，以處理你反覆執行的工作。這項 [技能](/zh-Hant/codex/build-skills) 可以保留最初讓 Codex 派上用場的任務、文件、指令或範例。

先從一個可行範例開始：例如，曾揀選套用 PR 的 Codex 對話、Notion 中的發布檢查清單、一組實用的 PR 留言，或說明上線流程的 Slack 討論串。

## 使用方式

1. 加入你想讓 Codex 使用的上下文。

   留在你想保留的 Codex 對話中，貼上 Slack 討論串或文件連結，並加入 Codex 應記住的規則、指令或範例。

2. 執行起始提示詞。

   提示詞會先為你想要的技能命名，再向 `$skill-creator` 提供要保留的任務、文件、PR、指令或輸出。

3. 讓 Codex 建立並驗證技能。

   結果應定義 `$skill-name`，說明其觸發時機，並將可重複使用的指示保存在正確位置。

   位於 `~/.codex/skills` 的技能可在任何程式碼庫中使用。你可以提交目前程式碼庫中的技能，讓團隊成員也能使用。

4. 使用技能後，再從對話中更新它。

   在下一個 PR、警示、審查、發布說明或設計任務中，叫用名稱為 `$skill-name` 的新技能。如果它使用錯誤的測試指令、遺漏審查規則、跳過執行手冊中的步驟，或寫出你不會送出的草稿，請 Codex 將相應的修正加入技能。

## 提供來源資料

向 `$skill-creator` 提供能說明技能應如何運作的資料。

| 你現有的內容                                              | 要新增的內容                                                                                                                                                             |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **你想保留的 Codex 對話工作流程** | 留在該對話中，然後輸入 `use this chat`。Codex 可將對話上下文、指令、編輯內容和回饋作為起點。                                         |
| **文件或執行手冊**                                      | 貼上發布檢查清單、提供事件應變執行手冊的連結、附上 API PDF 檔案，或指示 Codex 參考程式碼庫中的 Markdown 指南。                                 |
| **團隊對話**                                      | 貼上有人在其中說明警示的 Slack 討論串，提供包含前端規則的 PR 審查連結，或附上說明客戶問題的客服對話。 |
| **技能應重複使用的指令碼或指令**             | 加入你希望 Codex 在日後任務中執行的測試指令、預覽指令、發布指令碼、日誌擷取指令碼或本機輔助指令。                                    |
| **理想結果**                                          | 加入你希望日後任務比照的已合併 PR、最終更新日誌項目、已核准的上線公告、已解決工單、前後對照螢幕截圖，或 Codex 的最終回答。         |

如果來源位於 Slack、Linear、GitHub、Notion 或 Sentry，請在 Codex 中透過 [外掛程式](/zh-Hant/codex/plugins) 連接該工具、在起始提示詞中提及該工具，或將相關內容貼到對話中。

## Codex 建立的內容

大多數技能一開始都是 `SKILL.md` 檔案。工作流程需要時，`$skill-creator` 可加入較長的參考文件、指令碼或資源檔案。

## 你可以建立的技能

如果日後的任務都需要讀取同一份執行手冊、執行相同的 CLI、遵循同一套審查準則、撰寫同樣的團隊近況更新，或驗證同一個瀏覽器流程，便可使用相同模式。例如：

- **`$buildkite-fix-ci`** 會下載失敗作業的日誌、診斷錯誤，並提出最小幅度的程式碼修正方案。
- **`$fix-merge-conflicts`** 會簽出 GitHub PR、依據基底分支更新該 PR、解決衝突，並傳回確切的推送指令。
- **`$frontend-skill`** 讓 Codex 的成果符合你的 UI 風格偏好，並沿用現有元件、螢幕截圖驗證循環、素材選擇和瀏覽器細節潤飾流程。
- **`$pr-review-comments`** 把審查筆記轉成語氣得宜且附有 GitHub 連結的簡潔行內留言。
- **`$web-game-prototyper`** 規劃首個可玩循環的範圍、選擇素材、調整遊戲手感、擷取螢幕截圖，並在瀏覽器中進一步潤飾。
