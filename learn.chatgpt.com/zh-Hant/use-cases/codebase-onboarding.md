## 簡介

當你剛接觸某個程式碼庫，或突然需要處理不熟悉的功能時，Codex 可以協助你在開始修改程式碼前快速掌握狀況。目標不只是取得概略摘要，還要梳理請求流程、瞭解各模組的職責，並找出接下來值得閱讀的檔案。

## 使用方式

如果你剛接觸某個專案，最簡單的起點就是請 Codex 說明整個程式碼庫：

如果你要為現有程式碼庫新增功能，可以請 Codex 說明特定的系統區域。要求範圍界定得越明確，說明就越具體：

1. 將與你想瞭解的內容相關的檔案、目錄或功能區域提供給 Codex。
2. 請它追蹤請求流程，並說明哪些模組分別負責商業邏輯、傳輸、持久化或 UI。
3. 在編輯任何內容之前，先詢問驗證、副作用或狀態轉換發生的位置。
4. 最後，詢問接下來應閱讀哪些檔案，以及有哪些高風險環節。

有效的上手說明應讓你掌握清楚具體的脈絡，而不只是一份檔案名稱清單。最後，Codex 應說明主要流程、標出高風險部分，並指出你在開始編輯前，接下來應查看哪些檔案或執行哪些重要檢查。

## 接下來可問的問題

Codex 初步說明後，請繼續追問，直到內容具體到足以讓你有把握進行第一次編輯。好的後續問題通常能促使 Codex 點出各項假設、隱藏的相依性，以及變更後的重要檢查項目。

- 實際的商業邏輯與傳輸層或 UI 層，分別由哪些模組負責？
- 驗證在何處進行，又會在該處強制確保哪些假設成立？
- 如果我變更這個流程，有哪些相關檔案或背景工作容易遺漏？
- 編輯這個區域後，我應執行哪些測試或檢查？
