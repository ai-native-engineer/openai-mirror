## 從網站與部署目標著手

Codex 可建置或更新網站或應用程式、執行專案檢查、透過 Vercel 部署，並傳回網址。

交付內容越具體越有用，例如程式碼庫、螢幕截圖、地圖、設計摘要、產品說明、API 文件或資料來源。Codex 應先檢查專案再進行變更，然後預設使用 Vercel 外掛程式部署預覽版本。

當 Codex 需要建置或完善應用程式時，請使用 `@build-web-apps`。需要部署、檢查部署或讀取 Vercel 建置記錄時，請使用 `@vercel`。

## 分享前先檢查結果

Codex 應說明它變更了哪些內容、使用哪個指令建置專案，以及 Vercel 部署是否已準備就緒。若部署需要環境變數、選擇團隊、網域設定或登入步驟，Codex 應明確指出，而不是假裝網站已完成。

凡涉及正式環境的變更，都要明確說明。預設為預覽部署；只有在確定要部署至正式環境時才提出要求。

## 根據線上網址持續調整

取得預覽後，請繼續使用同一個對話。請 Codex 開啟網址、修正版面配置問題、更新文案、串接尚未接入的資料，或在部署失敗時讀取 Vercel 記錄。這個對話已包含程式碼庫、部署與建置所需的上下文。

有效的後續要求應具體明確：

- "行動裝置版面配置太擁擠了。請修正並重新部署預覽版本。"
- "請使用同一個專案，並加入來自 \[source\] 的最新資料。"
- "讀取建置失敗記錄，並修正部署問題。"
