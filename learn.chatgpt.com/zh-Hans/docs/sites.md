站点功能目前处于公开测试阶段，适用于 ChatGPT Plus、Pro、Business、Enterprise 和 Edu 套餐。测试期间，各套餐对应的使用限制适用于所有站点。ChatGPT 会显示当前限制，并在您即将达到某项限制时通知您。达到限制后，您可能无法创建站点、添加存储空间，或让用量较高的站点继续保持公开，但仍可编辑和管理现有站点。

站点功能让 ChatGPT 能够创建、托管、完善和分享网站、Web 应用及游戏。如果您希望将提示或兼容的现有项目转化为托管的网页体验，而无需单独设置部署工作流程，可以使用站点功能。

在 ChatGPT 桌面应用中打开 **站点** 。您可以根据提示或
兼容的本地项目创建站点，然后返回站点视图进行管理。

在网页版 ChatGPT 中使用站点功能创建和管理托管站点。选择
**更多** \> **站点**，或直接访问
[chatgpt.com/sites](https://chatgpt.com/sites)，即可找到您创建的站点。

站点功能没有独立的 Codex CLI 管理视图。请使用网页版 ChatGPT 或桌面应用创建、保存、部署和管理站点项目。发布前，您仍可使用 Codex CLI 编辑和测试本地项目。

站点功能没有独立的 IDE 扩展管理视图。请使用网页版 ChatGPT 或桌面应用执行站点相关操作，并使用 IDE 扩展编辑和测试本地源码项目。

  每个站点部署 URL 都对应一次生产环境部署。如果您希望在构建版本上线前进行审查，请让 ChatGPT 保存该版本，但不要部署。

## 开始使用站点

在 ChatGPT 的提示中加入“website”一词或提及 `@Sites`，
即可明确启动站点工作流程。

1. 描述站点

   描述站点的受众、用途、所需行为，以及站点应使用的信息。

2. 审查站点

   审查生成的内容和行为。确认站点使用预期的信息，并按预期处理数据。

3. 完善站点

   说明您希望进行的更改。如果相关文件或视觉上下文有助于 ChatGPT 完成更改，请添加这些内容。

4. 管理和分享站点

   返回 **站点** ，重新打开或完善相应站点。准备就绪后，选择哪些人
   可以访问该站点，并分享生成的链接。

在预览中选择 **编辑**。在 **描述网站修改**下，说明
您希望进行的更改。如果补充上下文会有所帮助，请使用 **截图** 或 **添加文件及其他内容** 
来提供相关信息。

## 查看站点分析数据

站点功能会自动记录访问流量，因此无需添加分析 SDK，即可了解用户如何使用已部署的站点。分析视图显示独立访客总数和页面浏览量，以及这两项指标随时间的变化。您可以更改日期范围或时间粒度，以查看不同时段的数据。

打开 **站点**，找到相应站点，然后选择 **更多操作** \> **分析**。

访问 [chatgpt.com/sites](https://chatgpt.com/sites)，找到相应站点，然后选择
**更多操作** \> **分析**。

站点功能在 CLI 或 IDE 扩展中没有独立的分析视图。请在网页版 ChatGPT 或桌面应用中打开站点，以查看其分析数据。

  

  目前，分析功能适用于不属于企业工作空间的站点。

## 添加“使用 ChatGPT 登录”功能

公开站点可以继续向所有人开放，同时提供可选的“使用 ChatGPT 登录”功能，以支持需要识别用户身份的功能，例如保存进度、个性化视图，或属于特定个人的记录。仅限工作空间访问的站点已使用 ChatGPT 身份信息，按分享设置控制访问。

请让站点功能添加登录功能：

```text
Add Sign in with ChatGPT to this public Site. Keep the Site available to signed-out visitors. Show a Sign in with ChatGPT action when someone is signed out. After they sign in, greet them with their full name when available, or their email address otherwise. Add a Sign out action, and keep authorization decisions in server-side code.

站点功能通过平台提供的路径处理登录和退出登录流程，然后引导访客返回您的站点：

```html
<a href="/signin-with-chatgpt">Sign in with ChatGPT</a>
<a href="/signout-with-chatgpt">Sign out</a>

访客登录后，站点功能会通过以下请求标头将其身份信息转发给服务器：

- `oai-authenticated-user-email` 包含经过身份验证的电子邮件地址。
- `oai-authenticated-user-full-name` 可能包含非空的个人资料名称。
  请将其视为可选字段，并在没有该值时改用电子邮件地址。

授权判断应在服务器端代码中完成，不要依赖分别传递姓和名的请求标头。

## 了解项目、版本和部署

站点会作为托管成果持续保留，
您可以在 ChatGPT 的 **站点** 中重新打开、完善、配置和分享它。

站点项目将本地源码项目与站点功能管理的托管服务关联起来。
站点功能会将这种关联关系和可选的存储绑定名称保存到
`.openai/hosting.json` 中。新建的本地起始项目最初可以没有
`project_id`；站点功能会在完成托管项目预配后添加该字段。

例如，使用关系数据库绑定且不使用文件存储的已预配站点，可以包含以下内容：

```json
{
  "project_id": "<project-id>",
  "d1": "DB",
  "r2": null
}

即使创建站点的 ChatGPT Work 聊天已经结束，该站点仍会显示在您的站点列表中。在网页端创建站点无需本地项目或清单。站点独立于 ChatGPT 项目。

站点发布分为两个独立阶段：

1. **保存版本。** ChatGPT 会构建一个可部署的版本。对于本地源码项目，
   ChatGPT 会将该版本与构建时使用的 Git 提交关联起来。
   如果您需要可供审查的部署候选版本，请执行此步骤。
2. **部署版本。** ChatGPT 会发布已保存的版本，并在部署成功后提供
   生产环境 URL。只有在您打算让所选受众访问站点时，
   才应执行此操作。

如果您需要确定以前的某个部署候选版本，请让 ChatGPT 列出或检查已保存的版本。

## 选择受支持的站点类型

对于新项目，站点工作流程可以从其推荐的站点起始模板开始。对于现有项目，请在请求部署之前，让 ChatGPT 确认该项目可以生成兼容的部署产物。

告诉 ChatGPT 您希望产品如何运作，以便它选择合适的站点类型：

| 站点需求                                                      | 向站点功能提出的要求                                                         |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 以内容为主的网站或落地页                            | 不持久化应用状态的站点，除非使用体验需要保存状态 |
| 保存记录、用户进度或游戏分数                   | D1，用于持久存储结构化数据的关系数据库                         |
| 图像、文档、音频、视频或其他上传内容              | R2，用于存储文件的对象存储                                                  |
| 包含可搜索元数据的已上传文件                        | 使用 D1 存储元数据，使用 R2 存储文件内容                                      |
| 需要使用当前工作空间用户身份信息的内部站点 | 经工作空间身份验证的用户身份                                         |
| 面向公众的登录功能或外部身份提供商                | 启用了身份验证的站点                                                |

请勿为临时界面状态（例如所选主题或已关闭的横幅）请求持久存储。对于用户希望托管站点保留的产品数据，则应请求持久存储。

## 管理访问权限和机密信息

在您更改访问权限之前，新建站点仅允许其所有者和工作空间管理员访问。在审查内容、数据处理方式和预期受众期间，请继续限制访问权限。

根据您的账户和工作空间设置，共享选项可能包括：

- **所有者和工作空间管理员**
- **选定的活跃用户或群组**（如支持此选项）
- **受邀的外部查看者**（在支持外部邀请时可用）
- **工作空间中的任何人**（如支持此选项）
- **互联网上的任何人**（仅在启用公开发布时可用）

访问者权限允许他人打开站点，但不赋予编辑权限。在企业工作空间中，公开发布默认关闭，必须由管理员启用。

对于受限共享，受邀访问者必须使用获得访问权限的账户登录。访问公开站点无需拥有 ChatGPT 工作空间的访问权限。站点的受众设置与站点内置的任何登录功能相互独立。

例如：

```text
Change this Site's access to everyone in my workspace after showing me the
current Site and confirming its URL.

### 邀请工作空间以外的人员

外部邀请可让您向指定人员授予站点访问权限，而无需公开站点。您可以邀请工作空间以外的查看者，也可以通过个人账户分享私有站点。此功能正逐步向 Plus、Pro、Business 和企业套餐的站点用户开放。

1. 打开您拥有的站点，然后选择 **分享**。
2. 若要保持站点私有，请将 **谁可以访问** 设为 **仅受邀人员**。
3. 在 **搜索人员或群组**中输入查看者的电子邮件地址；如果是个人站点，则在
**输入电子邮件地址** 中输入，然后选择收件人。
4. 检查受众范围和收件人的 **查看者** 权限，然后选择
**邀请**。
5. 确认查看者已显示在保存的访问权限列表中。分享站点链接，并请对方使用获得访问权限的账户登录。

外部查看者可以打开和使用站点。他们不会成为工作空间成员或站点编辑者，也无法编辑或发布站点。邀请会授予此站点的访问权限；请在分享前审查其内容和所连接的数据。

在企业套餐中，管理员可在 **工作空间设置 \> 权限与角色**下管理 **允许成员邀请外部访问者访问
站点** 。此权限
与公开发布站点的权限相互独立。
Business 工作空间没有单独的外部邀请权限
开关；必须启用站点，且该账户必须已获开放此功能。
如果看不到邀请选项，请检查所选账户、站点
所有权、工作空间权限以及此功能是否已向您开放。

若要移除查看者，请打开站点的共享设置并移除其访问权限。同时检查其余受众设置：移除一项邀请不会取消该人员通过公开共享、工作空间共享或群组共享获得的访问权限。

### 协作编辑站点

站点协作需要工作空间。在支持此功能的情况下，站点所有者可以邀请同一工作空间的活跃成员担任编辑者。

编辑者可以读取站点线上数据库中的数据。请仅邀请您信任的人员接触站点的代码和数据。

1. 打开站点，然后选择 **分享**。
2. 在 **添加人员或群组**下，找到并选择一名工作空间成员。该成员
   会被添加为访问者。
3. 打开该成员旁边的 **可查看** 菜单，然后选择 **可编辑**。权限设置会
   自动保存。该站点会显示在该成员的
   站点视图中的 **与您共享** 下。
4. 在所有者首次发布站点后，编辑者可以打开站点、进行修改、保存版本并发布更新。

站点所有者负责管理编辑权限，可以将现有访问者设为
编辑者、将编辑者的权限改为 **可查看**，或移除其访问权限。协同编辑
不会新增单独的工作空间权限开关。

编辑者不能更改站点的受众、邀请或移除其他人员、管理设置或分析数据、恢复较早的版本，也不能转让所有权。编辑者也不能首次发布站点；必须由所有者先发布站点，编辑者才能发布后续更新。

编辑权限与访问者权限相互独立。上述步骤会先将相关人员添加为访问者，再授予编辑权限。将访问者设为编辑者不会改变站点的受众设置。

### 配置运行时环境值

打开 **站点**，然后打开相应站点的设置，以添加、更新或移除托管环境中的
环境变量和机密值。请勿在提示、
附件或站点内容中包含机密值。

前往 [chatgpt.com/sites](https://chatgpt.com/sites)，找到相应站点，然后选择
**更多操作** \> **设置**。

请勿将这些值存储在 `.openai/hosting.json` 中。确保本地 `.env` 和
`.env.example` 文件中的键与本地开发所需的键保持一致，
并且不要提交机密值。

添加、更新或移除托管环境中的值后，请让 ChatGPT 重新部署已保存且已获批准的版本，以便下一次部署使用更新后的配置。

## 更改站点 URL

在支持编辑 URL 的情况下，站点所有者可以更改现有站点由 ChatGPT 托管的 URL，无需创建新的部署。

1. 打开 **站点**，找到相应站点，然后打开其设置。
2. 找到站点 URL，然后选择 **更改 URL**。
3. 输入一个可用的名称。名称必须至少包含五个字符，以小写字母开头，并且只能使用小写字母、数字和单个连字符。名称不能以连字符结尾，也不能包含连续的连字符。
4. 确认更改，然后等待站点更新地址。

更改 URL 不会创建新的部署。原地址会重定向到新地址，并保留路由和查询参数。

更改由 ChatGPT 托管的 URL 不会添加、移除或更改自定义域名。自定义域名是一项已有的独立功能；如支持该功能，请使用自定义域名设置。

## 连接自定义域名

在支持自定义域名的情况下，您可以连接自己已拥有的根域名或子域名。站点不会代您注册域名，因此您必须能够更改域名的 DNS 记录。功能推出时，企业工作空间不支持自定义域名。

连接域名的步骤如下：

1. 打开站点设置，然后选择 **添加域名**。
2. 输入您要使用的根域名或子域名。
3. 复制站点提供的 DNS 记录及其值，然后通过您的域名提供商添加这些记录。
4. 等待几分钟，然后返回站点设置并刷新域名状态。

您也可以让 ChatGPT 帮助您将域名指向站点。如果启用了浏览或计算机使用功能，ChatGPT 可以在您登录后协助您在域名提供商的平台上操作。

## 分享前进行审查

分享站点之前：

- 审查站点内容、生成的文本和图像、链接、上传的文件、表单以及交互行为。
- 确认站点不会泄露机密或敏感信息、机密值，或您无权分享的第三方内容。
- 从预期访问者的视角测试站点，包括其访问和登录行为。
- 审查收集个人信息或访问者提供的其他内容的功能。确定站点是否应收集、分享或发布这些信息。
- 如果站点采用“使用 ChatGPT 登录”功能，请说明其接收哪些访问者信息，以及如何使用这些信息。
- 如果站点收集或处理个人数据，请遵守
[适用的隐私和数据保护法律](https://help.openai.com/en/articles/20001340)。
- 选择能满足目标受众需求且共享范围最小的选项。
- 打开已共享的站点，确认目标受众可以访问。

对于从本地项目构建的站点，还应在 Codex 的[审查面板](/zh-Hans/codex/code-review?surface=app)中审查源代码更改和
所有数据库迁移。

## 下线或删除站点

若要取消访问权限而不删除站点，请打开其共享设置，将访问权限限制为仅您自己或选定的人员。确认之前的受众已无法打开该站点。

若要永久删除站点：

1. 打开 **站点** ，找到要删除的站点。
2. 选择 **删除站点** ，然后按照提示操作。
3. 输入站点的 Slug，然后选择 **永久删除**。

删除站点会将其永久移除。您无法恢复已删除的站点。

## 了解限制和不支持的用途

站点功能可托管在受支持的站点运行时中运行的网页体验。部分框架、私有网络、数据库、后台服务和托管模式不受支持。

支持 HTTP、HTTPS 和 WebSockets，但不支持原始入站和出站 TCP 连接。

每个站点都有以下存储限制：

| 资源            | 限制                  |
| ------------------- | ---------------------- |
| D1 数据库存储 | 10 GB                  |
| R2 对象存储   | 无固定存储限制 |

站点功能在推出时不支持数据驻留或推理驻留。这一限制适用于已部署的站点、站点代码、D1 和 R2 数据及文件存储、生成的产物和日志。

请勿使用站点处理受保护健康信息或支付卡数据；
面向未满 13 岁或未达到适用数字同意年龄的儿童；支持
金融交易；传播恶意软件；协助实施网络钓鱼；冒充个人
或组织；或以其他方式违反 OpenAI 政策。请参阅
[创建和管理 ChatGPT 站点](https://help.openai.com/en/articles/20001339)，
了解当前限制及相关政策链接。
