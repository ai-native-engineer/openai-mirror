使用项目整理相关聊天，并为 ChatGPT 提供所需的上下文。
ChatGPT 桌面应用中的 **项目** 视图包含 ChatGPT 项目和
关联到您计算机上文件夹的本地项目。

## 选择项目，或直接开始聊天

如果工作会持续一段时间、产生多个
成果，或依赖相同的文件和来源，请创建项目。如果工作内容独立，且不需要共享项目
上下文，则无需使用项目即可开始聊天。

使用项目集中管理相关聊天、文件、指令和来源。
同一个项目可以包含通过“聊天”或 ChatGPT Work 发起的聊天。

## 选择项目，或不使用项目开始聊天

如果工作会持续一段时间、产生多个
成果，或依赖相同的文件和来源，请创建项目。如果工作内容独立，且不需要共享项目
上下文，则无需使用项目即可开始聊天。

每个项目都有 **聊天** 部分，用于列出项目中的聊天，以及 **来源**
部分，用于存放上传的文件和已连接的上下文。项目指令适用于
项目中的所有聊天。ChatGPT 项目无法直接访问您计算机上的
文件夹，因此请上传或连接您希望 ChatGPT 使用的来源。

无论选择哪种方式，请从项目中开始新聊天，以使用其共享文件和
指令；之后可在 **聊天**部分重新打开该聊天。

Codex CLI 会将启动时所在的目录视为该聊天的项目。
请在您希望 Codex 执行任务的目录中运行 `codex`，或传入
`--cd <directory>`（`-C`）明确指定该目录。CLI 不提供
ChatGPT 的“项目”视图。

IDE 扩展会将 IDE 中打开的文件夹或工作空间视为本地
项目。在多根工作空间中，请为聊天选择对应的工作空间根目录。该
扩展不提供 ChatGPT 网页版或桌面应用中的“项目”视图。

## 在项目中工作

**项目** 视图集中显示 ChatGPT 项目和本地项目。
ChatGPT 项目会在相关聊天之间共享项目文件和上下文。本地
项目让聊天可以访问您计算机上的一个或多个文件夹，例如
一组源文件或一个代码库。

请针对每项不同的成果单独开始聊天，让消息和结果保持
聚焦，同时由项目统一整理相关工作。

  
    
  

## 在项目中工作

ChatGPT 项目让其中的聊天能够访问相同的已上传文件、项目
指令和已连接的来源。需要快速聊天时使用“聊天”，需要完成规模更大的交付成果时使用
ChatGPT Work；两者都会作为聊天显示在项目的
**聊天** 部分。请针对每项不同的成果单独开始聊天，让其
消息和结果保持聚焦，同时由项目保留共享上下文。

## 在项目目录中工作

请在应为聊天提供文件上下文的目录中启动 Codex。使用
`/new` 针对每项不同的成果单独开始聊天。Codex 运行时可使用 `/resume`，
也可运行 `codex resume`，以继续已保存的聊天。

聊天会保留对话记录和所记录的工作目录，而 Codex 会从
当前工作树读取文件。请将长期有效的项目指导保存在
`AGENTS.md` 或已提交的文档中，以供今后的聊天使用。

## 在工作空间中工作

打开应为聊天提供文件上下文的文件夹或工作空间。针对每项不同的成果
开始新聊天，然后从 **最近的聊天** 中选择对应聊天以
继续。同一项目中的聊天可以处理相同的文件，同时每个
聊天都会保留各自的对话记录。

当前选区和打开的文件会为当前轮次提供上下文。请将
长期有效的项目指导保存在 `AGENTS.md` 或已提交的文档中，以供
今后的聊天使用。

## 整理项目和聊天

让进行中的工作保持可见，并收起已完成的工作：

- **置顶项目** ，使其显示在侧边栏顶部附近。您也可以在
  “项目”视图中将其置顶。
- **置顶聊天** ，方便您经常返回；即使项目中出现较新的
  聊天，也能轻松找到它。
- **重命名聊天** ，使用简短标题说明聊天成果，例如“Q3
  发布简报”或“结账流程无障碍审查”。
- **搜索项目** ：在“项目”视图中搜索。打开侧边栏中的 **搜索聊天** ，
  在记得某个短语或分支名称、但不记得标题时查找以往的聊天。
  “搜索聊天”没有默认快捷键，但您可以在
   **设置 \> 键盘快捷键**中为其指定快捷键。
- **归档聊天** ：工作完成后，将对应聊天归档。在项目菜单中选择
**归档聊天** ，可将项目中的聊天一并归档。

置顶不会增加上下文，也不会改变 ChatGPT 可以访问的内容。它只会改变
项目或聊天在侧边栏中的显示位置。

可从 **设置 \> 已归档的聊天**恢复已归档的聊天。

## 使用本地项目处理文件夹和代码库

如果 ChatGPT 需要读取或更改您计算机上的文件，请添加本地项目。
项目不一定需要文件夹，但您可以根据需要附加文件夹。

要添加或更改文件夹，请打开项目菜单并选择 **编辑项目**。
选择 **添加文件夹** 即可附加多个文件夹。ChatGPT 可以读取和更改
每个附加文件夹中的文件。要更改默认工作目录，请将指针移至某个
文件夹，然后选择 **设为主文件夹**。

新聊天会在主文件夹中开始。Codex 还会将该文件夹作为
Git 操作以及自动发现 `AGENTS.md`、技能和
`config.toml` 的默认位置。其他文件夹仍可用于搜索、读取和
编辑文件，但 Codex 不会自动从
其他文件夹中发现这些项目文件。

当相关工作分布在不同位置时，例如应用与
其文档或网站与其后端，请使用多个文件夹。如果工作彼此无关，或者每个聊天
只应访问代码仓库的一部分，请创建单独的项目。
这样可以让工作上下文保持聚焦。远程项目目前仅支持一个
文件夹。

使用[本地环境](/zh-Hans/codex/environments/local-environment)为项目定义设置
操作和常用命令。[审查
窗格](/zh-Hans/codex/code-review?surface=app)可显示附加到同一项目的多个代码仓库
中的更改。Pull Request 操作和
[工作树](/zh-Hans/codex/environments/git-worktrees)操作都以主
代码仓库为目标。在工作树中开始聊天时，其他文件夹仍会保持
附加状态。

项目和工作树用于整理工作，但[沙盒](/zh-Hans/codex/sandboxing)
负责限制本地命令可以读取、更改或通过网络访问的内容。

## 不使用项目开始聊天

如果工作内容独立，且不需要共享项目文件、指令或文件夹访问权限，请选择 **新建聊天** 。

<a id="start-a-task-without-a-project-1"></a>

## 不使用项目开始聊天

如果聊天不需要共享的项目
文件、指令或来源，请从 ChatGPT 首页开始聊天。您可以使用“聊天”或 ChatGPT Work；在网页版中，
两者都会创建聊天。

如果工作范围扩大，请将其移入项目，并针对每项
成果使用清晰的聊天名称。一个项目可以包含分别用于研究、起草、审查和
后续跟进的并行聊天，而无需将所有消息混入同一个上下文。

## 使用快速对话快速提问

快速对话会打开普通的 ChatGPT 聊天。ChatGPT 聊天不会显示在
Codex 侧边栏中；该侧边栏用于显示您的 Codex 聊天和项目。

将指针移至 **新建聊天**，然后选择其右侧的 **快速对话** 图标。您也
可以按

<kbd>Cmd+Option+N</kbd>（macOS），或 <kbd>Ctrl+Alt+N</kbd>（Windows 和 Linux）。
您还可以从 **新建聊天**打开现有的 ChatGPT 聊天，并将其添加到 Codex
聊天中。
