## 让应用中合适的部分对系统可见

App Intents 是让 iOS 应用在自身 UI 之外也更实用的最直接方式之一。不要把您的应用当作一个封闭空间，只有用户启动应用并在界面中逐层点按后才能使用；请使用 Codex，公开应用中应供快捷指令、Siri、聚焦、小组件、控制项及由智能助理驱动的新型系统体验调用的操作和对象。

这对当前提升可发现性和实现自动化很有帮助，也是在为更加由智能助理驱动的未来做准备。如果您的应用已经能够撰写、打开、筛选、路由或总结有价值的内容，App Intents 可为系统提供一种以结构化方式调用这些能力的途径。

## 从操作和实体入手，而非覆盖每个屏幕

首次添加 App Intents 时，最佳做法通常不是“照搬整个应用”。请让 Codex 确定：

- 用户希望无需浏览完整界面即可触发的少数几项操作
- 系统需要理解哪些应用对象，才能正确路由这些操作
- 哪些工作流应以特定状态打开应用，哪些应直接在系统界面中完成

Apple 的 App Intents 指南为此提供了很好的思路：定义操作，定义系统所需的实体接口，然后让这些操作可在不同系统体验中被发现和复用。最实用的参考资料包括 [让操作和内容可被发现并广泛可用](https://developer.apple.com/documentation/appintents/making-actions-and-content-discoverable-and-widely-available)、[创建您的第一个 App Intent](https://developer.apple.com/documentation/appintents/creating-your-first-app-intent)，以及系统体验示例 [采用 App Intents 以支持系统体验](https://developer.apple.com/documentation/appintents/adopting-app-intents-to-support-system-experiences)。

## 从系统界面出发思考，而不只是快捷指令

这里的机会远不止“添加一条快捷指令”。设计良好的 App Intents 接口可让应用在多个场景中发挥作用：

- 快捷指令，用户可在其中直接运行操作，或将其组合成更大的自动化流程
- Siri，应用可在其中公开有意义的动词和深层链接，而不只是以通用方式打开应用
- 聚焦，应用实体和 App 快捷指令可在其中成为可被发现的系统入口
- 小组件、实时活动、控制项以及其他由意图驱动的 UI 界面
- 面向智能助理的新型体验，与任意 UI 流程相比，系统更容易理解其中的结构化操作和实体

## 遵循实际应用的架构模式

当应用采用如下结构时，通常效果最佳：

- 采用专用的 App Intents 目标，而不是将意图类型散布在互不相关的应用文件中
- `AppShortcutsProvider` 条目，用于撰写帖子或在指定标签页中打开应用等高价值用户操作
- 精简的 `AppEntity` 类型，用于表示系统需要理解的对象，例如账户、列表和时间线筛选条件
- 妥善将处理结果路由回应用主场景的意图处理逻辑，使调用的意图能够打开正确的撰写流程，或将应用切换到正确的标签页

对于大多数应用，我都会让 Codex 遵循这一模式：先构建一个面向系统的小型操作层，保持实体接口精简；当意图需要主 UI 时，再通过可预测的运行时交接机制返回应用。

## 让 Codex 设计首个意图接口

这里最有效的提示会向 Codex 提供您应用的核心对象和最重要的用户操作，然后要求它选择规模最小但实用的首个 App Intents 接口，而不是不加选择地公开所有内容。

## 实用技巧

### 向系统公开用户确实希望在应用外执行的操作

适合作为首批意图的通常是撰写、打开、查找、筛选、启动、继续或检查等操作。如果某项操作只有经过冗长的应用内设置流程才有用，它可能不适合放在第一轮 App Intents 中。

### 让实体比模型层更精简

系统通常不需要您的完整持久化模型。请让 Codex 定义规模最小的应用实体接口，同时仍为 Siri、快捷指令和聚焦提供足够的上下文，以正确路由和显示操作。

### 将其视为智能助理基础设施，而不只是快捷指令功能

即使您的首个版本中，用户能直接看到的改进仅限于 Shortcuts 或 Siri，更深层的收益也在于，您的应用开始通过结构化操作和实体来表达自身能力。与那些只能通过轻点操作和视图层级来体现自身能力的应用相比，这将使您的应用更容易接入未来的系统级入口和 AI 驱动型入口。
