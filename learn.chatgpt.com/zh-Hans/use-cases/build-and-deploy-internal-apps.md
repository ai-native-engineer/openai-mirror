## 在一项任务中完成构建和部署

站点是 ChatGPT 中的一项全托管式 Web 托管服务。您可以让 ChatGPT 创建应用，它会构建项目、运行项目以供测试、完成部署，并返回一个可供共享的 URL。

站点目前面向符合条件的付费套餐提供公开 Beta 测试。推出初期，免费版或 Go 套餐以及欧洲经济区（EEA）、瑞士或英国的用户无法使用；功能推出进度或工作空间设置也可能影响您能否访问。

其支持范围从静态站点一直到全栈 JavaScript 或 TypeScript Web 应用。因此，站点非常适合构建针对特定用途的内部工具，例如入职引导仪表板、培训中心、可搜索的资源库、轻量级工作流应用和报告视图。

有关设置、存储、部署和访问的指南，请参阅 [站点文档](/zh-Hans/codex/sites)。

从一项实用工作流开始。与提出宽泛要求来重建整个内部系统相比，范围清晰的初版更易于审查、部署和改进。

## 为 ChatGPT 提供工作流上下文

告诉 ChatGPT 应用面向哪些用户、用户需要执行哪些操作、应检查哪些源材料，以及哪些内容应在会话之间保留。明确说明预期的共享范围，并要求 ChatGPT 在部署前测试主流程。

使用 [插件](/zh-Hans/codex/plugins) 从已连接的内部数据源获取或刷新数据。请在 Web 端 Work 中，或在桌面端 Work 或 Codex 中，启动一项使用已连接应用或云端文件的站点任务。本地文件请使用桌面 App，已登录的网站请使用内置浏览器，现有 Chrome 会话请使用 Codex Chrome 扩展程序。

  如果您需要实时获取数据，可以使用在站点设置中配置的
  API 密钥连接第三方工具。不要在提示
  和文件中包含机密值。如果您想使用插件连接，可以 [从
  当前任务安排工作](/zh-Hans/codex/automations#schedule-work-from-a-task) 以获取数据
  （按设定的计划使用插件）、更新应用，并保存一个版本供审查。
  仅在获得审批后部署已审查的版本。

## 为应用选择存储方式

许多内部应用都需要持久化存储。站点支持两种存储原语：

- 使用兼容 SQLite 的数据库 D1 来存储结构化数据，例如清单状态、书签、筛选器、注释、配置和文件元数据。
- 使用 R2 对象存储来保存文件字节数据，例如需要持久保存的已上传文档、图像或其他资源。

将结构化元数据保存在 D1 中，将较大的文件对象保存在 R2 中。只读资源页面或小型静态站点可能不需要这两种存储中的任何一种。

站点不支持数据驻留或推理驻留。请勿用它处理受保护的健康信息或支付卡数据，也不要用它支持金融交易。在存储敏感信息前，请查阅 [站点数据和使用限制](https://help.openai.com/en/articles/20001339-creating-and-managing-chatgpt-sites)。

## 管理和共享项目

您可以管理哪些人能够访问已部署的项目。

在审查新项目的内容、数据处理方式和目标受众期间，请将其保持为私有状态。

根据您的账户和工作空间设置，您可以将其共享给：

- 您邀请的用户。
- 您工作空间中的所有人。
- 互联网上的任何人。

共享只允许他人访问项目，并不允许编辑。如需更改访问权限，请打开 [ChatGPT 中的站点](https://chatgpt.com/sites) 或直接让 ChatGPT 更改：

公开共享还适用于面向工作空间外部人员的轻量级活动指南、俱乐部资源页面或其他站点。在企业工作空间中，公开发布功能默认关闭，必须由管理员启用。即使有公开链接可用，也应将内部数据保持为私有状态。
