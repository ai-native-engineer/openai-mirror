## 简介

从一个技术栈迁移到另一个技术栈时，您可以使用 Codex 梳理并执行受控迁移，涵盖路由、数据模型、配置、身份验证、后台作业、构建工具、部署、测试，甚至语言和框架的惯例本身。

Codex 在这里很有用，因为它可以清点遗留系统、将旧概念映射到新概念，并通过多个检查点逐步落地变更，而不是一次性完成大规模重写。在您弃用遗留框架、移植到新运行时，或必须在产品保持正常运行的同时用一个技术栈逐步替换另一个技术栈时，这一点尤为重要。

## 使用方法

1. 首先清点迁移范围：遗留软件包、框架惯例、路由、数据访问、身份验证、配置、构建工具、测试、部署方面的假设，以及迁移后仍须保持的所有外部契约。
2. 请让 Codex 将遗留概念映射到目标技术栈，并指出哪些内容没有直接对应项。
3. 请选择一种增量策略：使用兼容层、逐模块移植、采用抽象分支，或采用绞杀者式替换，每次只处理一个边界。
4. 除非迁移本身迫使您做出用户可见的变更，否则请保持行为稳定，并明确说明这些例外情况。
5. 每个里程碑完成后，请执行能够证明功能对等性的最小范围验证：lint、类型检查、针对性测试、契约测试、冒烟测试，或与遗留路径进行并排对比检查。
6. 请在每个检查点后审查差异以及仍未消除的过渡风险，不要等到整个重写完成后再审查。

## 使用 ExecPlans

在我们的 [代码库现代化实践指南](/cookbook/examples/codex/code_modernization) 中，我们介绍了 ExecPlans：这类文档可让 Codex 掌握清理工作的全貌，明确说明预期的最终状态，并记录每一轮完成后的验证结果。
当您让 Codex 执行复杂迁移时，请要求它为系统的每个部分创建一份 ExecPlan，确保每项决策和技术栈选择均有记录，供日后审查。

## 结合目标推进

对于耗时较长的分段迁移任务，请使用 [目标](/zh-Hans/codex/use-cases/follow-goals) 来引导 Codex 完成工作。设定目标时，请明确最终状态、功能对等性检查、回滚预期和停止条件。
