## 让 Codex 负责完整的模拟器调试循环

在此用例中，最好由 Codex 负责整个循环：选择正确的应用目标，在模拟器中启动应用，检查当前屏幕，执行复现步骤，收集日志和截图，在需要时检查堆栈跟踪，修补代码，然后沿同一路径重新操作，以证明错误已消失。

如果您希望该循环一直由智能体自主执行，请使用 [Build iOS Apps 插件](https://github.com/openai/plugins/tree/main/plugins/build-ios-apps)。它的 iOS 调试器工作流基于 XcodeBuildMCP 构建，因此 Codex 可以与已启动的模拟器交互，并收集通常需要人工手动获取的同类证据。

为 XcodeBuildMCP 配置模拟器自动化、UI 自动化、调试和日志记录工作流后，Codex 就能负责完整的复现—调试—验证循环。如果 Codex 尚未选择项目、方案和模拟器，请先让它找到合适的项目、方案和模拟器，并在会话剩余期间复用该设置。

## 充分利用 XcodeBuildMCP 的功能

您可以在提示中要求 Codex 使用以下几类实用功能：

- 项目和模拟器发现：检查 Codex 是否已知道应使用哪个应用目标和模拟器，找到 Xcode 项目或工作空间，列出方案，找到或启动模拟器，并让该设置保持不变，以便用于后续构建和运行步骤。
- 构建和启动控制：构建当前应用目标，安装并启动面向模拟器的构建版本，需要时启用日志采集并重新启动应用；如果 Codex 需要检查应用专属的运行时日志，则确定应用的捆绑包 ID。
- UI 检查和交互：读取屏幕上的辅助功能层次结构、截图、点按控件、在字段中输入文本、滚动列表，以及执行边缘轻扫或其他模拟器手势。
- 日志和调试器状态：流式传输模拟器日志，将 LLDB 附加到正在运行的应用，设置断点，检查堆栈帧和局部变量，并在崩溃或卡死需要深入检查时运行调试器命令。

关键是让 Codex 在点按前检查视图树。XcodeBuildMCP 会提供辅助功能层次结构和坐标，因此 Codex 可以优先使用稳定的标签或元素 ID，而不是猜测屏幕上的原始坐标。

## 将模糊的错误转化为可复现的脚本

当您的提示给出一个具体错误和一个预期结果，并让 Codex 自主操作应用和收集证据时，iOS 调试器技能的效果最好。如果需要登录、深层链接或测试夹具，请一次说明清楚，并要求 Codex 仅在缺少相关输入导致无法继续时暂停。

## 实用技巧

### 要求提供证据，而不只是修复

请 Codex 提供用于解释错误的具体模拟器和方案，以及截图、日志片段和堆栈详情。这样一来，最终补丁会比仅凭一句“我觉得这样应该能修好”更易于审查。

### 优先使用辅助功能标签，而非坐标

如果控件缺少稳定的标签或辅助功能标识符，导致 Codex 不得不按坐标点按，请让它明确指出这一点。这通常表明，错误修复还应包含一项小幅的 UI 可测试性改进。

### 每次运行只处理一个错误

由模拟器驱动的调试循环功能强大，但每个提示只针对一种故障模式时，您仍会更容易相信其结果。请让 Codex 完成一轮复现—修复—验证循环，再扩展到相关问题。
