## 先明确网站和部署目标

Codex 可以构建或更新网站或应用、执行项目检查、通过 Vercel 部署，然后向您提供 URL。

交给 Codex 的材料应具体明确，例如代码仓库、截图、地图、设计简报、产品说明、API 文档或数据源。Codex 应先检查项目再进行更改，然后默认使用 Vercel 插件创建预览部署。

Codex 需要构建或完善应用时，请使用 `@build-web-apps`。需要执行部署、检查部署结果或读取 Vercel 构建日志时，请使用 `@vercel`。

## 分享前检查结果

Codex 应告诉您它做了哪些更改、使用了哪条命令构建项目，以及 Vercel 部署是否已就绪。如果部署需要设置环境变量、选择团队、配置域名或完成登录步骤，Codex 应明确说明这些要求，而不是在网站尚未完成时声称已经完成。

涉及生产环境的变更都应明确提出。默认创建预览部署；只有确实要部署到生产环境时，才要求执行生产部署。

## 基于可访问的 URL 继续迭代

获得预览版本后，请继续使用同一聊天。您可以让 Codex 打开该 URL、修复布局问题、更新文案、接入缺失的数据；如果部署失败，还可以让它读取 Vercel 日志。当前聊天中已经有与代码仓库、部署和构建相关的上下文。

有效的后续请求应具体明确：

- "移动端布局过于拥挤。请修复这个问题并重新部署预览版本。"
- "使用同一项目，并添加来自 \[source\] 的最新数据。"
- "读取构建失败日志并修复部署问题。"
