## 사이트와 배포 대상을 먼저 정하기

Codex는 웹사이트나 앱을 빌드하거나 업데이트한 뒤 프로젝트 검사를 실행하고 Vercel로 배포해 URL을 제공할 수 있습니다.

레포지토리, 스크린샷, 지도, 디자인 브리프, 제품 메모, API 문서 또는 데이터 소스처럼 구체적인 자료를 제공하면 작업을 더 효과적으로 맡길 수 있습니다. Codex는 변경 전에 프로젝트를 살펴본 다음 기본적으로 Vercel 플러그인을 사용해 프리뷰를 배포해야 합니다.

Codex가 앱을 빌드하거나 다듬어야 할 때는 `@build-web-apps`를 사용하세요. 배포하거나 배포 상태를 점검하거나 Vercel 빌드 로그를 확인해야 할 때는 `@vercel`을 사용하세요.

## 공유하기 전에 결과 확인하기

Codex는 변경한 내용, 프로젝트 빌드에 사용한 명령어, Vercel 배포 준비 여부를 알려야 합니다. 배포에 환경 변수, 팀 선택, 도메인 설정 또는 로그인 단계가 필요하다면 사이트가 완성된 것처럼 처리하지 말고 그 사실을 명확히 알려야 합니다.

프로덕션 변경은 명시적으로 요청하세요. 기본값은 프리뷰 배포이며, 프로덕션 배포는 실제로 필요한 경우에만 요청하세요.

## 라이브 URL을 바탕으로 반복 개선하기

프리뷰가 준비되면 같은 채팅을 계속 사용하세요. Codex에 URL을 열고 레이아웃 문제를 수정하거나, 문구를 업데이트하거나, 누락된 데이터를 연결하거나, 배포가 실패하면 Vercel 로그를 확인하도록 요청하세요. 이 채팅에는 이미 레포지토리, 배포, 빌드에 관한 컨텍스트가 있습니다.

후속 요청은 다음과 같이 구체적으로 작성하세요:

- "모바일 레이아웃이 너무 비좁습니다. 수정하고 프리뷰를 다시 배포해 주세요."
- "같은 프로젝트를 사용해 \[소스\]의 최신 데이터를 추가해 주세요."
- "실패한 빌드의 로그를 확인하고 배포 문제를 해결해 주세요."
