## 하나의 작업으로 빌드 및 배포

Sites는 ChatGPT에서 제공하는 관리형 호스팅 서비스입니다. ChatGPT에 앱을 만들어 달라고 요청하면 프로젝트를 빌드하고, 테스트용으로 실행하고, 배포한 후 공유 가능한 URL을 반환합니다.

Sites는 이용 자격을 갖춘 유료 플랜에서 공개 베타로 제공됩니다. 출시 시점에는 Free 또는 Go 플랜이나 EEA, 스위스, 영국에서 사용할 수 없으며, 단계적 출시 진행 상황이나 워크스페이스 설정에 따라 접근 가능 여부가 달라질 수 있습니다.

Sites는 정적 사이트부터 풀스택 JavaScript 또는 TypeScript 웹 앱까지 지원합니다. 따라서 온보딩 대시보드, 교육 허브, 검색 가능한 리소스 라이브러리, 간단한 워크플로우 앱, 보고서 화면처럼 특정 용도에 맞춘 내부 도구에 적합합니다.

설정, 스토리지, 배포 및 접근 권한에 관한 안내는 [Sites 문서](/ko-KR/codex/sites)를 참조하세요.

유용한 워크플로우 하나부터 시작하세요. 범위가 명확한 첫 번째 버전은 내부 시스템 전체를 재현해 달라는 광범위한 요청보다 검토하고 배포하고 개선하기가 더 쉽습니다.

## 예상 결과

첨부된 출시 브리프와 샘플 요청 5개를 사용하는 가상 예시입니다. 첫 번째 작업에서는 특정 용도에 맞춘 요청 트래커를 만들고 확인하며, 후속 요청에서는 담당자 필터를 추가하고 기한이 지난 요청을 더 쉽게 파악할 수 있게 합니다.

<div data-use-case-export-only>

출시 요청 트래커를 열면 차단된 요청 1개, 검토 중인 요청 2개, 기한이 지난 항목 1개를 포함한 **샘플 요청 5개가** 표시됩니다. 팀은 출시 및 상태별로 살펴보고, 차단된 작업을 필터링하고, 요청을 추가하고, 상태를 업데이트할 수 있습니다. 주요 플로우와 상태 저장 기능은 데스크톱 및 모바일 화면 너비에서 확인했습니다.

후속 요청을 반영한 트래커에는 담당자 필터가 추가되고 기한이 지난 작업이 강조됩니다. **차단된 요청은 맨 위에 유지되며 담당자가 없으면 요청을 준비 완료로 표시할 수 없습니다**. 미리보기는 계속 비공개로 유지되었습니다. Site는 게시하지 않았고 접근 권한도 변경하지 않았습니다.

## ChatGPT에 워크플로우 컨텍스트 제공

앱을 사용할 대상, 사용자가 수행해야 하는 작업, 검토해야 할 소스 자료, 세션 간 유지해야 할 항목을 ChatGPT에 알려 주세요. 의도한 공유 범위를 명확히 설명하고 배포 전에 주요 플로우를 테스트하도록 요청하세요.

연결된 내부 소스에서 데이터를 가져오거나 새로 고치려면 [플러그인](/ko-KR/codex/plugins)을 사용하세요. 연결된 앱이나 클라우드 파일을 사용하는 Sites 작업은 웹의 Work에서 시작하거나 데스크톱의 Work 또는 Codex에서 시작하세요. 로컬 파일에는 데스크톱 앱을, 로그인된 사이트에는 내장 브라우저를, 기존 Chrome 세션에는 Codex Chrome 확장 프로그램을 사용하세요.

  실시간으로 데이터를 가져와야 하는 경우 Site 설정에서 구성한
  API 키를 사용해 타사 도구에 연결할 수 있습니다. 프롬프트와
  파일에 비밀 값을 포함하지 마세요. 플러그인 연결을 사용하려면 [현재 작업에서
  작업을 예약](/ko-KR/codex/automations#schedule-work-from-a-task)하여 정해진 일정에 따라 플러그인으로 데이터를
  가져오고, 앱을 업데이트하고, 검토할 버전을 저장할 수 있습니다.
  검토를 마친 버전은 승인을 받은 후에만 배포하세요.

## 앱에 사용할 스토리지 선택

많은 내부 앱은 데이터를 영구 저장해야 합니다. Sites는 두 가지 스토리지 기본 요소를 지원합니다:

- 체크리스트 상태, 북마크, 필터, 주석, 구성, 파일 메타데이터 같은 구조화된 데이터에는 SQLite 호환 데이터베이스인 D1을 사용하세요.
- 업로드된 문서, 이미지 또는 영구 보관해야 하는 기타 자산의 파일 바이트에는 R2 객체 스토리지를 사용하세요.

구조화된 메타데이터는 D1에, 더 큰 파일 객체는 R2에 저장하세요. 읽기 전용 리소스 페이지나 소규모 정적 사이트에는 둘 다 필요하지 않을 수 있습니다.

Sites는 데이터 레지던시나 추론 레지던시를 지원하지 않습니다. 보호 대상 의료 정보나 결제 카드 데이터를 처리하거나 금융 거래를 가능하게 하는 용도로 사용하지 마세요. 민감한 정보를 저장하기 전에 [Sites의 데이터 및 사용 제한](https://help.openai.com/en/articles/20001339-creating-and-managing-chatgpt-sites)을 검토하세요.

## 프로젝트 관리 및 공유

배포한 프로젝트를 누가 방문할 수 있는지 관리할 수 있습니다.

새 프로젝트의 콘텐츠, 데이터 처리 방식, 공유 대상을 검토하는 동안 프로젝트를 비공개로 유지하세요.

계정 및 워크스페이스 설정에 따라 다음 대상과 공유할 수 있습니다:

- 초대한 사용자.
- 워크스페이스의 모든 사용자.
- 인터넷상의 모든 사용자.

공유하면 다른 사용자가 프로젝트를 방문할 수 있지만 편집 권한은 부여되지 않습니다. 접근 권한을 변경하려면 [ChatGPT에서 Sites](https://chatgpt.com/sites)를 열거나 ChatGPT에 직접 요청하세요:

공개 공유는 워크스페이스 외부 사용자를 위한 간단한 이벤트 안내, 동호회 리소스 페이지 또는 기타 사이트에도 적합합니다. 엔터프라이즈 워크스페이스에서는 공개 게시가 기본적으로 꺼져 있으며 관리자가 활성화해야 합니다. 공개 링크를 사용할 수 있더라도 내부 데이터는 비공개로 유지하세요.
