## 소개

코드베이스에 미사용 코드, 중복 로직, 낡은 추상화, 대형 파일 또는 변경 비용을 필요 이상으로 높이는 레거시 패턴이 쌓였다면, 리팩터링으로 엔지니어링 부채를 줄이는 방안을 고려해야 합니다. 리팩터링은 스택 마이그레이션으로 확대하지 않으면서 기존 시스템의 구조를 개선하는 작업입니다.

Codex는 먼저 복잡하게 얽힌 영역을 파악한 뒤, 미사용 경로 삭제, 대형 모듈 구조 정리, 중복 경로 통합, 오래된 프레임워크 패턴 현대화, 단계별 검증 강화 등의 정리 작업을 검토하기 쉬운 작은 단위로 적용할 수 있어 유용합니다.

현재 코드베이스 자체를 개선하는 것이 목표입니다:

1. 더 이상 필요하지 않은 미사용 코드, 오래된 헬퍼, 오래된 플래그, 호환성 shim을 제거합니다.
2. 헬퍼를 추출하고 컴포넌트를 분리하거나 사이드 이펙트를 더 명확한 경계로 옮겨 복잡한 모듈을 간소화합니다.
3. 레거시 패턴을 레포지토리의 현재 규칙에 맞는 방식으로 대체합니다. 예를 들어 최신 프레임워크 프리미티브, 더 명확한 타입, 더 단순한 상태 플로우, 표준 라이브러리 유틸리티를 사용합니다.
4. 외부에 공개된 동작을 그대로 유지하면서 다음 변경에 드는 비용을 줄입니다.

## 사용 방법

1. 수정을 시작하기 전에 Codex에 대상 영역을 파악하도록 요청하세요. 복잡한 모듈, 중복 로직, 미사용 코드, 테스트, 외부에 공개된 계약, 레포지토리에 더는 맞지 않는 오래된 패턴을 확인하게 하세요.
2. 한 번에 하나의 정리 주제만 선택하세요: 미사용 코드를 제거하거나, 제어 플로우를 단순화하거나, 오래된 패턴을 현대화하거나, 대형 파일을 각각 담당 범위가 명확한 작은 부분으로 나누세요.
3. Codex가 파일을 패치하기 전에 현재 동작, 적용하려는 구조적 개선 사항, 동작이 그대로 유지되었음을 입증할 수 있는 최소한의 검사를 설명하게 하세요.
4. 전체 정리 작업을 하나의 diff로 묶지 말고 각 단계가 끝날 때마다 검토하고 최소한의 유의미한 검사를 실행하세요.
5. 정리 작업을 완료하는 데 필요한 경우가 아니라면 스택 변경, 종속성 마이그레이션, 아키텍처 전환은 별도 작업으로 분리하세요.

  작업을 시작하기 전에 플랜 모드를 사용해 리팩터링 계획을
세울 수 있습니다.

## ExecPlans 활용하기

[코드 현대화 쿡북](/cookbook/examples/codex/code_modernization)에서는 ExecPlans를 소개합니다. ExecPlans는 Codex가 정리 작업을 전체적으로 파악하고, 목표 상태를 명확히 기술하며, 각 단계 후 검증 결과를 기록할 수 있게 해 주는 문서입니다.
리팩터링이 여러 모듈에 걸치거나 여러 세션이 필요할 때 유용합니다. 삭제 사항, 패턴 업데이트 내용, 안정적으로 유지해야 했던 계약, 아직 보류 중인 작업을 기록하는 데 사용하세요.

## 반복 가능한 패턴에 스킬 활용하기

[스킬](/ko-KR/codex/build-skills)은 동일한 정리 규칙을 여러 레포지토리, 서비스 또는 팀에서 반복해 적용할 때 유용합니다. 사용할 수 있다면 프레임워크별 스킬을 활용하고, 위험한 정리 작업에는 보안 및 CI 스킬을 추가하세요. 미사용 코드 제거, 모듈 추출 또는 레거시 패턴 현대화를 위한 검증된 체크리스트가 있다면 팀 스킬을 만드세요.
여러 코드베이스에 같은 현대화 단계를 반복해서 적용하게 된다면 Codex를 사용해 첫 번째 성공 사례를 재사용 가능한 스킬로 만들 수 있습니다.
