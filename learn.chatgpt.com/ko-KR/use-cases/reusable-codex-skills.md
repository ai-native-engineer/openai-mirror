## Codex가 바로 활용할 수 있는 스킬 만들기

스킬을 사용해 반복 작업에 필요한 재사용 가능한 지침, 리소스, 스크립트를 Codex에 제공하세요. [스킬](/ko-KR/codex/build-skills)을 사용하면 Codex를 처음 유용하게 활용했을 때의 작업, 문서, 명령어 또는 예시를 보존할 수 있습니다.

먼저 실제로 잘 작동한 예시 하나를 준비하세요: PR을 체리픽한 Codex 채팅, Notion의 릴리스 체크리스트, 유용한 PR 댓글 모음 또는 출시 프로세스를 설명하는 Slack 스레드 등입니다.

## 사용 방법

1. Codex가 사용할 컨텍스트를 추가하세요.

   보존하려는 Codex 채팅을 그대로 열어 둔 채 Slack 스레드나 문서 링크를 붙여 넣고, Codex가 기억해야 할 규칙, 명령어 또는 예시를 추가하세요.

2. 시작 프롬프트를 실행하세요.

   이 프롬프트는 원하는 스킬의 이름을 지정한 다음, 보존할 작업, 문서, PR, 명령어 또는 출력을 `$skill-creator`에 전달합니다.

3. Codex가 스킬을 만들고 검증하도록 하세요.

   결과에서는 `$skill-name`을 정의하고, 스킬이 트리거될 조건을 설명하며, 재사용 가능한 지침을 올바른 위치에 저장해야 합니다.

   `~/.codex/skills`에 있는 스킬은 어느 레포지토리에서나 사용할 수 있습니다. 현재 레포지토리의 스킬을 커밋하면 팀원도 사용할 수 있습니다.

4. 스킬을 사용한 다음 채팅에서 업데이트하세요.

   다음 PR, 알림, 검토, 릴리스 노트 또는 디자인 작업에서 새 `$skill-name`을 호출하세요. 스킬이 잘못된 테스트 명령어를 사용하거나, 검토 규칙을 빠뜨리거나, 런북 단계를 건너뛰거나, 실제로 보내지 않을 초안을 작성한다면 Codex에 해당 수정 사항을 스킬에 추가해 달라고 요청하세요.

## 참고 자료 제공

스킬이 어떻게 작동해야 하는지 설명하는 자료를 `$skill-creator`에 제공하세요.

| 보유한 자료                                              | 추가할 내용                                                                                                                                                             |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **보존하려는 Codex 채팅의 워크플로우** | 해당 채팅을 그대로 열어 둔 채 `use this chat`이라고 입력하세요. Codex는 채팅 컨텍스트, 명령, 편집 내용 및 피드백을 시작점으로 활용할 수 있습니다.                                         |
| **문서 또는 런북**                                      | 릴리스 체크리스트를 붙여 넣거나, 인시던트 대응 런북 링크를 추가하거나, API PDF를 첨부하거나, 레포지토리의 Markdown 가이드를 Codex가 참조하도록 하세요.                                 |
| **팀 대화**                                      | 누군가 알림을 설명한 Slack 스레드를 붙여 넣거나, 프런트엔드 규칙이 담긴 PR 검토 링크를 추가하거나, 고객 문제를 설명하는 지원 대화를 첨부하세요. |
| **스킬에서 재사용할 스크립트 또는 명령**             | 향후 Codex 작업에서 실행할 테스트 명령어, 미리보기 명령어, 릴리스 스크립트, 로그 가져오기 스크립트 또는 로컬 도우미 명령어를 추가하세요.                                    |
| **좋은 결과물**                                          | 향후 작업의 기준으로 삼을 병합된 PR, 최종 변경 로그 항목, 승인된 출시 공지, 해결된 티켓, 변경 전후 스크린샷 또는 Codex의 최종 답변을 추가하세요.         |

참고 자료가 Slack, Linear, GitHub, Notion 또는 Sentry에 있다면, 해당 도구를 Codex에 [플러그인](/ko-KR/codex/plugins)으로 연결하거나, 시작 프롬프트에서 언급하거나, 관련 부분을 채팅에 붙여 넣으세요.

## Codex가 만드는 항목

대부분의 스킬은 `SKILL.md` 파일로 시작합니다. `$skill-creator`는 워크플로우에 필요할 경우 더 긴 참고 자료, 스크립트 또는 에셋을 추가할 수 있습니다.

## 만들 수 있는 스킬

향후 작업에서도 동일한 런북을 읽거나, 동일한 CLI를 실행하거나, 동일한 검토 기준을 따르거나, 동일한 팀 업데이트를 작성하거나, 동일한 브라우저 플로우를 QA해야 할 때 이 패턴을 사용하세요. 예:

- **`$buildkite-fix-ci`** 스킬은 실패한 작업의 로그를 다운로드하고 오류를 진단한 뒤, 변경 범위를 최소화한 코드 수정안을 제안합니다.
- **`$fix-merge-conflicts`** 스킬은 GitHub PR을 체크아웃하고, 베이스 브랜치를 기준으로 업데이트한 다음, 충돌을 해결하고 정확한 푸시 명령어를 반환합니다.
- **`$frontend-skill`** 스킬은 Codex가 사용자의 UI 취향, 기존 컴포넌트, 스크린샷 QA 루프, 에셋 선택 방식 및 브라우저 마무리 작업에 맞춰 작업하도록 합니다.
- **`$pr-review-comments`** 스킬은 검토 메모를 적절한 어조와 GitHub 링크가 포함된 간결한 인라인 댓글로 바꿉니다.
- **`$web-game-prototyper`** 스킬은 첫 번째 플레이 가능 루프의 범위를 설정하고, 에셋을 선택하고, 게임 플레이 감각을 조정하고, 스크린샷을 캡처한 뒤 브라우저에서 결과물을 다듬습니다.
