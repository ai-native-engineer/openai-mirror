## 소개

한 스택에서 다른 스택으로 전환할 때 Codex를 활용하면 라우팅, 데이터 모델, 구성, 인증, 백그라운드 작업, 빌드 도구, 배포, 테스트는 물론 언어와 프레임워크 규칙 자체까지 마이그레이션 대상을 파악하고 체계적으로 이전할 수 있습니다.

Codex는 레거시 시스템의 현황을 파악하고, 기존 개념을 새 개념에 매핑하며, 한 번에 전면 재작성하지 않고 체크포인트별로 변경 사항을 적용할 수 있어 이런 작업에 유용합니다. 제품이 계속 작동해야 하는 상황에서 레거시 프레임워크에서 벗어나거나, 새 런타임으로 포팅하거나, 한 스택을 다른 스택으로 점진적으로 교체할 때 특히 중요합니다.

## 사용 방법

1. 먼저 레거시 패키지, 프레임워크 규칙, 라우팅, 데이터 액세스, 인증, 구성, 빌드 도구, 테스트, 배포 전제 조건, 전환 후에도 유지되어야 하는 외부 계약 등 마이그레이션 범위를 파악하세요.
2. Codex에 레거시 개념을 대상 스택에 매핑하고 직접 대응하는 항목이 없는 부분을 명시해 달라고 요청하세요.
3. 호환성 레이어, 모듈별 포팅, 추상화를 통한 브랜치 전환(branch-by-abstraction), 경계를 하나씩 교체하는 스트랭글러 방식 중에서 점진적 전략을 선택하세요.
4. 마이그레이션 자체로 사용자에게 보이는 변경이 불가피해질 때까지 기존 동작을 유지하고, 예외는 명확히 밝히세요.
5. 각 마일스톤 후에는 린트, 타입 검사, 집중 테스트, 계약 테스트, 스모크 테스트, 레거시 경로와의 병렬 비교 등 동등성을 입증하는 데 필요한 최소한의 검증을 실행하세요.
6. 전면 재작성이 끝날 때까지 기다리지 말고 체크포인트마다 diff와 남은 전환 리스크를 검토하세요.

## ExecPlans 활용하기

[코드 현대화 쿡북](/cookbook/examples/codex/code_modernization)에서는 ExecPlans를 소개합니다. ExecPlans는 Codex가 정리 작업의 전체적인 현황을 파악하고, 의도한 최종 상태를 명시하며, 각 작업 단계 후 검증 결과를 기록하는 데 사용하는 문서입니다.
Codex에 복잡한 마이그레이션을 맡길 때는 모든 결정과 기술 스택 선택 사항이 기록되어 나중에 검토할 수 있도록 시스템의 각 부분에 대한 ExecPlan을 만들게 하세요.

## 목표와 함께 사용하기

장기간 진행되는 마이그레이션 단위 작업에는 [목표](/ko-KR/codex/use-cases/follow-goals)를 사용해 Codex가 작업을 수행하도록 안내하세요. 명확한 최종 상태, 동등성 검사, 롤백 기준, 중단 조건을 지정해 목표를 설정하세요.
