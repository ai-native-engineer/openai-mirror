## 소개

컴퓨터 사용은 인터페이스를 확인하고, 플로우를 클릭해 진행하고, 필드에 입력하며, 실패한 내용을 기록할 수 있어 QA 점검에 적합합니다. 따라서 실제와 같은 사용자 여정에서 기능 버그와 UI 이슈를 모두 찾는 데 유용합니다.

핵심은 Codex에 테스트할 환경, 가장 중요한 플로우, 원하는 보고서 형식을 명확히 알려 주는 것입니다.

## 사용 방법

1. [컴퓨터 사용 플러그인](/ko-KR/codex/computer-use)을 설치하세요.
2. 어떤 앱, 빌드 또는 환경을 테스트할지 Codex에 알려 주세요.
3. 가장 중요하게 생각하는 플로우나 핵심 사용 사례를 명시하세요.
4. 결과를 쉽게 트리아지하거나 다른 사람에게 전달할 수 있도록 구조화된 보고서를 요청하세요.

요청 범위를 넓게 잡을 수도 있습니다:

- `@Computer Test my app. Find any major issues and give me a report.`

또는 더 구체적으로 요청할 수도 있습니다:

- `@Computer Test my app in staging. Cover signup, invite a teammate, and upgrade billing. Log every bug with repro steps, expected result, actual result, and severity.`

레포지토리에서 이미 테스트 계획 파일을 관리하고 있다면 채팅에 첨부하거나 Codex가 해당 파일을 참조하도록 지정하세요. 그러면 QA 점검이 기존 플로우를 따릅니다.

## 실용적인 팁

### 테스트 설정을 구체적으로 명시하세요

계정 상태, 테스트 데이터, 기능 플래그 또는 선택한 환경이 플로우에 영향을 준다면 처음부터 명시하세요. Codex가 로컬, 스테이징 또는 프로덕션과 유사한 환경 중 어디에서 테스트하는지 알면 훨씬 더 나은 결과를 제공합니다.

### 중요한 이슈 유형을 명시하세요

Codex가 기능 오작동, 레이아웃 이슈, 이해하기 어려운 문구, 시각적 회귀 또는 이 모두에 집중해야 하는지 명시하세요.

### 중단할지 계속할지 결정하세요

차단 이슈 하나만으로 실행을 종료해야 한다면 이를 명시하세요. 그렇지 않다면 Codex가 나머지 플로우를 계속 진행하고, 요약 전에 모든 비차단 이슈를 수집하도록 지시하세요.

## 유용한 후속 작업

QA 점검이 끝나면 같은 채팅을 열어 둔 채 Codex에 발견한 버그 중 하나를 수정하거나, 결과를 Linear 또는 GitHub에 바로 등록할 수 있는 초안으로 정리하거나, 다음 점검 범위를 실패가 발생한 특정 플로우 하나로 좁혀 달라고 요청하세요.
