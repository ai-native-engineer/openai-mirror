## 소개

Codex가 한 번의 일반적인 턴을 마친 뒤 멈추지 않고 지속적인 목표 하나를 향해 계속 작업하도록 하려면 `/goal`을 사용하세요. 목표가 명확하고 검증 루프가 있으며, 매 단계마다 직접 방향을 제시하지 않아도 Codex가 충분히 작업을 진행할 수 있는 경우에 유용합니다. `/goal`을 사용하면 사용자 입력 없이도 Codex가 여러 시간 동안 독립적으로 작업할 수 있습니다.

`/goal <objective>`로 목표를 설정하고 `/goal`로 현재 목표를 확인하세요. 실행을 제어해야 할 때는 `/goal pause`, `/goal resume` 또는 `/goal clear`를 사용하세요.

슬래시 명령어 목록에 `/goal`이 표시되지 않으면
`config.toml`에서 `features.goals`를 활성화하세요:

```toml
[features]
goals = true

CLI에서 `codex features enable goals` 명령어를 실행하거나 Codex에 실행을 요청할 수도 있습니다.

## 적합한 작업 선택하기

좋은 목표의 범위는 프롬프트 하나보다는 넓고 범위가 정해지지 않은 백로그보다는 좁아야 합니다. Codex가 무엇을 달성해야 하는지, 무엇을 변경하면 안 되는지, 진행 상황을 어떻게 검증할지, 언제 중단할지를 정의해야 합니다.

다음과 같은 작업에 적합합니다:

- 대상 스택, 동등성 검사, 제약 조건이 명확한 코드 마이그레이션
- 각 체크포인트가 끝날 때마다 Codex가 테스트를 실행할 수 있는 대규모 리팩터링
- Codex가 작동하는 결과물을 계속 개선할 수 있는 실험, 게임 또는 프로토타입

서로 관련 없는 작업을 단순히 모아 놓은 목록에는 목표를 사용하지 마세요.

## 루프 설정하기

1. 목표 하나와 종료 조건 하나를 명시하세요.
2. Codex가 먼저 읽어야 할 파일, 문서, 이슈, 로그 또는 계획을 지정하세요.
3. 진행 상황을 입증할 명령어나 산출물을 정의하세요.
4. Codex가 체크포인트 단위로 작업하면서 간략한 진행 로그를 남기도록 하세요.
5. 실행 중에는 `/goal`로 상태를 확인하세요.
6. 작업이 완료되거나 진행이 막히거나 방향을 변경해야 할 때 목표를 일시 중지하거나 재개하거나 지우세요.

핵심은 작업 조건을 명확히 정하는 것입니다. Codex는 시작하기 전에 "완료"의 의미를 알아야 합니다. 목표가 마이그레이션이라면 "완료"는 새 경로가 계약 테스트를 통과하고 레거시 경로로 여전히 롤백할 수 있는 상태를 의미할 수 있습니다. 목표가 게임이나 프로토타입이라면 "완료"는 앱이 빌드되고 실행되며, 입력으로 제공한 참조 자료 또는 예상 동작과 일치하는 상태를 의미할 수 있습니다.

  Codex에 도움을 요청하세요. 먼저 만들고 싶은 것에 대해
대화한 다음, Codex가 직접 목표를 설정하고 작업을 시작하도록 요청하세요.

## Codex가 독립적으로 작업하도록 하기

목표를 수행하는 동안 실행 과정을 신뢰할 수 있도록 간결한 진행 보고를 요청하세요. 유용한 상태 업데이트에는 현재 체크포인트, 검증한 내용, 남은 작업, Codex의 진행이 막혔는지가 포함됩니다.
상태 보고가 모호해지면 일회성 지시를 추가하기보다 목표를 더 구체화하세요. 다음으로 중요한 체크포인트, 이를 입증하는 명령어, 일시 중지해야 하는 조건을 Codex에 정확히 알려 주세요.

Codex는 목표를 수행할 때 사용자가 확인하지 않아도 여러 시간 동안 독립적으로 작업할 수 있습니다. 종료 조건에 도달했다고 확신하면 실행을 중단하므로 `/goal`은 모니터링할 필요가 없는 백그라운드 작업으로 생각하면 됩니다.

## 목표 예시

### 마이그레이션

게임을 새 스택으로, 모바일 앱을 새 플랫폼으로, 코드베이스를 새 프레임워크로 옮길 때는 `/goal`을 사용해 Codex에 마이그레이션을 맡길 수 있습니다:

### 프로토타입 제작

새 앱, 게임 또는 기능을 처음부터 만들 때 `/goal`을 사용하면 Codex가 완성도 높은 첫 버전을 구현하도록 할 수 있습니다. 만들려는 대상을 정확히 설명한 PLAN.md 파일을 사용해 첫 버전 제작 과정을 안내할 수 있습니다.

### 프롬프트 최적화

평가 스위트가 있다면 `/goal`을 사용해 평가 결과를 기준으로 프롬프트를 최적화할 수 있습니다. Codex는 실패 사례를 확인하고 프롬프트를 업데이트한 다음 평가를 다시 실행하며, 점수가 향상되거나 종료 조건에 도달할 때까지 이 과정을 반복할 수 있습니다.
