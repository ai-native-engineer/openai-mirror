## 소개

Codex가 동일한 API, 로그 소스, 내보낸 받은편지함 데이터, 로컬 데이터베이스 또는 팀 스크립트를 계속 사용한다면 이 작업에 조합 가능한 인터페이스를 제공하세요. 어느 폴더에서나 실행하고, 살펴보고, 범위를 좁히며, `git`, `gh`, `rg`, 테스트 및 레포지토리 스크립트와 조합할 수 있는 명령으로 만들면 됩니다.

Codex가 언제 CLI를 사용해야 하는지, 무엇을 먼저 실행할지, 출력을 간결하게 유지하는 방법, 다운로드한 파일이 저장되는 위치, 승인이 필요한 쓰기 명령을 기록하는 연계 스킬을 추가하세요.

이 워크플로우에서는 Codex가 `$cli-creator`를 사용해 명령을 빌드합니다. `$skill-creator`를 사용하면 `$ci-logs` 같은 재사용 가능한 스킬을 저장할 수 있으며, 이후 작업에서는 이 스킬을 이름으로 호출할 수 있습니다.

## CLI가 수행할 작업 정하기

Codex가 어떤 기술로 구현해야 하는지가 아니라, Codex로 무엇을 하려는지부터 정하세요. 좋은 CLI는 반복되는 읽기, 검색, 다운로드, 내보내기, 초안 작성, 업로드, 폴링 또는 안전한 쓰기 작업을 Codex가 어느 레포지토리에서나 실행할 수 있는 명령으로 바꿔 줍니다.

| 상황                                              | CLI를 사용해 Codex가 할 수 있는 작업                                                                                              |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| **CI 로그는 빌드 페이지를 거쳐야 확인할 수 있습니다.**                  | 빌드 URL을 받아 실패한 작업 로그를 `./logs`에 다운로드하고, 파일 경로와 짧은 발췌문을 반환합니다.                          |
| **지원 티켓이 매주 내보내기 파일로 제공됩니다.**         | 최신 CSV 또는 JSON 내보내기 파일을 인덱싱하고, 고객이나 문구로 검색한 뒤, 고정 ID로 티켓 하나를 조회합니다.                        |
| **API 응답이 너무 커서 컨텍스트에 담을 수 없습니다.**          | 필요한 필드만 나열하고, ID로 전체 객체를 조회하며, 완전한 응답은 파일로 내보냅니다.                      |
| **Slack 내보내기 파일에는 긴 스레드가 포함되어 있습니다.**                   | `--limit` 옵션으로 검색하고 스레드 하나를 조회한 다음, 전체 아카이브 대신 주변 컨텍스트를 반환합니다.                             |
| **팀 스크립트가 서로 다른 네 단계를 실행합니다.**           | 설정, 탐색, 다운로드, 초안 작성, 업로드, 폴링 및 실제 쓰기를 각각 별도 명령으로 분리합니다.                               |
| **플러그인이 레코드는 찾지만, Codex에는 파일이 필요합니다.** | 플러그인은 채팅에서 계속 사용하고, CLI로 첨부 파일, 트레이스, 보고서, 동영상 또는 로그 번들을 다운로드한 뒤 경로를 반환합니다. |

## 문서, 파일 또는 명령 공유하기

Codex가 참고하려면 문서 또는 OpenAPI 사양, 민감 정보를 가린 curl 명령, 내보내기 파일 또는 데이터베이스 경로, 로그 폴더, 기존 스크립트처럼 구체적인 자료가 필요합니다. CLI가 익숙한 스타일을 따르게 하려면 `gh`, `kubectl` 또는 팀 자체 도구에서 가져온 짧은 `--help` 출력을 붙여 넣으세요.

명령에 인증이 필요하면 지원해야 할 환경 변수 이름, 구성 파일 경로 또는 로그인 플로우를 Codex에 알려 주세요. 시크릿은 셸이나 구성 파일에 직접 설정하세요. 채팅에 시크릿을 붙여 넣지 마세요. 인증 정보가 없으면 CLI의 설정 검사가 원인을 명확히 알리며 실패하도록 Codex에 요청하세요.

## Codex에 CLI와 스킬 빌드 요청하기

이 페이지의 시작 프롬프트를 사용하세요. Codex가 참고할 소스와 CLI가 지원할 첫 번째 작업을 입력하세요.

Codex는 코드를 작성하기 전에 제안하는 명령 인터페이스를 보여 주고, 빌드 진행에 꼭 필요하지만 누락된 정보만 물어봐야 합니다.

## 어느 폴더에서나 명령이 작동하는지 확인하기

Codex가 `cargo run`, `python path/to/script.py` 또는 설치되지 않은 패키지 명령을 실행한 뒤 작업을 끝내서는 안 됩니다. 이후 작업에서 사용할 방식과 동일하게, 설치된 명령을 다른 레포지토리나 임시 폴더에서 테스트하도록 요청하세요.

**나중에 에이전트가 사용할 방식으로 CLI 테스트하기**

Codex가 거대한 JSON 덩어리를 반환하면 기본 응답의 범위를 좁히고 전체 페이로드를 파일로 내보내는 기능을 추가하라고 요청하세요. 승인 경계를 잊으면 다른 작업에서 사용하기 전에 연계 스킬을 업데이트하도록 요청하세요.
