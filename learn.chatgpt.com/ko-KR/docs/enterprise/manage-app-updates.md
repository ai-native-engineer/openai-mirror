ChatGPT 데스크톱 앱은 일반적으로 업데이트를 자동으로 확인하고 설치합니다. 조직에서
새 릴리스가 사용자에게 제공되기 전에 검토해야 한다면 앱의 기본 제공
업데이터를 끄고 기기 관리 플랫폼을 통해 승인된 버전을
배포할 수 있습니다.

앱 업데이터는 기본적으로 활성화되어 있습니다. 이를 꺼도 Microsoft Store,
Microsoft Intune, 모바일 기기 관리(MDM), 패키지 관리자 또는 기타 외부
배포 도구에서 업데이트를 설치하는 것은 차단되지 않습니다.

## 시작하기 전에

다음 항목을 갖추었는지 확인하세요:

- 워크스페이스에서
[관리형 구성](https://chatgpt.com/codex/settings/managed-configs)에
  접근할 수 있는 Codex 관리자 권한.
- 조직 관리형 업데이트를 지원하는 macOS 또는 Windows용 ChatGPT 데스크톱
앱 릴리스.
- 관리 기기에 승인된 앱 패키지를 설치할 수 있는 MDM 또는 소프트웨어
배포 플랫폼.
- 새 릴리스를 테스트하고 보안 업데이트를 배포하며 설치된 앱 버전을
추적하는 프로세스.

Windows에 앱을 아직 배포하지 않았다면
[Windows 앱 배포](/ko-KR/codex/enterprise/windows-deployment)부터 시작하세요.

## 앱 내 업데이트 끄기

  앱 내 업데이트를 끄면 조직에서 새 앱 릴리스와 보안 수정 사항을
신속하게 배포해야 합니다. 업데이트가 지연되면
앱과 앱에 포함된 구성 요소가 알려진 보안
취약점에 노출될 수 있습니다. 이전 앱 버전에는 별도의 보안 패치나
연장 지원이 제공되지 않습니다.

데스크톱 앱의 자체 업데이터를 비활성화하는 관리형 정책을 만드세요:

1. [관리형 구성](https://chatgpt.com/codex/settings/managed-configs)을
여세요.
2. **정책 추가를** 선택하거나 관리하려는 사용자, 그룹 또는
   플랫폼에 적용할 기존 정책을 여세요.
3. **대상에서** **대상 추가를** 선택해 정책을 특정
**그룹**, **사용자** 또는 **플랫폼에** 할당하세요. 가능하면
   소규모 파일럿 그룹부터 시작하세요.
4. **원시 TOML을** 열고 **requirements.toml** 편집기를 찾으세요.
5. 다음 정책을 추가하세요:

   ```toml
   [features]
   in_app_updates = false

   정책에 이미 `[features]` 테이블이 있다면 해당 테이블에
`in_app_updates = false`를 추가하세요. 두 번째 `[features]` 테이블을 추가하거나
   설정을 **config.toml에** 넣지 마세요.

6. **변경 사항 저장을** 선택하세요.
7. 영향을 받는 사용자에게 ChatGPT 데스크톱 앱을 완전히 종료한 후 다시 열도록 요청하세요.
앱 창을 닫는 것만으로는 애플리케이션이 재시작되지 않을 수 있습니다.

일부 워크스페이스에는 **원시 TOML** 탭 대신 정책 목록 편집기가 표시됩니다.
이 인터페이스에서는 동일한 TOML 블록을 해당 정책에 직접 추가하고, 가능하면
**그룹을** 사용해 할당한 다음 **저장을** 선택하세요.

관리형 정책의 전달 및 우선순위에 관한 자세한 내용은
[관리형 구성](/ko-KR/codex/enterprise/managed-configuration)을 참조하세요.

## 관리형 설정 확인

앱이 재시작되면 영향을 받는 사용자의 기기에서 정책을 확인하세요:

1. 정책 적용 대상 계정으로 ChatGPT 데스크톱 앱에 로그인하세요.
2. **설정** \> **일반을** 여세요.
3. **앱 내 업데이트** 항목을 찾아 **관리됨** 표시와
   “조직에서 앱 내 업데이트를 사용 중지했습니다.”라는 메시지가 나타나는지 확인하세요.
4. 기기 관리 플랫폼에서 승인된 앱 버전을 계속 배포할 수 있는지
확인하세요.

**업데이트 확인** 메뉴 옵션은 정책으로 앱 내 업데이트를
차단해도 계속 표시될 수 있습니다. 해당 메뉴 옵션의 표시 여부가 아니라
**관리됨** 표시로 정책을 확인하세요.

처음 재시작한 후 표시가 나타나지 않으면 앱이 아직 캐시된 정책을
사용하고 있을 수 있습니다. 정책이 새로 고쳐질 때까지 기다린 다음 앱을 완전히
종료하고 다시 여세요. **관리됨** 표시가 나타나기 전에는 업데이트 제한이 적용된다고 간주하지 마세요.

## 승인된 앱 버전 배포

앱 내 업데이트를 끈 후 기존 기기 관리 프로세스를 사용하여
새 릴리스를 배포하세요:

1. 조직에서 배포할 앱 버전을 선택하세요.
2. 관리 중인 각 운영 체제와 기기 아키텍처에 맞는 지원 설치 패키지를
확보하세요.
3. 대표 사용자로 구성된 소규모 그룹에서 릴리스를 테스트하세요.
4. Microsoft Intune, MDM 플랫폼 또는 다른 소프트웨어 배포 도구를 통해
승인된 패키지를 배포하세요.
5. 기기 인벤토리에서 플랫폼이 지정한 버전을 설치했는지 확인한 후
다른 그룹으로 롤아웃을 확대하세요.

릴리스의 단계적 배포와 버전 선택, 완료되지 않은 배포의 복구 방식은 관리
플랫폼에서 결정됩니다. 플랫폼에서 롤백을 허용하더라도 이전 버전으로
되돌린다고 해서 지원 기간이 연장되거나 서비스 호환성이
보장되는 것은 아닙니다.

macOS용으로는
[ChatGPT 데스크톱 앱 설치 프로그램](https://persistent.oaistatic.com/codex-app-prod/ChatGPT.dmg)을 다운로드하세요.
Windows 설치 방법 및 아키텍처별 패키지에 관한 자세한 내용은
[Windows 앱 배포](/ko-KR/codex/enterprise/windows-deployment)를 참조하세요.

## 앱 내 업데이트 다시 켜기

앱의 정상적인 업데이트 동작을 복원하려면:

1. 영향을 받는 사용자의 업데이트를 끄는 관리형 정책, 시스템 `requirements.toml` 파일 및 MDM
   프로필을 확인하세요.
2. 해당하는 각 `[features]` 테이블에서 `in_app_updates = false`를 삭제하세요.
3. 정책 변경 사항을 저장하고 업데이트된 기기 관리형 요구 사항을 다시 배포하세요.
4. 영향을 받는 사용자에게 ChatGPT 데스크톱 앱을 완전히 종료한 후 다시 열도록 요청하세요.
5. **설정** \> **일반에서** 관리형 **앱 내 업데이트**
   행이 더 이상 표시되지 않는지 확인하세요.

적용 가능한 정책에서 `in_app_updates = false`를 설정하지 않으면 앱의 기본 제공
업데이터가 정상적으로 작동합니다. **관리됨** 표시가 계속
나타나면 다른 워크스페이스 정책, MDM 프로필, 시스템
`requirements.toml` 파일을 검토하세요. 관리형 소스가 적용되는 순서는
[위치 및 우선순위](/ko-KR/codex/enterprise/managed-configuration#locations-and-precedence)에서
확인할 수 있습니다.

## 보안 및 지원 책임 이해하기

앱이 관리형 업데이트 정책을 수신해 적용하면 해당 정책은 다음을 수행합니다:

- 데스크톱 앱이 자체 업데이터를 통해 업데이트를 확인, 다운로드 또는 설치하지
못하게 합니다.
- OpenAI에서 관리하는 버전 고정, 별도 릴리스 채널 또는 이전 버전의
서비스 호환성 보장을 제공하지 않습니다.
- 지원되는 macOS 및 Windows 빌드용 ChatGPT 데스크톱 앱에 적용됩니다. 모바일
앱, Codex CLI 또는 IDE 확장의 업데이트는 관리하지 않습니다.

## 일반적인 문제 해결

인증 문제, 연결 문제 또는 시간 초과로 앱이 관리형 정책을 가져오거나
적용하지 못하면 기본 제공 업데이터가 계속 활성화되어 있을 수 있습니다.
**관리됨** 표시가 나타나기 전에는 앱이 업데이트를 차단한다고 간주하지 마세요.

**관리됨** 표시가 나타나지 않으면 다음 항목을 확인하세요:

- 영향을 받는 사용자가 올바른 워크스페이스를 선택했는지 확인하세요.
- 정책이 해당 사용자, 그룹 또는 플랫폼을 대상으로 하는지 확인하세요.
- 기기에서 지원되는 앱 버전을 실행하고 있는지 확인하세요.
- 앱이 관리형 정책을 전달하는 서비스에 연결할 수 있는지 확인하세요.
- 설정이 **requirements.toml** 파일에 있으며 **config.toml** 파일에는 없는지 확인하세요.
- 정책을 저장한 후 사용자가 앱을 완전히 종료하고 다시 열었는지 확인하세요.

관리형 구성을 열거나 정책을 저장할 수 없다면 워크스페이스의 Codex
관리자 권한이 있는지 확인하세요.

앱 내 업데이트를 비활성화한 후 앱 버전이 변경되면
Microsoft Store, Intune, MDM, 패키지 관리자 또는 다른 배포 시스템이
업데이트를 설치했는지 확인하세요. 이 정책은 앱의 기본 제공 업데이터만 제어합니다.
