ChatGPT Work는 Codex의 기반 기술을 ChatGPT에 적용해 시간이 오래 걸리고
여러 단계가 필요한 작업을 처리할 수 있게 합니다. 채팅, 파일, 워크스페이스
리소스와 연결된 시스템에서 컨텍스트를 수집하고, 승인된 도구를 사용하며,
바로 검토할 수 있는 결과물을 만들 수 있습니다. 액세스, 컨텍스트, 수행할 수 있는 동작,
네트워크 동작 및 크레딧 사용량은 플랜, 워크스페이스 설정, 소스 권한과 사용 환경에 따라 달라집니다.

## 개요

ChatGPT Work를 사용하면 시간이 오래 걸리고 여러 단계가 필요한 작업을 ChatGPT에 위임할 수 있습니다.
연결된 소스에서 정보를 수집하고 여러 단계에 걸쳐 추론하며, 문서,
프레젠테이션 또는 분석 자료를 작성한 후 검토할 수 있도록 결과를 제공합니다.

ChatGPT Work는 지원 대상 플랜과 워크스페이스에서 지원되는 웹, 모바일,
데스크톱 환경을 통해 사용할 수 있습니다. 기능이 지원되는 경우 워크스페이스 소유자 또는 권한이 있는
관리자는 Work Cloud, Work Local, Codex Local을 각각 별도의
권한으로 관리할 수 있습니다. 지원 대상 Enterprise 및 Edu 워크스페이스에서는
권한이 있는 관리자가 비활성화하지 않는 한 기본 워크스페이스 역할에 Work가 포함됩니다. 브라우저와
네트워크 제어는 Work Cloud를 추가로 제한하며, 사용 가능 여부는 역할,
플랜, 워크스페이스 및 지역에 따라 달라집니다. 자세한 내용은
[ChatGPT Work와 Codex](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex)를 참조하세요.

이 자주 묻는 질문에서는 관리자가 ChatGPT Work를 관리하는 방법을 설명합니다. 액세스 및 데이터 제어,
규정 준수와 가시성, 사용량과 지출, 인시던트 대응 및
도입 방식을 다룹니다. 호스팅 실행 모델과 보안 경계는
[ChatGPT Work 개요](/ko-KR/codex/enterprise/chatgpt-work-overview)를 참조하세요.

## 핵심 관리 제어 기능

관리자는 다음 제어 계층을 통해 ChatGPT Work를 관리합니다:

- **엔터프라이즈 워크스페이스 액세스:** ID 및 액세스 제어로 워크스페이스의
  인증과 액세스를 관리합니다. 플랜과 구성에 따라 관리자가 제어할 수 있는
  ID 기능에는 SSO, 도메인 확인, SCIM 프로비저닝,
  사용자 수명 주기 관리, ID 그룹 동기화가 포함될 수 있습니다.
  ChatGPT Business에는 SCIM과 동기화된 ID 그룹이 포함되지 않습니다.
  사용자는 계정 수준의 OpenAI 다중 인증(MFA)을 활성화할 수 있습니다.
  ChatGPT는 워크스페이스 전체에 다중 인증(MFA)을 의무화하는 기능을 제공하지 않습니다.
  이를 요구하는 조직은 ID 공급자를 통해 SSO와 다중 인증(MFA)을 의무화해야 합니다.
  SSO와 관련 ID 설정은
[글로벌 관리자 콘솔](https://help.openai.com/en/articles/12289294-admin-portal)에서 관리하세요.
  [다중 인증](https://help.openai.com/en/articles/7967234-enabling-or-disabling-multi-factor-authentication-mfa)을 참조하세요.
- **워크스페이스 내 ChatGPT Work 액세스:** 기능이 제공되는 경우 Work Cloud는
  지원되는 웹, 모바일, 데스크톱 환경에서 호스팅되는 Work를 관리합니다.
  Work Local은 로컬 데스크톱의 Work를 관리하며, Codex Local은 데스크톱, CLI, IDE
  클라이언트에서 지원되는 로컬 Codex 액세스를 제어합니다. 클라우드 브라우저와 네트워크
  설정은 Work Cloud를 추가로 제한합니다. 사용자 지정 역할 기반 접근 제어(RBAC)와
  사용 가능한 권한은 플랜과 워크스페이스에 따라 달라집니다.
- **그룹 멤버십:** SCIM을 지원하는 플랜에서는 ID 공급자를 통해 그룹을
  동기화하여 직원의 입사, 역할 변경, 퇴사에 맞춰
  액세스 권한이 업데이트되도록 하세요. 자세한 내용은
[그룹 및 프로비저닝](/ko-KR/codex/enterprise/groups-and-provisioning)을 참조하세요.
- **워크스페이스 및 멤버 역할:** Enterprise의 기본 제공 역할에는 소유자,
  관리자, 멤버, 분석 조회자가 포함됩니다. 지원되는 플랜에서는 사용자 지정 역할과
  멤버 RBAC로 ChatGPT Work, 플러그인 및 기타 기능에 대한 액세스를 제어합니다.
  시트 유형이 적용되는 경우 멤버에게는 ChatGPT가 포함된 시트도 필요하며,
  Codex 전용 시트로는 Work 액세스 권한이 부여되지 않습니다. 자세한 내용은
[역할 및 워크스페이스 권한](/ko-KR/codex/enterprise/roles-and-workspace-permissions)을 참조하세요.
- **플러그인 및 앱:** 플러그인 정책은 플러그인의 사용 가능 여부와
  설치를 관리합니다. 앱 액세스, 동작 제어 및 승인 방식은
  별도로 구성합니다. 워크스페이스 에이전트에는 지원되는 경우 자체 제어 기능이
  적용됩니다. 자세한 내용은 [플러그인 제어](/ko-KR/codex/enterprise/apps-and-connectors),
[플러그인](/ko-KR/codex/plugins) 및
[App 보안 백서](https://cdn.openai.com/business-guides-and-resources/app-security-whitepaper.pdf)를 참조하세요.
- **소스 시스템 권한:** 사용자는 원본 애플리케이션에서 계정 또는 공유 연결에
  허용된 콘텐츠와 동작에만 액세스할 수 있습니다. 자세한 내용은
[앱의 관리자 제어, 보안 및 규정 준수](https://help.openai.com/en/articles/11509118-admin-controls-security-and-compliance-in-apps-enterprise-edu-and-business)를 참조하세요.
- **승인 및 동작 제한:** 동작 제어를 지원하는 앱에서는 관리자가
  모든 동작, 읽기 전용 동작 또는 직접 지정한 동작 집합을 허용하고
  새로 추가된 동작의 처리 방식을 결정할 수 있습니다. 이와 별개로 앱 권한에 따라
  ChatGPT가 앱을 사용하기 전에 확인을 요청하는 시점이 결정됩니다.
- **크레딧:** ChatGPT Work와 Codex는 요금, 크레딧 및 사용 한도를 공유합니다.
  지원 대상 Enterprise 및 Edu 관리자는 워크스페이스 기본값,
  그룹 기본값 및 개별 예외 설정으로 사용자별 월 한도를 설정할 수 있습니다.
  워크스페이스에서 허용하면 사용자는 한도 상향을 요청할 수 있습니다.
  Business에는 별도의 크레딧 및 지출 제어 모델이 적용됩니다. 자세한 내용은
[ChatGPT 사용 한도 및 지출 제어](/ko-KR/codex/enterprise/usage-limits)를 참조하세요.
- **분석 및 보고:** 글로벌 관리자 콘솔과 워크스페이스 분석은
  도입 현황과 크레딧 사용량 분석을 지원합니다. Compliance API 및 Codex
  보고 화면은 문서에 명시된 이벤트와 제품 범위에 맞게 사용하세요.
  특정 프롬프트, 파일, 승인, 동작, 오류 또는 도구 호출이 포함된다고 안내하기 전에
  현재 스키마를 검토하세요. 자세한 내용은
[거버넌스](/ko-KR/codex/enterprise/governance)를 참조하세요.

## 액세스, 데이터, 시스템 및 사용자 동작

### 데이터와 시스템에 대한 액세스 및 사용자 동작은 어떻게 보호되나요?

ChatGPT Work에는 ChatGPT 워크스페이스에 이미 설정된 ID, 액세스 및 권한
제어가 적용됩니다. 관리자는 ID 관리와
워크스페이스 역할을 사용하며, 지원 대상 플랜에서는
[RBAC](https://help.openai.com/en/articles/11750701-rbac)도 활용해 ChatGPT Work를
사용할 수 있는 대상을 결정합니다.

지원되는 경우
[SCIM](https://help.openai.com/en/articles/10011769-openai-platform-scim-integration-faq)과
그룹 동기화를 통해 ID 공급자와 액세스 권한을 동기화할 수 있습니다.
이를 통해 직원의 입사, 역할 변경, 퇴사에 따른 액세스와 권한을 중앙에서 관리할 수 있습니다.

소스 시스템에서는 작업에 사용되는 계정 또는 승인된 공유 연결의
권한이 적용됩니다. 개인 연결은 해당 사용자의 소스 시스템
액세스 권한을 사용합니다. 에이전트 소유 연결이나 공유 연결을 사용하면
권한이 있는 에이전트 사용자가 연결된 계정을 통해 데이터나 동작에 액세스할 수 있으며,
자신의 계정으로는 접근할 수 없는 데이터나 동작도 포함될 수 있습니다. 연결의 권한 범위,
사용 가능한 동작, 에이전트 사용 대상을 의도한 업무에 필요한 범위로 제한하세요. 자세한 내용은
[워크스페이스 에이전트 연결 및 권한](https://help.openai.com/en/articles/20001143-chatgpt-workspace-agents-for-enterprise-and-business)을 참조하세요.

### ChatGPT Work는 데이터와 컨텍스트에 어떻게 액세스하나요?

ChatGPT Work는 승인된 앱과 해당되는 경우 플러그인을 통해 현재 채팅,
업로드된 파일, 워크스페이스 리소스, 연결된 시스템을 사용할 수 있습니다.
활성화된 기능과 권한에 따라 문서, 레포지토리, 티켓, 채널, 이메일,
캘린더가 포함될 수 있습니다. 이전 파일은 현재 채팅, 지원되는 프로젝트,
승인된 Library 액세스 또는 활성화된 Library 자동 참조를 통해
사용할 수 있습니다. 저장된 메모리에는 별도의 워크스페이스 및 사용자 제어가 적용됩니다.

각 컨텍스트 소스에는 자체 제어가 유지됩니다. 사용자는 채팅 컨텍스트를 제공하고,
관리자는 워크스페이스 리소스를 관리하며, 연결된 시스템은 인증과
권한을 적용합니다. ChatGPT Work는 사용자 또는 승인된 공유 연결에
허용된 정보에만 액세스할 수 있습니다.

ChatGPT Work에는 해당되는 ChatGPT 워크스페이스 보호 조치가 적용됩니다. 레지던시, 보존,
로그 기록 및 기능 제공 여부는 플랜, 지역, 사용 환경과 연결된
시스템에 따라 달라지므로 현재 구성에 적용되는 범위를 확인하세요.

### 영향이 큰 동작 중 제한되거나 검토가 필요한 것은 무엇인가요?

동작마다 위험 수준이 다릅니다. 일반적으로 읽기나 초안 작성은 데이터
변경, 정보 공유 또는 외부 시스템에서의 동작보다 영향이 적습니다. 역할, 범위를 좁힌
권한과 자격 증명, 지원되는 승인 기능을 함께 활용해 영향이 큰 동작을
신뢰할 수 있고 검토를 거친 용도로만 사용하도록 제한하세요.

일반적인 동작 범주는 다음과 같습니다:

- **읽기:** 원본 데이터를 변경하지 않고
  승인된 소스의 정보에 액세스하거나 이를 검색 또는 요약합니다.
- **초안 작성:** 사용 전에 사람이 검토할 수 있도록 문서, 이메일, 보고서, 코드 또는 기타
  콘텐츠를 준비합니다.
- **쓰기:** 문서, 티켓, 레포지토리 또는 프로젝트 관리 도구 등 연결된 시스템의
  레코드를 생성, 업데이트 또는 삭제합니다.
- **공유:** 정보를 전송하거나 게시하는 등의 방법으로
  더 많은 사람, 시스템 또는 외부 대상이 정보에 접근할 수 있도록 합니다.
- **예약:** 사용자가 매번 직접 실행을 시작할 필요 없이
  향후 지정한 시각이나 반복 일정에 따라 작업을 시작합니다.
- **실행:** 코드, 셸 명령어, 브라우저 자동화 등
  외부 환경과 직접 상호작용하는 도구 기반 작업을 실행합니다.

영향이 큰 동작에는 사람의 검토, 제한된 자격 증명, 좁은 권한 범위 및
지원되는 승인 절차를 사용하세요. 플러그인 동작에는 각 통합의
권한 및 보안 제어가 계속 적용됩니다.

### ChatGPT Work는 기업의 개인정보 보호 및 데이터 관련 약정 이행을 어떻게 지원하나요?

ChatGPT Work에는 플랜, 구성, 사용 환경, 기능 및 지역에 따라 고객의
ChatGPT 워크스페이스에 적용되는 개인정보 보호, 보안 및 데이터 관련 약정이
적용됩니다. ChatGPT Enterprise의 경우 여기에는
[기본적으로 비즈니스 데이터를 학습에 사용하지 않는 정책](https://help.openai.com/en/articles/8983130-what-if-i-want-to-keep-my-history-on-but-disable-model-training),
전송 및 저장 중 암호화, 워크스페이스 수준 액세스 제어와
지원되는 감사 로그 기록이 포함됩니다.

데이터 레지던시, 추론 레지던시, HIPAA 또는 비즈니스 제휴 계약이
모든 경우에 적용되는 것은 아닙니다. 사용 중인 기능과 지역에 관한 최신
[데이터 및 추론 레지던시 안내](https://help.openai.com/en/articles/9903489-data-residency-and-inference-residency-for-chatgpt)와
고객 계약을 확인하세요.

연결된 서비스에는 자체적인 보존, 로그 기록, 액세스, 레지던시 및
규정 준수 요구 사항이 있습니다. ChatGPT Work에서 플러그인, 레포지토리 또는 타사
시스템을 사용할 때는 ChatGPT 워크스페이스 제어와 연결된
시스템의 제어를 모두 평가하세요.

Codex 활동의 경우 엔터프라이즈 제어의 적용 범위가 개발 환경,
레포지토리, 구성된 도구 및 관련 활동까지 확장될 수 있습니다. 워크스페이스 제어와 함께
[관리자용 도입 가이드](/ko-KR/codex/enterprise/admin-setup) 및
[거버넌스](/ko-KR/codex/enterprise/governance)를 검토하세요.

### 어떤 데이터가 저장, 보존 또는 삭제되나요?

ChatGPT Work의 데이터 보존과 삭제는 ChatGPT 워크스페이스의
플랜, 관리자 설정, 사용 중인 기능에 따라 결정됩니다. 보존 방식은
ChatGPT Work가 액세스하는 정보에 따라 달라질 수 있습니다. 대화와 적용 대상
Library 파일에는 해당 워크스페이스 설정이 적용됩니다. 프로젝트 파일, 임시 업로드,
저장된 메모리, 컴플라이언스 이벤트, 동기화된 앱 데이터 및
타사 기록에는 별도의 보존 및 삭제 규칙이 적용될 수 있습니다. 자세한 내용은
[채팅 및 파일 보존 정책](https://help.openai.com/en/articles/8983778-chat-and-file-retention-policies-in-chatgpt)을 참조하세요.

ChatGPT Work는 채팅 콘텐츠, 업로드되거나 생성된 파일, 아티팩트,
실행 메타데이터를 생성할 수 있습니다. Codex 채팅에서는 레포지토리 또는 환경
메타데이터, 명령어 출력, diff 및 로그도 생성될 수 있습니다. 최신 제품 문서와
[Compliance API](/ko-KR/codex/enterprise/compliance-api) 문서에서 정확한 데이터
유형, 보존 기간 및 삭제 방법을 확인하세요.

조직의 데이터 거버넌스, 규정 준수, 기록 보존 정책이 각 시스템에 적용되도록
ChatGPT 워크스페이스와 연결된 엔터프라이즈 시스템의 데이터 보존 요구 사항을
모두 검토하세요.

## 관측 가능성

### 관리자 또는 소유자가 확인할 수 있는 사용량 데이터는 무엇인가요?

관리자와 소유자는 제품 분석 및 컴플라이언스 로그를 통해 서로 다른
정보를 확인할 수 있습니다. 글로벌 관리자 콘솔에서는 지원 범위 내에서 ChatGPT와
Codex 도입 현황 및 크레딧 사용량을 확인할 수 있습니다. 사용자, 제품, 에이전트, 모델별
세부 정보의 제공 여부는 분석 화면과 워크스페이스에 따라 달라집니다.
지원 대상 워크스페이스에서는 Compliance API가 지원되는 클라우드 Work 활동을
포함한 ChatGPT 대화 기록을 제공 범위 내에서 제공합니다. 제공 범위는 제품,
사용 환경, 권한, 사용 가능한 엔드포인트, 문서에 명시된 이벤트 스키마에 따라 달라집니다. 자세한 내용은
[워크스페이스 분석](/ko-KR/codex/enterprise/workspace-analytics) 및
[Compliance API](/ko-KR/codex/enterprise/compliance-api)를 참조하세요.

### 프롬프트, 출력, 파일, 동작 또는 도구 호출이 기록되나요?

컴플라이언스 로그 플랫폼은 지원 대상 Enterprise 및 Edu 워크스페이스에
Work 사용자 프롬프트와 에이전트 응답을 제공합니다.
[연결된 앱 호출은 별도로 기록됩니다](https://help.openai.com/en/articles/11509118-admin-controls-security-and-compliance-in-apps-enterprise-edu-and-business).
또한 지원 대상 워크스페이스에서는 지원되는
[Library 전용 Compliance API 엔드포인트](https://help.openai.com/en/articles/20001052-library-for-chatgpt)를 통해 활성 Library 파일에 액세스할 수 있습니다.
이러한 기록이 호스팅 환경의 모든 파일 작업, 셸 명령어,
브라우저 상호작용, 도구 호출, 승인에 대해 완전한 감사 추적 기록을 제공하는 것은 아닙니다.
인증이 필요한 Compliance API 문서에서 현재 지원되는 이벤트와
제품 범위를 확인하세요.

컴플라이언스 로그 플랫폼은 데이터를 30일 동안 보존합니다. 조직에서 더 오래 보존해야 하는 경우,
승인된 전자 증거 개시, 데이터 손실 방지, SIEM
또는 데이터 레이크 시스템으로 기록을 지속적으로 내보내세요. 자세한 내용은
[OpenAI 컴플라이언스 플랫폼 가이드](https://help.openai.com/en/articles/9261474-compliance-api-for-chatgpt-enterprise-edu-and-chatgpt-for-teachers)를 참조하세요.

### 비정상적인 동작, 장애 또는 사용량 급증을 빠르게 탐지할 수 있나요?

워크스페이스 분석, 컴플라이언스 로그 및 연결된 모니터링 도구를 활용하면
관리자가 사용량을 검토하고 지원 범위 내의 ChatGPT, Work, Codex 활동을
조사할 수 있습니다. 선택한 보고 화면에 따라 활성 사용자, 지원 대상 메시지,
앱 활동, 에이전트 사용량, 인증 또는 관리 이벤트, 크레딧 소비량 등이
신호에 포함될 수 있습니다. 내보낸 로그는 전자 증거 개시, 데이터 손실 방지,
SIEM, 감사, 조사에 활용할 수 있습니다. 탐지 품질은 플랜, 이벤트 포함 범위,
귀속 정보, 데이터 최신성 및 구성된 규칙에 따라 달라집니다.

검토가 필요할 수 있는 신호에는 예상치 못한 사용량 또는 크레딧 소비량 증가,
비정상적인 사용자 또는 에이전트 활동, 반복되는 운영 오류 및 관련 인증 또는
관리 이벤트가 포함됩니다. 적용되는 분석, 컴플라이언스 및 감사 로그
스키마와 대조해 정확한 신호를 확인하세요.

Codex 활동에 대해서는 Codex 분석과 Analytics API가 지원 범위 내의
도입 현황 및 활동 지표를 제공합니다. 로컬 Codex 클라이언트를 사용하는 조직은
API 요청, 오류, 프롬프트 메타데이터,
도구 승인 결정, 도구 결과 등의 이벤트를 OpenTelemetry로 내보내도록 선택할 수 있습니다.
`otel.log_user_prompt = true` 설정을 별도의 명시적 옵트인으로 활성화하지 않는 한
프롬프트 내용은 가려집니다. 자세한 내용은
[모니터링 및 텔레메트리](/ko-KR/codex/agent-approvals-security#monitoring-and-telemetry)를 참조하세요.
이 로컬 Codex 텔레메트리는 웹에서 사용하는 ChatGPT Work의
OpenTelemetry 내보내기를 제공하지 않습니다.

## 거버넌스

### 관리자는 액세스, 권한 및 정책을 어떻게 제어할 수 있나요?

거버넌스는 서로 연관되어 있지만 별개인 세 가지 계층으로 구성됩니다:

- **ChatGPT Work 액세스 제어는** 각 사용 환경에서 ChatGPT Work를
  사용할 수 있는 대상을 결정합니다.
- **워크스페이스 에이전트 제어는** 워크스페이스 에이전트가 제공되는 경우
  재사용 가능한 에이전트와 공유 연결을 생성, 게시, 공유, 예약 또는
  구성할 수 있는 대상을 결정합니다.
- **Codex 관리형 구성은** 적용 대상인 로컬 Codex 런타임 동작을
  관리하며 호스팅되는 ChatGPT Work를 구성하지 않습니다.

관리형 구성은 지원되는 런타임 동작을 제한합니다. 워크스페이스 액세스를
부여하거나 RBAC를 대체하거나 사용자의 워크스페이스 액세스를 취소하지 않습니다.
이러한 계층을 하나의 통일된 ChatGPT Work 정책 체계로 볼 수는 없습니다.
분석 기능과 컴플라이언스 로그는 문서에 명시된 제품 및 이벤트
범위에서 추가적인 가시성을 제공합니다.

지원되는 로컬 Codex 클라이언트에는 엔터프라이즈 관리자가
[관리형 구성](/ko-KR/codex/enterprise/managed-configuration)과
[권한 프로필](/ko-KR/codex/permissions)을 적용할 수 있습니다. 이러한 로컬 클라이언트 제어 기능은
호스팅되는 ChatGPT Work에 대한 액세스를 부여하거나 해당 워크스페이스 권한을 대체하지 않습니다.

### 그룹, 역할, 워크스페이스 또는 기능별로 액세스 범위를 지정할 수 있나요?

예. 사용자 지정 멤버 RBAC를 지원하는 대상 엔터프라이즈 및 Edu 플랜에서는
워크스페이스 역할, ID 그룹,
관리자가 정의한 권한에 따라 ChatGPT Work 기능의 사용 범위를 지정할 수 있습니다. ChatGPT Business에는
해당하는 워크스페이스 수준의 제어 기능이 적용되지만, 사용자 지정 멤버 RBAC나
SCIM 그룹 동기화는 포함되지 않습니다. 비즈니스 요구 사항과
조직 정책에 따라 지원되는 기능을 할당하세요. 자세한 내용은
[RBAC 가이드](https://help.openai.com/en/articles/11750701-rbac)와
[RBAC 단계별 안내](https://vimeo.com/1207482321/d1286e4467?share=copy&fl=sv&fe=ci)를 참조하세요.

사용자 지정 RBAC를 사용할 수 있는 경우, 조직은 이를 통해 어떤 사용자가
ChatGPT Work에 액세스하고, 워크스페이스 설정을 관리하고, 승인된 플러그인을
구성하거나 지원되는 워크스페이스 에이전트 기능을 사용할 수 있는지 정할 수 있습니다.
조건을 충족하는 엔터프라이즈 및 Edu 워크스페이스에서는 월별 사용량 한도에
워크스페이스 기본값, 그룹 기본값, 사용자별 재정의를 적용해 단계적 도입을 지원할 수 있습니다.

연결된 시스템에 대한 액세스는 별도로 관리됩니다. 워크스페이스 권한, 플러그인 설정,
소스 시스템의 제어 기능을 사용해 플러그인, 공유 자격 증명, 레포지토리,
쓰기 가능한 작업의 이용 대상을 필요한 최소 범위로 제한하세요.
지원되는 로컬 Codex 클라이언트에서는 관리형 구성으로 로컬 런타임 기능을
추가로 제한할 수 있습니다. 호스팅되는 Work에는 자체 워크스페이스 및
제품별 제어 기능이 적용됩니다.

### 런타임 및 네트워크 경계는 어떻게 관리되나요?

ChatGPT Work의 보안 경계는 작업에 따라 달라집니다. 일반 채팅 대화,
연결된 워크플로우, 예약 작업, Codex 채팅은 권한, 도구, 네트워크 액세스가
서로 다른 환경에서 실행될 수 있습니다.

각 실행 환경은 해당 환경에 적용되는 제어 기능으로 관리하세요. Work 클라우드는
지원되는 웹, 모바일, 데스크톱 환경에서 호스팅되는 Work를 관리합니다. Work 로컬은
로컬 데스크톱 Work를 관리하고, Codex 로컬은 데스크톱, CLI, IDE
클라이언트에서 지원되는 로컬 Codex 액세스를 제어합니다. 브라우저 및 셸의 네트워크
권한은 Work 클라우드를 추가로 제한합니다. 검색, 앱, 플러그인, 사용 가능한
워크스페이스 에이전트, 소스 시스템 권한은 각각 별도로 관리됩니다.
관리형 구성과 로컬 런타임 정책은 각각 지원하는 로컬 환경에만 적용됩니다.
이러한 제어 기능은 서로 대체할 수 없습니다.

ChatGPT 데스크톱 앱, CLI, IDE에서 Codex를 로컬로 실행하면
사용자 기기에서 운영 체제 샌드박스와 승인 정책에 따라 실행됩니다.
Codex 클라우드는 OpenAI가 관리하는 격리된 환경에서 채팅을 실행합니다. 지원되는
로컬 클라이언트의 경우 엔터프라이즈 관리자는 관리형 요구 사항을 사용해
권한 프로필, 승인, 파일 시스템 및 네트워크 액세스, MCP 서버,
훅, 명령어 규칙과 기타 지원되는 런타임 동작을 제한할 수 있습니다.

## 사용량 및 비용

<a id="how-does-work-usage-translate-into-spend-over-time"></a>
<a id="how-does-work-mode-usage-translate-into-spend-over-time"></a>

### ChatGPT Work 사용량은 시간에 따라 비용에 어떻게 반영되나요?

[ChatGPT Work와 Codex는 요금, 크레딧, 사용량 한도를 공유합니다](/ko-KR/codex/pricing).
적용 대상인 크레딧 기반 계약에서는 직원들의 채팅 및 Work 사용량을 합산해
워크스페이스에 할당된 공유 크레딧과 비교하여 검토하세요. 크레딧 소모량은
모델, 적용되는 추론 또는 속도 설정, 처리한 입력과 출력,
적용 대상 도구나 기능에 따라 달라집니다.

약정 크레딧을 사용한다고 청구 금액이 자동으로 늘어나지는 않습니다.
실제 청구 금액은 남은 크레딧 잔액, 계약 요율,
계정의 초과 사용 가능 여부, 설정된 워크스페이스 초과 사용 한도에 따라 달라집니다.
계획 수립 예시, 실제 적용되는 사용자 한도, 보고 범위, 청구에 관한 자세한 내용은
[ChatGPT Work: 사용량 및 비용](/ko-KR/codex/enterprise/chatgpt-work-usage-and-cost)을 참조하세요.

비용 변동이 가장 큰 패턴은 대개 자주 실행되거나,
대량의 정보를 검색 또는 처리하거나, 여러 도구나 앱을 호출하거나,
실패 후 재시도하거나, 대용량 아티팩트를 생성하는 워크플로우에서 나타납니다.
비용에 유의해야 할 예로는 예약 작업이나 반복 작업, 대용량 파일,
엔터프라이즈 소스 전반을 대상으로 한 광범위한 검색, 반복적인 앱 호출,
레포지토리를 처리하거나 명령어를 실행하거나 클라우드 환경을 사용하는 Codex 채팅이 있습니다.
워크스페이스 에이전트 API 트리거도 지원되는 경우 사용량을 늘릴 수 있습니다.

지출 제어, 사용량 분석, 보고 기능을 사용해 이러한 패턴을 지속적으로
모니터링하세요. 현재 분석 화면에서 지원되는 기준별로 사용량을 검토하고
비즈니스 가치에 따라 한도나 도입 범위를 조정하세요. 집계된 분석 결과를
워크플로우별 비용을 정확히 산정한 자료로 간주하지 마세요.

워크스페이스 분석, 컴플라이언스 로그, 연결된 모니터링 도구는 관리자가
사용량을 검토하고 지원 범위에 포함된 활동을 조사하는 데 도움이 됩니다. 위험하거나
비정상적인 동작을 탐지할 수 있는지는 플랜, 로그 범위, 귀속 정보,
데이터 최신성, 모니터링 시스템에 설정된 규칙에 따라 달라집니다.

### 어떤 사용량 한도, 알림 또는 상한을 사용할 수 있나요?

조건을 충족하는 엔터프라이즈 및 Edu 워크스페이스에서는 크레딧 기반 사용량에 대해
월별 사용자당 한도와 워크스페이스 전체의 지출 제어 기능을 사용할 수 있습니다:

- **크레딧 소모량 모니터링:** Global Admin Console과
  워크스페이스 설정에서 지원되는 크레딧 사용량 보고서를 검토하세요.
- **기본 월별 한도 설정:** 워크스페이스에 적용할
  사용자당 기본 크레딧 한도를 설정하세요.
- **그룹별 한도 적용:** 각 그룹의 워크플로우, 담당 업무 또는 도입 단계에 맞는
  사용자당 월별 기본 한도를 설정하세요.
- **사용자별 한도 재정의:** 그룹 전체의 기본값을 변경하지 않고
  특정 사용자에게 다른 한도를 설정하세요.
- **한도 상향 요청 검토:** 요청 기능이 활성화된 경우 사용자는
  월별 한도 상향을 요청할 수 있습니다. 승인하면 해당 사용자의 한도가 개별적으로 재정의됩니다.
- **워크스페이스 전체의 비용 위험 관리:** Global Admin Console에서 워크스페이스 크레딧 알림과
  초과 사용 한도를 별도로 설정하세요. 알림은 수신자에게 통지하는 역할을 하며,
  초과 사용 한도는 약정 크레딧 풀이 소진된 후
  초과 사용 대상에 해당하는 사용량을 제어합니다.
- **사용량 데이터 내보내기:** 조건을 충족하는 엔터프라이즈 관리자는
  통합 Cost API를 통해 크레딧 사용량 데이터에 액세스하여 내부 보고나
  모니터링에 활용할 수 있습니다.

사용자는 자신의 사용량을 확인하고, 요청 기능이 활성화된 경우 추가 크레딧을 요청할 수 있지만
할당된 한도는 변경할 수 없습니다. 자세한 내용은
[사용량 한도 및 초과 사용 관리](https://help.openai.com/en/articles/20001001-manage-usage-limits-and-overages-in-chatgpt-enterprise-and-edu)
및
[지출 제어 단계별 안내](https://vimeo.com/1207484127/0f2029dd01?share=copy&fl=sv&fe=ci)를 참조하세요.

## 인시던트 대응 및 철회 관리

### 관리자는 액세스를 차단하거나 활동을 중지하려면 어떻게 해야 하나요?

사용자를 제거하거나 인시던트를 검토하는 과정에서 관리자는 액세스 차단,
앱 비활성화, 공유 자격 증명 철회, 예약 작업 일시 중지,
Codex 자격 증명 철회 등이 필요할 수 있습니다.

철회 방법은 다음과 같습니다:

- 사용자의 워크스페이스 또는 그룹 액세스를 제거하세요. SCIM으로 관리되는 사용자는
ID 공급자에서 액세스를 제거해야 합니다. 그렇지 않으면 나중에 동기화될 때
사용자가 다시 프로비저닝될 수 있습니다.
- 해당 플러그인이나 앱을 비활성화하거나 사용을 제한하세요.
- 공유 연결, 봇 또는 서비스 계정의 액세스는 해당 항목을 관리하는
화면에서 철회하세요. 워크스페이스 소유자와 관리자는 Codex 워크스페이스
액세스 토큰을 별도로 철회할 수 있습니다.
- 워크스페이스 에이전트 소유자나 워크스페이스 관리자를 통해 해당 에이전트의 게시를
취소하거나 삭제하세요.
- 해당 예약 작업을 비활성화하거나, 지원되는 경우 워크스페이스 에이전트 API
트리거를 비활성화하세요.
- Codex 액세스의 경우 관련 액세스 토큰, 레포지토리 연결,
클라우드 환경 액세스를 각각 철회하세요. 관리형 구성은
액세스를 철회하는 수단이 아닙니다.

## 관리자 권장 조치

- **먼저 누구에게 액세스 권한을 부여할지 확인하세요.** ChatGPT Work 액세스를 제한할지,
  파일럿을 진행할지, 아니면 조직 전반에 도입할지 결정하세요. 많은 조직은
  파워 유저, 내부 챔피언 또는 사용 사례가 명확한 팀부터 시작합니다.
- **역할과 권한을 검토하세요.** **권한 및 역할에서** ChatGPT Work에
  액세스할 수 있는 사용자나 그룹을 확인하세요. 비즈니스 요구, 준비 상태,
  거버넌스 기준에 맞춰 액세스 권한을 설정하세요.
- **플러그인과 데이터 소스를 검토하세요.** ChatGPT Work는 파일, 이메일,
  캘린더, Slack, CRM 등 승인된 비즈니스 컨텍스트를 활용할 때 가장 유용합니다.
  활성화된 플러그인과 사용 대상을 검토하고, 앱 정책이 사용자에게 권장하는
  작업 위임 방식에 여전히 부합하는지 확인하세요.
- **적절한 사용 사례의 기준을 정하세요.** ChatGPT Work는 연구, 정보 종합, 분석, 파일 생성,
  워크플로우 업데이트, 재사용 가능한 결과물 작성 등 여러 단계가 필요한
  고부가가치 작업에 적합하다고 안내하세요. 빠른 질문, 간단한 문구 수정,
  브레인스토밍에는 채팅을 사용하세요.
- **크레딧 및 사용량 제어 설정을 검토하세요.** ChatGPT Work는 수행 시간이 긴 작업을 처리할 수 있으므로
  일반적인 채팅보다 더 많은 크레딧을 사용할 수 있습니다. 기본 설정,
  그룹별 기본 설정, 사용자별 재정의 설정과 투입 수준을 비즈니스 가치에 맞추는 방법에 관한
  내부 지침을 검토하세요.
- **처음 적용할 고부가가치 워크플로우를 선정하세요.** 고객 브리핑, 정기 보고서,
  연구 결과 종합, 트래커 업데이트, 완성도 높은 문서와 슬라이드처럼 명확하고
  검토 가능한 결과물부터 시작하세요.
- **내부 챔피언과 지원팀이 준비를 갖추도록 하세요.** 내부 챔피언, 교육 책임자,
  지원팀에 도입 리소스를 먼저 제공하여 질문에 답하고 피드백을 수집하며,
  효과적으로 작업을 위임하는 모범을 보일 수 있도록 하세요.
- **검토 및 승인 기준을 안내하세요.** 결과물을 공유하거나 사용하기 전에 이를 검토하고 중요한 주장을 검증하며,
  중대한 영향을 미칠 수 있는 조치를 승인할 책임은 여전히 사람에게 있음을
  사용자에게 알리세요.
- **도입 현황을 모니터링하고 조정하세요.** 도입 후 사용량, 피드백, 크레딧 소비량,
  위임된 작업을 검토하세요. 검토 결과를 바탕으로 액세스 권한, 지침, 교육,
  도입 확대 범위를 조정하세요.
