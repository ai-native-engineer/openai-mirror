커밋하거나 푸시하기 전에 ChatGPT 또는 Codex를 사용해 코드 변경 사항을 검토하세요.

## 검토 시작

ChatGPT Work에서 검토할 코드를 업로드하거나 설치된 소스 [플러그인](/ko-KR/codex/plugins)을 통해
해당 코드에 접근할 수 있게 하세요. 프롬프트에 Pull Request, 브랜치, 커밋,
파일과 검토 기준을 명시하세요.

### 앱에서 검토

검토 창을 열어 변경 내용을 확인하고 줄별 피드백을 제공한 다음,
스테이징, 되돌리기, 커밋 또는 푸시할 항목을 결정하세요.

변경 사항을 검토하도록 Codex에 요청하려면 Composer에 `/review`를 입력하세요.
**기준 브랜치와 비교하여 검토** 또는 **커밋되지 않은 변경 사항 검토** 옵션을 선택하세요. Codex는 작업 트리를 변경하지 않고
우선순위에 따라 검토 결과를 보고합니다.

검토 창을 사용하려면 프로젝트가 Git 레포지토리 안에 있어야 합니다. 프로젝트가 아직
Git 레포지토리가 아니면 앱에서 레포지토리를 만들라는 메시지가 표시됩니다.

`/review`를 입력해 CLI 검토 프리셋을 여세요. Codex는 선택한 diff를 읽는 전담 검토자를 실행하고,
작업 트리는 변경하지 않은 채 조치 가능한 검토 결과를
우선순위에 따라 보고합니다.

IDE 확장의 Composer에 `/review`를 입력하세요. **기준 브랜치와 비교하여
검토** 또는 **커밋되지 않은 변경 사항 검토** 옵션을 선택하세요. Codex는 작업 트리를
변경하지 않고 우선순위에 따라 검토 결과를 보고합니다.

`/review` 명령어는 열려 있는 프로젝트가 Git
레포지토리 안에 있을 때만 표시됩니다.

## 검토 범위 선택

프롬프트에 검토할 Pull Request, 브랜치, 커밋 또는 파일을 지정하세요. 설치된
소스 플러그인으로 접근할 수 없는 로컬 파일을 검토하려면 해당 파일을
채팅에 업로드하세요.

### 표시되는 변경 사항

검토 창에는 Codex가 편집한 내용뿐 아니라 Git 레포지토리의 상태가
반영됩니다. Codex가 변경한 내용, 사용자가 직접 변경한 내용 및 레포지토리의
그 밖의 커밋되지 않은 변경 사항이 모두 포함됩니다.

기본적으로 검토 창에는 **스테이징되지 않음** 상태의 변경 사항이 표시됩니다. Git 인덱스를 보려면 **스테이징됨** 보기를,
선택한 커밋을 보려면 **커밋** 보기를, 기준 브랜치와의 diff를 보려면 **브랜치** 보기를,
어시스턴트의 가장 최근 턴을 보려면 **마지막 턴** 보기를 사용하세요.

### 여러 레포지토리 검토

[로컬 프로젝트에 여러 폴더가 포함되어 있고](/ko-KR/codex/projects#use-local-projects-for-folders-and-codebases)
각 폴더가 서로 다른 Git 레포지토리에 속하는 경우, 검토 창에 각
레포지토리의 변경 사항을 표시할 수 있습니다. 검토 헤더의 레포지토리 선택기를 열면
현재 검토 창을 벗어나지 않고 다른 레포지토리를 살펴보고
추가되거나 삭제된 줄을 확인할 수 있습니다.

연결된 모든 레포지토리에서 어시스턴트가 최근에 변경한 내용을 보려면 **마지막 턴** 보기를 선택하세요.
이 보기에서는 레포지토리 선택기에 **모든 레포지토리** 항목이 표시됩니다.
 **스테이징되지 않음**, **스테이징됨**, **브랜치** 같은 다른 검토 범위는
선택한 레포지토리에 적용됩니다.

다음 `/review` 검토 범위 중 하나를 선택하세요:

- **기준 브랜치와 비교하여 검토** 옵션은 병합 기준점을 찾아 브랜치의 diff를 검토합니다.
- **커밋되지 않은 변경 사항 검토** 옵션에는 스테이징된 파일, 스테이징되지 않은 파일 및 추적되지 않은 파일이 포함됩니다.
- **커밋 검토** 옵션은 선택한 커밋에 해당하는 변경 사항을 정확히 검토합니다.
- **사용자 지정 검토 지침** 옵션은 사용자가 지정한 기준에 중점을 두고 검토합니다.

다음 `/review` 검토 범위 중 하나를 선택하세요:

- **기준 브랜치와 비교하여 검토** 옵션은 현재 브랜치를 선택한 브랜치와 비교합니다.
- **커밋되지 않은 변경 사항 검토** 옵션은 작업 트리의 변경 사항을 검토합니다.

## 검토 결과 활용

검토 결과는 웹 채팅에 표시됩니다. 근거 제시를 요청하거나, 범위를 좁혀
후속 검토를 요청하거나, ChatGPT에 수정된 파일을 준비해 달라고 요청하세요.

### 코드 검토 결과

검토 결과는 검토 창에 인라인 댓글로 표시됩니다.

기본적으로 검토는 현재 채팅에서 실행됩니다. 별도의 검토 채팅을 시작하려면 **설정** \> **일반** \>
**코드 검토** 메뉴에서 **분리됨** 옵션을 선택하세요. 자세한 내용은
[개발자 설정](/codex/developer-settings?surface=app#app-code-review)을 참고하세요.

  
    
  

검토 내용은 대화 기록에 하나의 턴으로 표시됩니다. 검토에 현재 세션과 다른 모델을
사용하려면 `config.toml`에서 `review_model` 값을
설정하세요.

기본적으로 검토는 현재 채팅에서 실행됩니다. `/review`가 별도의 검토 채팅을 시작하도록 하려면
`chatgpt.reviewDelivery` 값을 `detached`로 설정하세요. 자세한 내용은
[IDE 확장 설정 참조 자료](/codex/developer-settings?surface=ide#ide-editor-settings-reference)를 확인하세요.

ChatGPT에 수정된 파일을 준비해 달라고 요청해도 채팅에서 사용할 수 있는 도구와
워크스페이스 권한은 그대로 적용됩니다.

Codex가 찾아낸 문제를 수정하도록 요청하면 기존 [샌드박스 및 승인
설정](/ko-KR/codex/sandboxing)이 적용됩니다.

## 검토 창 탐색

- 파일 이름을 클릭하면 일반적으로 선택한 편집기에서 해당 파일이 열립니다.
  기본 편집기는 [개발자 설정](/codex/developer-settings?surface=app#app-project-and-terminal-behavior)에서 선택할 수 있습니다.
- 파일 이름의 배경을 클릭하면 diff가 펼쳐지거나 접힙니다.
- <kbd>Cmd</kbd>를 누른 상태에서 한 줄을 클릭하면 선택한 편집기에서 해당 줄이 열립니다.
- 원하는 변경 사항은 [스테이징하고, 원하지 않는 변경 사항은 되돌릴](#staging-and-reverting-files) 수 있습니다.

## 피드백을 위한 인라인 댓글

인라인 댓글을 사용하면 diff의 특정 줄에 피드백을 직접 남길 수 있습니다.
Codex가 적절히 수정하도록 안내할 때 가장 빠른 방법인 경우가 많습니다.

인라인 댓글을 남기려면 다음 단계를 따르세요:

1. 검토 창을 여세요.
2. 댓글을 남길 줄 위에 마우스 포인터를 올리세요.
3. 나타나는 **+** 버튼을 선택하세요.
4. 피드백을 작성하고 제출하세요.
5. 피드백을 모두 남긴 후 채팅에 메시지를 보내세요.

댓글은 특정 줄에 연결되므로 Codex는 일반적인 지침을 받았을 때보다
더 정확하게 응답할 수 있습니다.

Codex는 인라인 댓글을 검토 지침으로 간주합니다. 댓글을 남긴 후
의도를 명확히 밝히는 후속 메시지를 보내세요. 예: “인라인 댓글을
반영하고 변경 범위를 최소화하세요.”

## Pull Request 검토

Codex에 레포지토리의 GitHub 접근 권한이 있고 현재 프로젝트가 Pull Request
브랜치에 있다면, ChatGPT 데스크톱 앱을 벗어나지 않고 Pull Request 피드백을
처리할 수 있습니다. 사이드바에는 Pull Request 컨텍스트와 검토자의 피드백이
표시되고, 검토 창에는 diff와 함께 댓글이 표시되므로 같은 채팅에서 Codex에
문제 해결을 요청할 수 있습니다.

GitHub CLI(`gh`)를 설치한 다음 `gh auth login` 명령어로 인증하면
Codex가 Pull Request 컨텍스트, 검토 댓글, 변경된 파일을 불러올 수 있습니다.
`gh`가 설치되지 않았거나 인증되지 않은 경우, Pull Request 세부 정보가
사이드바나 검토 창에 표시되지 않을 수 있습니다.

전체 수정 과정을 한곳에서 진행하려면 다음 플로우를 사용하세요:

1. Pull Request 브랜치에서 검토 창을 여세요.
2. Pull Request 컨텍스트, 댓글 및 변경된 파일을 검토하세요.
3. 처리하려는 댓글을 반영해 수정하도록 Codex에 요청하세요.
4. 검토 창에서 수정 결과의 diff를 확인하세요.
5. 준비가 되면 변경 사항을 스테이징하고 커밋한 다음 Pull Request 브랜치에 푸시하세요.

GitHub에서 트리거되는 검토에 대해서는 [GitHub에서 Codex 사용하기](/ko-KR/codex/third-party/github)를 참고하세요.

## 파일 스테이징 및 되돌리기

검토 창에서 Git 작업을 사용해 커밋 전에 diff를 원하는 대로 조정할 수 있습니다.

다음 범위에서 변경 사항을 스테이징하거나, 스테이징을 해제하거나, 되돌릴 수 있습니다:

- **전체 diff**: 검토 창 상단에서 **모두 스테이징** 또는 **모두 되돌리기** 등의 작업 버튼을 사용하세요.
- **파일별**: 개별 파일을 스테이징하거나 스테이징을 해제하거나 되돌리세요.
- **헝크별**: 개별 헝크를 스테이징하거나 스테이징을 해제하거나 되돌리세요.

작업의 일부만 반영하려면 스테이징하고, 변경 사항을 폐기하려면 되돌리세요.

### 스테이징된 상태와 스테이징되지 않은 상태

Git에서는 한 파일에 스테이징된 변경 사항과 스테이징되지 않은 변경 사항이 동시에 존재할 수 있습니다. 이 경우 검토 창의 두 보기 모두에 같은 파일이 표시될 수 있으며, 이는 Git의 정상적인 동작입니다.
