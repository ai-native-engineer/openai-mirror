  + 새로운 우선순위 보기는 실행 중인 작업, 읽지 않은 업데이트, 사용자의 응답을 기다리는 작업을 작업 목록 상단에 표시합니다.
  + 이제 전송 대기 중인 프롬프트는 연결된 호스트와 동기화되고 계속 수정할 수 있으며, 앱이 백그라운드에 있어도 전송됩니다.
  + 장시간 실행되는 작업에서는 이제 작업 시간이 실시간으로 표시됩니다.
  + 작업 메뉴에 스레드 ID를 복사하는 옵션이 추가되었습니다.

  ### 개선 사항 및 버그 수정

  + 작업 목록을 불러오고 정리하는 속도와 안정성이 개선되었습니다. 날짜별 구분이 간결해졌으며, 멈춤 현상이나 프로젝트가 사라지는 문제가 줄었습니다.
  + 재연결의 안정성이 향상되어 보내기 상태에서 멈추거나, 승인이 누락되거나, 작업 업데이트가 갱신되지 않는 문제가 해결되었습니다.
  + 긴 응답이 스트리밍 중에 끊겨 보이는 현상이 줄었습니다.
  + 사이드 채팅을 더 이상 재연결할 수 없더라도, 메시지는 직접 닫기 전까지 계속 확인할 수 있습니다.

  + **클라우드 브라우저 로그인:** 지원 대상 요금제에서는 웹, iOS,
    Android의 ChatGPT Work가 클라우드 브라우저를 통해 [지원되는 웹사이트에
    로그인](/codex/browser?surface=web#web-sign-in-to-a-website)하도록
    요청할 수 있습니다. 로그인 정보는 채팅이 아닌 로그인 플로우에 입력하세요. 클라우드
    브라우저 세션은 로컬 브라우저와 별도로 유지됩니다. 엔터프라이즈 또는 Edu 워크스페이스에서는
    웹사이트 로그인을 사용할 수 없습니다.

  사용 가능 여부는 기능 출시 상황과 워크스페이스 설정에 따라 달라집니다. 웹사이트 접근 및
  작업 확인 요구 사항은 계속 적용됩니다.

  ### Gmail, Slack, GitHub 이벤트로 예약 작업 실행하기

  이제 Gmail, Slack 또는 GitHub에서 지원되는 이벤트가 발생하면 ChatGPT 예약 작업을 실행할 수 있습니다.
  발신자나 제목을 기준으로 Gmail 메시지를 필터링하거나, 선택한 Slack 채널을 모니터링하거나,
  검토, 댓글, 커밋 업데이트, 병합 등의 Pull Request 활동에 대응하세요.

  지원 대상 요금제를 사용하면 웹과 모바일의 ChatGPT에서 이벤트로 실행되는 작업을 이용할 수 있습니다.
  작업을 만들기 전에 관련 앱을 연결하고 앱이 요청하는 접근 권한을 승인하세요.
  ChatGPT Slack 앱은 모니터링하는 각 채널의 멤버여야 하며,
  연결된 GitHub 앱에는 모니터링하는 각 레포지토리에 대한 접근 권한이 있어야 합니다.

  이벤트로 실행되는 작업에는 시간 기반 일정을 함께 설정할 수 없습니다. 조건에 맞는
  이벤트가 짧은 간격으로 들어오면 ChatGPT가 한 번의 실행에서 함께 처리할 수 있습니다.
  **예약됨을** 열어 대기 중인 이벤트를 검토하거나 **지금 실행을** 선택하세요.

  예약 작업을 실행하는 방법을 알아보세요](/codex/automations?surface=web#web-trigger-tasks-from-app-events).

  + **Site URL 수정:** URL을 수정할 수 있는 경우 소유자는 새로운 배포를 생성하지 않고 [기존 Site의 ChatGPT 호스팅 주소를 변경](/codex/sites#change-a-site-url)할 수 있습니다. 이전 주소는 새 URL로 리디렉션됩니다. 사용자 지정 도메인은 별도의 기존 기능이며 이 설정으로 변경되지 않습니다.
  + **유럽 지역의 컴퓨터 사용 기록:** EEA, 스위스, 영국의 ChatGPT Pro, Business 및 엔터프라이즈 사용자는 이제 macOS용 ChatGPT 데스크톱 앱에서 [컴퓨터 사용 기록](/codex/customization/computer-history)을 사용할 수 있습니다. 이 기능은 기본적으로 꺼져 있으며 메모리가 필요합니다. 워크스페이스 멤버가 기능을 켤지 선택하려면 Business 및 엔터프라이즈 관리자가 먼저 접근을 허용해야 합니다.
  + **스레드 스냅샷 공유:** 모든 Codex 요금제에서 macOS용 ChatGPT 데스크톱 앱을 통해 [로컬 Codex 스레드의 읽기 전용 스냅샷을 공유](/codex/use-chatgpt#share-a-read-only-snapshot-of-a-codex-thread)할 수 있습니다. 원본 스레드가 변경되어도 스냅샷은 업데이트되지 않습니다. 개인 계정의 링크는 링크가 있는 누구나 열 수 있으며, 워크스페이스 계정의 링크는 해당 워크스페이스의 멤버만 열 수 있습니다. Codex는 알려진 비밀 정보 패턴을 가리지만 민감한 내용이 남아 있을 수 있으므로 공유하는 내용을 검토하세요. [ChatGPT 데이터 제어](https://chatgpt.com/#settings/DataControls)의 **공유 링크** 항목에서 링크를 확인하거나 공유를 취소하세요.

  ### Daybreak Blue와 Daybreak Red 소개

  Daybreak는 이제 승인을 받은 방어 담당자에게 Daybreak Blue와
  Daybreak Red라는 두 가지 액세스 등급을 제공합니다. 명시적으로 승인된 보안 활동에서 보안 이슈를 검증된 수정 사항으로
  전환하는 데 사용하세요.

  대부분의 방어적 보안 작업에는 Daybreak Blue를 먼저 사용하세요. 이 등급에서는
  취약점 발견, 보안 코드 검토, 탐지 엔지니어링, 인시던트 대응,
  멀웨어 분석, 패치 검증에 GPT-5.6 Sol 같은
  범용 모델을 사용할 수 있습니다.

  Daybreak Red에서는 별도 승인을 받아 GPT-5.6 Cyber처럼 특정 목적에 맞게 학습된 모델에
  액세스할 수 있습니다. 승인된 범위에서 취약점 재현, 익스플로잇 검증,
  침투 테스트, 레드팀 테스트, 복잡한 시스템 분석에 이 모델을 사용할 수 있습니다.

  액세스하려면
  [Trusted Access for Cyber](/codex/cyber-safety#trusted-access-for-cyber)를 통해 승인을 받아야 합니다. 액세스 권한은
  승인된 ID, 워크스페이스 또는 API 조직 및 프로젝트, 모델,
  제품 인터페이스에만 적용됩니다. Daybreak Red에는 별도의 승인과 프로비저닝이 필요하며,
  Daybreak Blue 액세스 권한으로는 Daybreak Red에 액세스할 수 없습니다.

  격리된 환경에서 작업하고 수행 범위를 정의하며,
  최소 권한 원칙에 따른 [권한 프로필](/codex/permissions)을 사용하세요. 자동 검토 대상 작업이
  샌드박스 경계를 넘기 전에 [자동 검토](/codex/sandboxing/auto-review)를
  구성하세요.

  + 긴 프롬프트의 편집 성능을 개선했습니다.
  + 이제 음성 대화에 백그라운드 대화 설정이 적용됩니다.
  + 재연결 후 승인 및 사용자 입력 요청이 안정적으로 복구되도록 개선하고, 대화 기록에 승인 세부 정보가 더 명확하게 표시되도록 했습니다.
  + 목표를 완료한 후 후속 `/goal` 프롬프트에서 발생하던 문제를 수정했습니다.
  + 작업 목록이 멈추거나 작업 제목이 사라지는 현상, 추론 요약이 깜빡이는 현상, 대화 기록 화면이 비정상 종료되는 문제를 수정했습니다.

  ### ChatGPT로 로그인(베타)

  ChatGPT로 로그인 기능이 Airtable, GitLab, HubSpot, Notion, Supabase, Vercel을
  시작으로 일부 플러그인과 파트너 사이트에 베타로 순차 출시되기
  시작했습니다.

  ChatGPT 플러그인 디렉터리에서 지원되는 플러그인을 연결하면
  ChatGPT로 로그인 기능을 사용해 해당 서비스의 계정을 더 간단한 절차로
  만들거나 연결할 수 있습니다. 이 기능을 제공하는 파트너 사이트에서도 **ChatGPT로
  로그인을** 선택해 계정을 만들거나 기존 계정에 액세스할 수 있습니다.

  이를 통해 ChatGPT와 Codex에서 지원되는 도구로 더 쉽게 작업을 시작할 수 있습니다.

  로그인하면 파트너에게 이름, 이메일 주소 및 프로필 사진(있는 경우)만
  제공됩니다. 각 플러그인이 요청한 액세스 권한은 별도의 단계에서 검토하고
  승인해야 합니다.

  데스크톱 앱과 [iOS의 원격 기능](/codex/remote-connections#set-up-mobile-access)을 통해 사용할 수 있습니다.

  포함할 수 있습니다. 프로젝트 메뉴에서 **프로젝트 편집을** 선택해 폴더를 추가하고

  `AGENTS.md`, 스킬, `config.toml`의 자동 검색도 기본 폴더를 기준으로 이루어집니다.
  보조 폴더에서도 계속 파일을 검색하고 읽고 편집할 수 있습니다.

  프로젝트](/codex/projects#use-local-projects-for-folders-and-codebases)를 사용해 보세요.

  #### 작업 시작, 진행 확인, 방향 조정

  처음부터 다시 시작하지 않고 반복적인 후속 작업을 이어갈 수 있습니다.

  ### 웹 검색이 이제 기본으로 활성화됩니다

  Codex는 이제 Codex CLI와 IDE 확장의 로컬 작업에서 웹 검색을 활성화합니다.
  기본적으로 Codex는 OpenAI가 관리하는 웹 검색 결과 인덱스인 웹 검색 캐시를 사용합니다. 캐시 모드는 라이브 페이지를 가져오는 대신 사전 인덱싱된 결과를 반환하고, 라이브 모드는 웹에서 최신 데이터를 가져옵니다. `--yolo` 또는 다른 [전체 권한 샌드박스 설정](/codex/agent-approvals-security)을 사용하는 경우 웹 검색은 기본적으로 라이브 결과를 사용합니다. 이 동작을 비활성화하거나 모드를 전환하려면 `web_search` 구성 옵션을 사용하세요:

  + `web_search = "cached"` (기본값; 웹 검색 캐시의 결과를 제공)
  + `web_search = "live"` (웹에서 최신 데이터를 가져옴; `--search`와 동일)
  + `web_search = "disabled"`로 설정하여 도구 제거

  자세한 내용은 [구성 문서](/codex/config-file/config-basic)를 확인하세요.

  ### 공유 구성을 위한 Team Config

  Team Config는 팀이 레포지토리와 머신 전반에서 Codex를 표준화하는 데 사용하는 파일을 하나로 모읍니다. 이를 사용해 다음을 공유할 수 있습니다:

  + `config.toml` 기본값
  + 샌드박스 외부의 명령어 제어를 위한 `rules/`
  + 재사용 가능한 워크플로우를 위한 `skills/`

  Codex는 현재 작업 디렉터리, 상위 폴더, 레포지토리 루트의 `.codex/` 폴더와 사용자 위치(`~/.codex/`) 및 시스템 위치(`/etc/codex/`)에서 이러한 레이어를 로드합니다. 우선순위가 높은 위치의 설정은 낮은 위치의 설정을 재정의합니다.

  관리자는 위치와 관계없이 기본값을 재정의하는 `requirements.toml`을 사용해 제약 조건을 계속 강제할 수 있습니다.

  자세한 내용은 [Team Config](/codex/enterprise/admin-setup#step-4-standardize-local-configuration-with-team-config)에서 알아보세요.

  + 설정 후 에이전트가 네트워크 액세스 없이 실행 중임을 나타내는 표시를 추가했습니다
  + PR을 푸시한 후 git 패치를 복사할 수 있는 옵션을 추가했습니다
  + 유니코드 브랜치 이름 지원을 추가했습니다
  + 시크릿이 설정 스크립트로 파이프되지 않던 버그를 수정했습니다
  + 브랜치 이름이 충돌할 때 브랜치를 생성하지 못하던 문제를 수정했습니다.
  + 여러 문자로 구성된 이모지가 포함된 diff를 렌더링할 때 발생하던 문제를 수정했습니다.
  + 작업을 시작하거나 설정 스크립트를 실행하거나 PR을 푸시할 때, 또는 GitHub 연결이 끊겼을 때 표시되는 오류 메시지를 개선해 더 구체적인 내용과 해결 방법을 안내하도록 했습니다.
  + 팀 온보딩을 개선했습니다.
  + 새 작업이 로드되는 동안 표시되는 화면을 다듬었습니다.
  + 후속 Composer를 다듬었습니다.
  + GitHub 연결이 끊기는 빈도를 90% 줄였습니다.
  + PR 생성 지연 시간을 35% 줄였습니다.
  + 도구 호출 지연 시간을 50% 줄였습니다.
  + 작업 완료 지연 시간을 20% 줄였습니다.
  + Codex 탭을 더 쉽게 구분할 수 있도록 페이지 제목을 작업 이름으로 설정하기 시작했습니다.
  + 에이전트가 네트워크 액세스 없이 작업 중임을 인식하고 사용자에게 종속성 설정을 제안할 수 있도록 시스템 프롬프트를 조정했습니다.
  + 문서를 업데이트했습니다.
