    cloud. Saisissez vos informations lors de la procédure de connexion, et non dans la discussion. Les sessions du navigateur

    n’est pas disponible pour les espaces de travail Entreprise ou Edu.

  ### Déclenchez des tâches planifiées en réponse à des événements dans Gmail, Slack et GitHub

  Les tâches planifiées de ChatGPT peuvent désormais s’exécuter lorsque des événements pris en charge se produisent dans Gmail, Slack
  ou GitHub. Filtrez les messages Gmail par expéditeur ou par objet, surveillez les canaux Slack
  de votre choix ou réagissez à l’activité des pull requests, comme les révisions, les commentaires, les mises à jour de commits
  et les fusions.

  Les tâches déclenchées par des événements sont disponibles dans ChatGPT sur le web et sur mobile avec
  les offres éligibles. Connectez l’application concernée et approuvez les accès qu’elle demande avant
  de créer une tâche.
  L’application ChatGPT pour Slack doit être membre de chaque canal surveillé, et
  l’application GitHub connectée doit avoir accès à chaque dépôt surveillé.

  Une tâche déclenchée par un événement ne peut pas aussi suivre un calendrier d’exécution. Lorsque des événements
  correspondant aux critères arrivent à peu d’intervalle, ChatGPT peut les regrouper en une seule exécution.
  Ouvrez **Planifiées** pour consulter les événements en attente ou choisissez **Exécuter maintenant**.

  [Apprenez à déclencher des tâches planifiées en réponse à des
  événements dans les applications](/codex/automations?surface=web#web-trigger-tasks-from-app-events).

  ### Présentation de Daybreak Blue et Daybreak Red

  Daybreak propose désormais aux défenseurs autorisés deux niveaux d’accès : Daybreak Blue et
  Daybreak Red. Utilisez-les pour passer des problèmes de sécurité identifiés à des correctifs validés dans le cadre
  d’interventions explicitement autorisées.

  Commencez par Daybreak Blue pour la plupart des travaux de cybersécurité défensive. Ce niveau donne accès
  à des modèles polyvalents tels que GPT-5.6 Sol pour la recherche de vulnérabilités,
  la revue de code axée sur la sécurité, l’ingénierie de la détection, la réponse aux incidents, l’analyse des logiciels malveillants
  et la validation des correctifs.

  Daybreak Red donne accès, sous réserve d’une approbation distincte, à des modèles spécialement entraînés
  comme GPT-5.6 Cyber pour la reproduction autorisée de vulnérabilités, la validation d’exploits,
  les tests d’intrusion, le red teaming et l’analyse de systèmes complexes.

  L’accès nécessite une approbation via
  [Trusted Access for Cyber](/codex/cyber-safety#trusted-access-for-cyber) et
  ne s’applique qu’aux éléments approuvés : l’identité, l’espace de travail ou l’organisation API et son
  projet, le modèle et l’interface du produit. Daybreak Red nécessite une approbation
  et un provisionnement distincts ; l’accès à Daybreak Blue ne permet pas d’accéder à Daybreak Red.

  Travaillez dans un environnement isolé, définissez le périmètre de votre intervention, utilisez
  des [profils d’autorisations](/codex/permissions) fondés sur le principe du moindre privilège et configurez
  la [Révision automatique](/codex/sandboxing/auto-review) pour les actions éligibles avant qu’elles ne
  franchissent la limite du bac à sable.

  En savoir plus sur la [Cybersécurité](/codex/cyber-safety),
  le [barème des crédits Codex](/codex/pricing#credits-overview) et
  les [prix des tokens de l’API](/api/docs/pricing).

  + Saisissez du texte dans la barre d’adresse du navigateur intégré pour rouvrir des pages de votre

  secondaires restent disponibles pour la recherche, la lecture et la modification de fichiers.

  ### La recherche web est désormais activée par défaut

  Codex active désormais la recherche web pour les tâches locales dans la CLI Codex et l’Extension IDE.
  Par défaut, Codex utilise un cache de recherche web, qui est un index de résultats web géré par OpenAI. Le mode avec cache renvoie des résultats préindexés au lieu de récupérer les pages en temps réel, tandis que le mode en direct récupère les données les plus récentes sur le web. Si vous utilisez `--yolo` ou un autre [paramètre de bac à sable avec accès complet](/codex/agent-approvals-security), la recherche web utilise par défaut les résultats en direct. Pour désactiver ce comportement ou changer de mode, utilisez l’option de configuration `web_search` :

  + `web_search = "cached"` (par défaut ; renvoie les résultats du cache de recherche web)
  + `web_search = "live"` (récupère les données les plus récentes sur le web ; équivaut à `--search`)
  + `web_search = "disabled"` pour supprimer l’outil

  Pour en savoir plus, consultez la [documentation de configuration](/codex/config-file/config-basic).
